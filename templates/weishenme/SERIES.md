# 系列圣经 —「你每天都在用，但你不知道它怎么工作」（为什么系列）

**发布顺序：EP.01 陀螺仪 → EP.02 微波炉 → EP.03 降噪耳机。**（降噪耳机先做、后发；下文用集名称呼，不用编号。）

从陀螺仪、降噪耳机、微波炉三集的反馈和发布数据里沉淀下来的写法。**陀螺仪是这个系列的标杆**（发布后两个平台流量和点赞都最好），后面每一集照下面的结构、时间骨架、停留和文字规则来。

**本圣经只用于「为什么系列」。** 不同系列不硬套一个模型：What if 系列信息密度更大，适当的停顿和静止是可以的，规则另定；两个系列之间取长补短，各自发挥自己的优势。

## 从陀螺仪学到的（发布数据 + 逐帧测量，2026-11）

陀螺仪 44.5 s；对照 What if《地球停转》89.5 s。用 `tools/motion.py` 测"每秒画面变化"（前后帧平均像素差）：

| | 陀螺仪 | 地球停转 |
|---|---|---|
| 每秒画面变化 平均 / 中位 | 8.1 / 6.8 | 2.6 / 1.0 |
| 几乎静止的时间占比 | 11% | 23% |
| 最长静止 | 1.6 s | 3.1 s |

1. **第 0 帧就有动作，问题 2 秒内出现。** 陀螺仪第 0 帧手机就在转（第 1 秒画面变化 8.6）；不用"想象一下……"式的铺垫开场。
2. **每一秒都在动。** 任何静止段 ≤ 1.5 s（中位每秒画面变化 ≥ 5 不再是硬指标，以观众观感为主——用户 2026-11-09）；刻意的停顿除外（打叉前的真静音、片尾最后落定）。**慢的是信息，不是画面**：停在一个状态上讲解时，镜头要缓推或漂移，画面里的东西要持续地动（陀螺仪那块硅一直在振动，动作本身就是内容）。成片前用 `tools/motion.py` 量一遍。
3. **一个连续空间，一种画风。** 转场都是同一空间里的镜头运动；外面亮、里面暗（暗场浸入）是唯一允许的切换，不换画风、不换世界。
4. **结尾把开头的动作原样再做一次。** 开头出现的人和物，结尾要回来。
5. **一个机制，屏上数字 ≤ 3 个。** 累人的不是字多，是要消化的结论多（两片字幕密度差不多：5.2 vs 4.7 字/秒）。
6. **时长控制在 60 s 以内。**
7. **画面和音乐定节奏，字幕跟着动作走**；不让画面停下来等字。

## 流程（每一集）

1. **选题**：给出几个候选，用户定。
   **选题标准："哦，对啊，为什么呢？"**（陀螺仪为什么最火；小红书上"为什么 iPhone 来电有时滑动接听、有时是两个按钮"点赞也特别多）：
   - **一个天天都在经历的瞬间**，不是一个东西的名字：是"把手机横过来"，不是"陀螺仪"。
   - **习以为常到从没想过**：一问出来，第一反应是"对啊，为什么？"，而不是"我知道啊"或"我没用过"。
   - **问题里不出现任何专业词**，一句话就能让人在脑子里看到那个画面。
   - **答案出乎意料，又能一句话说清**："里面根本没有陀螺，是一块一直在抖的硅。"
   - 自测：把封面问题念给没看过的人听，他会不会停下来想一秒。按这个标准，陀螺仪最强；微波炉次之（很多人默认"微波炉就是不均匀"）；降噪耳机再次（不是人人都有，而且"主动降噪"这个词很多人已经知道）。
   - **先有现象，再找原理**（不要从"我知道一个有意思的技术"出发再去包装标题）：平时刷到、用到时把"诶，对啊，为什么？"的瞬间记进 `episodes/weishenme/选题库.md`（现象 / 第一反应 / 封面问题），攒够再筛。
   - **"为什么设计成这样"类的问题**（如 iPhone 两种来电界面）只做入口：答案太短、设计意图难查实时，接一个能演出来的机制再做（锁屏要滑动 → 裤兜里也会误触 → 触摸屏感应的是电）。
   - 这只是选题假设，要用数据验证：每集发布后记下封面问题、完播率、点赞、收藏，几集后对照。
2. **白话版先行**：动手做视频之前，先把这一集的原理和内容用白话写出来（`白话.md`：一句话结论 + 按视频顺序一步一步讲 + 每段画面打算怎么表现），发给用户读。**用户读懂、确认之后再开始做。**看不懂的地方，先改白话版，不在视频里补救。
3. SPEC（问题表、分镜、声音）→ 制作 → 自检循环（CLAUDE.md）→ 交付。

## 叙事：一个微型侦探故事（固定六段）

情绪曲线：**熟悉 → 疑问 → 误导 → 探索 → 顿悟 → 补一刀 → 闭环**

1. **现象，不是名词。** 前 2–3 秒是人人做过的动作 + 一个问题（"手机怎么知道你把它横过来了？"）。第 0 帧就有大字问题。
   绝不以"今天我们讲 X"开场，专业名词不出现在入口。
2. **（可选）一个错误直觉，然后打叉。** 2026-11-09 起不必反直觉；错误猜测必须是观众真会有的想法，想不出就不用这一拍。 用大众心里的图像（"你是不是以为里面藏了个小陀螺？"），放在同一个物体里，橙色铺底（每集一次），啪，打叉，一句话翻转（"其实里面什么都不转。"）。
3. **钻进去找答案（系列招牌）。** 物体 → 外壳 → 内部 → 芯片/结构/信号 → 原理，一条连续空间、一台相机推进，让人觉得"我们真的钻进去了"。
   尺度参照只在它本身就在画面里、一眼能认出时才用（EP.01 的米粒放在主板上可以）；不要为了比喻凭空放一个东西进来（降噪耳机的芝麻很突兀，已删）。
4. **只讲一个核心机制。** 一个视觉动作，分三拍：本来的状态 → 一个变化 → 变化有多大就说明什么。方向必须画出来（参照物、错位量、直角符号），慢放要标注。宁愿慢。
   **名词在这里才出现，作为答案的一部分**（"这块会'偏'的硅，就叫陀螺仪。"）。不再加回扣误区的小字。
5. **"原来还差这一步"。** 只知道一半还不够（"但只知道'转了'，够吗？"）→ 第二个部件登场，分屏分工。
   **先让观众看到"只靠第一个部件会出什么问题"**（一个具体、日常的情形，比如"耳塞没戴紧，噪音漏进来"），再让第二个部件登场；第二个部件第一次出现时要在整体里指出它的位置。分屏只在两个部件都已经认识之后才用。（降噪耳机 v2 的教训："只听外面，够吗？"没有铺垫，观众看不懂。）
6. **回到开头的现象，闭环。** 从里面拉回日常物，把开头那个动作再做一次，这次让部件在动作发生时开口说话，最后一句回答第 0 秒的问题（"所以，你一横手机，它就知道了。"）。不做教科书式总结卡。
7. **（可选）最后一镜的小提示。** 和日常体验相关的一句实用提醒（降噪耳机："戴久了耳朵发胀？其实气压没变，是大脑的误会。调低降噪，或摘下来歇会儿。"），最后一句字幕读完后，在同一个字幕位置出现（不压画面），不单独成段、不展开新原理。

## 节奏：每 5–7 秒必须有一个新的认知问题

- 是**新的问题**，不是新的知识点。模式：问题 → 答案 → 新问题 → 答案。
- 每个问题都要在下一个问题之前被画面回答；问题之间允许有短的"预测型"问题（"这时，手机转一下呢？"），画面在 0.5–1 秒内给出答案。
- 问题越短越好，能三个字就不用十个字（"然后呢？"）。
- EP.01 的问题表（参照）：0 s 手机怎么知道你把它横过来了？/ 4.25 s 你是不是以为里面藏了个小陀螺？/ 8.5 s 那它到底怎么测旋转？/ 13 s 它自己不转，怎么知道你在转？/ 19.25 s 这时，手机转一下呢？/ 22.75 s 为什么一偏，就知道转多快？/ 29 s 但只知道"转了"，够吗？/ 34.5 s 手机到底怎么判断横屏？
- 每 2–4 秒画面上必须有新的事发生（扫描、推进、掀盖、偏移、分屏、拉出……）。

## 模板（时间骨架以 降噪耳机 v4 为准，每集照这个填内容）

**时长控制在 60 s 以内。** 决定完播率的是内容本身，不是秒数——只要每一步都有新问题、画面看得懂、一直在动，观众会跟着一步步看完。不为压时长去赶节奏、删停留；也不为凑时长加内容；内容超了先砍枝节（降噪耳机砍掉了"自适应"一段，"戴久了不舒服"缩成最后的小提示）。

下表是 降噪耳机 v4（59.75 s，120 BPM）的实际时间，作为各段比例的参考；陀螺仪 EP.01 v5（44.5 s）是内容更简单时的紧凑版本。

| 段 | 时长 | 降噪耳机 v4 | 内容 | 必须 |
|---|---|---|---|---|
| 1 现象 | ≈ 5 s（EP.05 起试行 ≈ 2.75 s） | 0–5 | 先让"之前"的状态停 2 s（镜头从第 0 帧就在缓推），再做日常动作，结果紧跟；问题 Q1 | 第 0 帧大字问题和动作；动作前停 ≥ 1.5 s |
| 2 误区（可选，2026-11-09 起不必反直觉） | ≈ 5.5 s | 5–10.5 | Q2 错误直觉 → 0.5 s 真静音 → 打叉 → 一句翻转 | 错误图像在同一物体里扫出（橙底）；问题停留 ≥ 2.5 s；打叉是最响的三下之一 |
| 3 钻进去 | ≈ 11.5 s | 10.5–22 | Q3 → 揭开外壳 → 圈出部件 → 推进（≥ 2 s）→ A3 → 短问题 Q4 → 跟着信号走 → 浸入 | 每一层落定后停 ≥ 1 s 再推进；跟信号时镜头先停稳 |
| 4 机制 | ≈ 16.5 s | 22–38.5 | 本来的状态（停 ≥ 3 s）→ Q5 → 变化（慢放，≥ 1 s 渐变）→ 一句白话讲清变化 → A5 → Q6 → 变化的反例 → A6 → **名词揭晓** | 只有一个视觉动作；镜头沿着它缓慢漂移，不停；变化出现后 ≥ 2 s 才换字；名词揭晓是最响的三下之一 |
| 5 补一刀 | ≈ 6 s | 38.5–44.5 | 先给一个具体问题（"耳塞没戴紧呢？"）→ 第二个部件在原画面里登场、开口 → 补上 | 第二个部件出现前先看到问题；它第一次出现时指出位置 |
| 6 闭环 | ≈ 8.25 s | 44.5–52.75 | 拉出 → Q9 → 开头的动作重演（之前的状态先停 ≥ 1.5 s），部件在动作发生时开口 → 结果 → 最后一句回答 Q1 | 气泡同屏 ≥ 2 s；结果是最响的三下之一；最后一句 ≥ 2.2 s |
| （可选）小提示 | ≈ 3.6 s | 52.75–56.35 | 最后一句读完后，在同一个字幕位置出一条和日常体验相关的提醒（小标"小提示" + 三行以内） | 不单独成段、不展开新原理；读完时间 ≥ 0.1 s × 字数 + 0.5 s |
| 片尾 | ≈ 3.25 s | 56.5–59.75 | 物体缩成描边徽标，EP 号 + 名称，系列名逐字打出，橙色问号落定 | 问号和最后一个旋律音同拍 |

## 停留时间与节奏（EP.01 v4→v5、降噪耳机 v1→v2 的教训：太赶就看不懂）

- **字幕停留 ≥ 0.1 s × 字数 + 0.5 s**（标点算字）。
- **每个变化之前，先让"之前"的状态停 ≥ 1.5 s**：先看清噪音，再按下；先看清只有噪音的波，再加反向波。
- **关键画面落定后至少停 2 s**，再切走或换字：错误图像、打叉、部件内部、机制变化、名词、分屏、闭环动作。
- **镜头推进、钻入、拉出 ≥ 1.5–2.25 s**；渐变（反向波出现、抵消）≥ 1 s。
- **画面先给答案，字幕后到**（领先 0.5–1 s）。
- 拉长时间优先给"看"，不加新内容；任何一段都不能超过 3 s 没有新事件。

## 文字量（降噪耳机 v1→v2 的教训：文字太多看不过来）

- **只保留理解当下画面必需的字。** 同一时刻屏上最多：一句字幕（≤ 2 行）+ 1–2 个短标签（最好 ≤ 3 个字）。
- 不加解释性小字（"空气不动，鼓膜就不动""所以芯片要在几十微秒里算完"）、尺寸标注、名词下面的回扣小字——画面已经说明的，就不再写。（专业名词例外，见「文案」：要出现时用小字）
- 标签只给后面还会用到、或画面里认不出的东西（"芯片""扬声器""鼓膜""芝麻"）；字幕已经说出名字的东西不再贴标签（字幕说了"麦克风"，麦克风上就不再写）。
- 说话气泡上方只写部件名，不再加"告诉芯片："一行。
- 慢放、示意只用两个字的小标（"慢放"）。

## 画面密度（EP.04 风格测试的教训：画面太满，观众就看不下去、也吸收不了）

- **一个画面只有一个看点。** 观众第一眼就该落在这一拍要讲的东西上；别的东西要么退成背景（变灰、变暗、虚掉），要么不出现。
- 同一时刻屏上只放：一个主体 + 一个正在变化的东西（光、读数、指针）+ 一句字幕（≤ 2 行）+ 最多 1–2 个短标签。装饰性的东西（家具、底纹、图号、标题栏、角标、状态读数）一律不加。
- 新元素一个一个进：上一个看懂了，再进下一个；讲完就退场，不在画面里越攒越多。
- 选风格时先问：**把它减到"一个主体 + 一束光 + 一句字"，它还像它自己、还好看吗？** 靠堆元素才成立的风格（全息界面、电路板底纹、等距小房间、蓝图标题栏）不适合本系列。

## 从 降噪耳机学到的（已并入模板）

- **开场必须是一眼能认出的整体**（人头 + 耳机、整台手机），剖面和透视只放在整体里的一个"窗口"里；不要用解剖剖面开场。
- **亮场景的字幕区也要有同底色的柔和遮罩**（误区段用橙色），任何轮廓线都不从字幕后面穿过。
- **部件标签放在物体外面，用细引线指过去**，不压在零件上；跟随信号时先让镜头停稳，再走信号、再出标签。
- **声音类题材让配乐直接演示原理**：降噪耳机的地铁轰鸣层由画面的抵消量驱动，开场按下那一刻节拍才落下。
- **用表情做最小的情绪线**：一只眼睛（"＞"→"︶"）就够了，不加完整五官。
- 暗场溶接 ≤ 0.25 s，避免中间出现发灰的帧。

## 从 微波炉学到的

- **钻进去要一镜到底**：从物体一路推到最小的那一层（微波炉 → 碗 → 饭 → 一粒米 → 米里面的水分子），镜头匀速一直往里，暗场在最后一刻接上，暗场里继续往里推，不切、不回头。
- **"为什么"要演出过程，不能只给结果的分布**：微波炉 v1 的"被水吃掉"只画了一条越来越矮的波和一片渐变色，看不懂；v2 让水分子排成一列一列，波每经过一列被"咬"掉一截、那一列变橙，走到第四列就没了——每咬一口还有一个越来越轻的音。
- **闭环不硬套拟人对话**：部件开口只用在它本来就会"报告"的东西上（陀螺仪、麦克风）。微波炉的"我在扭！""还没轮到我…"很尬，改成在宏观画面里把机制再演一遍：微波一道道钻进饭的外层就消失，虚线标出它到得了的地方，外圈变橙，中间一直灰。
- **字幕和标签不放在 y > 1450 的位置**：平台底部的标题、简介会挡住（微波炉 v1 的"两三厘米"在 1530，被挡了）。
- 用户给定的字幕原话照用；放不下就拆成三行（96 px），不缩小字号到和别的字幕不一致。
- **"还有一个部件"要演出来它在干什么，不能只介绍它**：它听到/感到什么 → 告诉谁（气泡飞进芯片）→ 结果怎么变（读数回 0），三步都在同一个画面里看得见。
- **闭环要让人看见、听见效果**：把机制段里的同一个读数（降噪耳机是"听到的噪音"）在闭环里再走一遍；部件开口时气泡出现在部件自己身上；按下之后不要用鼓和上升音效盖住效果。
- **字幕措辞和屏上读数一致**：读数还剩 62%，就不能说"抵消不掉"，要说"抵消不干净"。
- **AAC 编码用 `-aac_coder fast`**：ffmpeg 默认编码器会在瞬态上冒出 +5–8 dB 的爆音（EP.01 发布版里有 11 处）；`verify.sh` 里用 `tools/aacspikes.py` 查。

## 示意画法：新元素先示意，再示意它的影响（用户 2026-11-14，EP.07 起）
用户原话：「最好的一种示意就是画面出现那个新元素就先示意它，然后它又带来哪些影响接着示意，这样观众可以一直跟着我们的演示和画面走，也可以更好的吸收我们的传播」；同时指出「真正的原理部分画面很小，下边用不到的地方占比太大」「接到的光变少不够一眼看见，要自己来回找」。
1. 新元素第一次出现时先示意它：点亮它、画一个橙框、标名字（小字），其余部分压暗（聚光）。
2. 紧接着示意它带来的影响，一次只让一个东西在变；有因果的几步依次点亮，步与步之间用橙色小箭头接上（例：血管变粗 → 读数降低 → 曲线落下）。
3. 观众要看的现象放在一条视线上，不让人在画面上下两处来回找；解释小字贴在被解释的东西旁边。
4. 讲原理的区域占满可用面积（字幕下方到 y 1450 之间），不放用不到的背景层（例：剖面里用不到的脂肪、肌肉层改为暗底）。
