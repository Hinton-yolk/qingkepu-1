# 远景 PoC 05：数据中心冷通道，Cycles 对 LTX

DECISIONS 11-14 记的下一步：「测一个远景氛围镜头，看 LTX 在它擅长的地方比 Cycles 好多少」（用户：「我们再测试一个远景的」）。

## 镜头
- 数据中心冷通道：两排 42U 机柜面对面，中间是开孔通风地板，头顶是黄色光纤槽、黑色梯架和条形灯，空气里有薄雾。服务器、存储、交换机面板是程序生成的贴图（`make_panel_textures.py`，示意，不是某个真实型号），带绿、蓝、琥珀色指示灯。
- 相机从通道口匀速推进约 3.3 m，后半段转向右侧第 5 台机柜第 27U 的一台 1U 交换机（OSFP 口插着绿色拉环模块，呼应插入镜头）。
- 24 fps、145 帧（6.04 秒）、1088×1920，按原生 24 fps 渲染（PoC 04 的教训：不再从 30 fps 降帧）。
- 脚本：`build_aisle.py`。`frames` / `anim` 出 Cycles，`clay` 出 Workbench 灰模，灰模和 Cycles 同场景、同相机、同尺寸。

## 三版
| 版本 | 怎么出 | 机器 / 用时 / 费用 |
|---|---|---|
| **Cycles** | 96 采样 + 降噪，薄雾体积，动态模糊 | RunPod 两台 RTX 4090，墙钟 12.1 分钟，约 **$0.36**，每帧约 8–9 秒 |
| **LTX V1** | 灰模 + Cycles 首帧 | RunPod A100-SXM4-80GB（$2.19/时），两版共墙钟 17.1 分钟，约 **$0.62**；下载权重 255 秒，V1 生成 314 秒、V2 277 秒 |
| **LTX V2** | 灰模 + Cycles 首、中、末三帧（第 0、72、144 帧） | 同上 |

- 灰模在本机 CPU 上用 Workbench 渲，145 帧，费用 0。
- 费用都是脚本按单价和墙钟时长估的上限，以 RunPod 账单为准。所有机器都已删除。
- LTX 打开了隐形标记：两版视频都检测到（bit accuracy 1.0），音频检测不稳（0.5），和 PoC 04 一样。原始结果见 `deliver/marks.txt`。

## 看到的
- **三版都跟住了灰模**：推进速度、转向、终点构图一致。
- **Cycles**：面板细节清楚（硬盘托架、指示灯、交换机的 OSFP 口和绿色拉环）；运动平稳，逐帧差值没有突变。只有第 51 帧通道远处的地板单帧变暗（亮度差 2.7/255），大约是降噪的偶发误差，正常播放时很难察觉。
- **LTX V1（只给首帧）**：
  - 指示灯更绿、更显眼，有一点「电影感」；
  - 但**改动了结构**：约 4.5 秒，通道尽头变成一个浅灰色房间的墙角，左边那排机柜被截短；
  - 结尾的交换机变糊，面板被重画成一条条发绿光的横带，**认不出 OSFP 口**。
- **LTX V2（三帧约束）**：几乎就是 Cycles 的复制，雾和反光略有差别。没有比 Cycles 更好看，只是多花了钱和时间。

## 结论（建议，待用户定）
- **这个远景里，LTX 没有比 Cycles 好**：V1 好看的部分不多，还改了结构；V2 只是在复刻 Cycles。
- 原因在测试设计：LTX 的外观来自关键帧，而关键帧就是我们的 Cycles 帧，所以它很难超过 Cycles。这个场景又是规则的机柜、面板，正好是程序建模的强项，Cycles 本身已经够好。
- **LTX 真正可能有优势的情况**：用 Cycles 做起来很费劲的画面，比如人、手、真实的杂乱环境；同时首帧换成**图像模型生成的写实图**，而不是 Cycles 帧。如果还想测，下一次应该按这个方向设计。
- 在那之前，**远景和近景都用 Cycles** 更省事：确定性强，单次约 $0.36 / 6 秒，不需要额外查编出来的结构。

## V3：首帧换成 GPT 照片级图（2026-11-14 晚）
用户的思路：Cycles 和 LTX 的「塑料感」来自我们自己画的参考帧，所以先用 Cycles 出灰模，用户拿灰模让 GPT 生成写实照片，再用这张照片当参考。用户：「两步一起做，先跑V3」。
- **输入**：灰模（本机 CPU 重渲，Workbench，约 2.5 秒一帧，6 分钟）+ GPT 照片当首帧（`deliver/gpt_output/gpt_first_0s.webp`，944×1666，缩放到 1088×1920，长宽比几乎一样）。提示词照照片补了顶棚的梯架、青色线缆、管道和尽头的白墙（`ltx_in_v3/run.sh`）。
- **GPT 有没有守住构图**：和灰模首帧叠在一起看，通道、消失点、端墙、机柜高度大致对得上；GPT 自己加了很多顶棚结构（梯架、管道、喷淋管），左排机柜的边线有些偏。
- **机器**：A100-SXM4-80GB，$2.19/时。墙钟 11.2 分钟，约 **$0.41**：下载权重约 2.5 分钟，等灰模渲完约 2 分钟，生成 272 秒。机器已删除。
- **输出**：`ltx_out_v3/v3_gptfirst.mp4`，1088×1920，24 fps，145 帧（不进仓库）。sha256 见提交说明。隐形标记：视频检测到（bit accuracy 1.0），音频不稳（0.5）。
- **看到的**：
  - 整段跟住了灰模：推进、转向、结尾构图都对得上。
  - 照片的质感一直保持到最后一帧：黑色顶棚和成捆的青色线缆、黄色光纤槽、地板上灯的倒影、六角冲孔网门、门把手、门后服务器的指示灯。结尾特写（`out/v3_end_zoom.jpg` 不进仓库）没看到编出来的怪结构。
  - 结尾那台交换机认不出来：GPT 首帧里没有它，灰模里它只是一块面板。这次测的是远景，不影响结论；要特写就得给末帧关键帧。
  - 稳定：逐帧差值最大的几帧（126–128）正好是相机转得最快的时候，和灰模的节奏一致；相邻帧平均亮度最大跳 2.3/255，没看到闪烁。
- **初步结论**：首帧换成照片级图以后，LTX 在远景上明显超过了我们的 Cycles（PoC 05 的 Cycles 版和 V1、V2）。PoC 05 前面的结论「LTX 没胜过 Cycles」要改成：**LTX 好不好看，取决于首帧；首帧是照片级，它就能把照片级的质感带过整段运动。**

## 第二步：Cycles 照着照片复刻
- 脚本：`build_aisle_photo.py`（相机、布局和 `build_aisle.py` 一样，灰模通用）+ `make_photo_textures.py`（冲孔网门、冲孔地板）。
- 照着照片补的：白色端墙和洗墙灯、冲孔网前门和把手、门后的蓝 / 黄跳线、亮的冲孔金属地板（低粗糙度，能映出灯）、裸露的黑色顶棚（横向支架、梯架和成捆的青色线缆、横跨通道的梯架、银色线管、红色喷淋管、烟感）、箱形吊灯（间距 1.9 m）、U 形黄色光纤槽和托架、吊杆、下线口。
- 静帧迭代了四轮（544 宽、32 采样，本机 CPU 每张约 55 秒），用 `tools/frame_stats.py` 对平均亮度：0.54 → 0.36 → 0.29 → 0.29（照片 0.29）。
- **整段**：96 采样，RunPod 两台 3090（一台 Community $0.22/时 20.5 分钟、一台 Secure $0.5/时 18.0 分钟），约 **$0.34**（脚本上限估计）。第一台分到的 Community 4090 坏了（`cuInit: Unknown error`），脚本按规矩不退回 CPU、一分钟内停下删机，失败的两段改到 Secure 重渲。`out/aisle_cycles_photo_1088.mp4`（不进仓库）sha256 45f42f0b7442016a6d37be200e112d6d3fb1ad1d1fe680563326f5477652e56f。
- 稳定：逐帧差值中位数 6.1，最大 14.0（相机转得最快处，和 V3 同一段）；相邻帧平均亮度最大跳 2.3/255。

主 agent 看到的：
- **照片对标版比原版前进了一大步**：黑顶棚、管线、冲孔亮地板、白端墙、门和跳线都有了，亮度也对上了照片。
- **但仍看得出是渲染的**，和 V3 并排更明显：
  - 顶棚太空：V3 顶上是密密麻麻的梯架和成捆线缆，我们只有几道；
  - 黄色光纤槽底面发暗发橄榄色，下线口看起来像柱子；
  - 灯和地板倒影太硬（亮部 95 分位 0.85，V3 0.65），像影棚光，不像机房里漫射的光；
  - 网门后的设备偏灰、偏整齐。
- 主 agent 的估计：照片对标版的真实感约为 V3 的六到七成（和之前估「六到七成把握」一致）。要再往上，主要是顶棚的杂乱程度和光的柔和度，每一项都要再花一两轮。

## 结论（建议，待用户定）
- 首帧是照片级时，**LTX V3 是这个远景里最像真的一版**，费用和 Cycles 同一个量级。PoC 05 前面「LTX 没胜过 Cycles」的结论只对「拿 Cycles 帧当首帧」成立。
- 可能的分工修正（待用户定）：**远景 / 氛围镜头**走「Cycles 灰模 → GPT 照片级首帧 → LTX」；**讲机制、看结构的特写**仍用 Cycles（确定性，器件不能编）。照片对标的做法（照着 GPT 照片调 Cycles）也值得留着：它让 Cycles 版明显变好，可以用在必须用 Cycles 的镜头上。
- 风险：GPT 照片会自己加结构（这次加了顶棚管线、左排偏移），LTX 会照着它补细节；每段都要逐帧查有没有不合理的东西。
