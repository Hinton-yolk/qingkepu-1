链路：Blender 灰模（V1.1 S04）+ 用户用 GPT Image 画的三张照片级关键帧 → LTX-2.5 Layout-To-Render → 一段约 5 秒的写实镜头。
用户 2026-11-16 批准预算（预计 $0.45–0.60，上限约 $1.30），并确认图片对应：上传的第 3 张 = F001，第 1 张 = F090，第 2 张 = F150。

## 1. 结论（先说）
- **相机运动：成立。** LTX 跟住了 Blender 的推拉和机位，三个关键时刻都和照片几乎一致。
- **三张照片的外观：基本连成了一个镜头。** 没有「三张图之间硬变形」的感觉；材质、色调、光缆颜色一路一致。
- **结构稳定性：不合格。** 有三处明显的生成错误，其中两处会被行家和普通观众一眼看出：
  1. **0.8–1.0 秒，光缆连续性断开**：光缆往下插进理线槽底板上的一个「孔」，旁边又冒出另一段光缆；
  2. **3.8–4.3 秒，机柜前面板融化**：服务器面板变成皱巴巴的锡纸 / 鳄鱼皮纹理；
  3. **4.4–4.7 秒，光缆变粗、拖影、饱和度过高**。
- **能不能直接发布：不能。** 0–0.7 秒、1.5–3.5 秒、4.8–5.0 秒这几段的画质接近可用；问题集中在相机运动最快、离关键帧最远的两段。
- 成本上这条路成立：一次 5 秒约 $0.24，生成本身约 4 分钟。

## 7. 可能的原因
1. **快速、大尺度的相机运动 + 关键帧间隔长**：第 72 帧到第 120 帧之间，相机从两台机柜的全景推到一只插头的特写。这一段 LTX 只有灰模的轮廓可依，服务器面板在灰模里只是平的灰块，模型就自己「编」纹理，结果编成了皱纸。
2. **灰模里光缆的走法在这个机位上有歧义**：光缆先向前、往下，再折回理线槽。从 F001 的机位看，「往下再折回」被读成「插进槽底」。关键帧照片里光缆在画面右边出了画，没有提供这一段的信息。
3. **光缆在近景里很粗、很饱和**：照片里光缆就是醒目的浅绿松石色，LTX 在运动模糊时进一步放大了饱和度和粗细。

## 8. 如果要再试一次（**没有做**，等导演定；每次约 $0.25）
按性价比排序：
1. **在第 96 帧（4.0 秒）加一张 GPT 关键帧**，正好盖住融化的那一段。需要用户用灰模第 96 帧再出一张照片。我可以先出这张灰模帧和提示词。
2. **给灰模里的服务器前面板加结构**：风孔、把手、硬盘位的分格，让 LTX 有东西可「照着画」。只改硬件外形，不改相机和路线。
3. **把 A 端光缆的走法改成一眼能看懂**：例如出了插头直接向下垂进槽里、再顺着槽走，不再「往前再折回」。这会改到已批准的物理路线，要导演同意。
4. 把相机在 3.0–4.6 秒的推进放慢一点：这会改已批准的运镜，要导演同意。
