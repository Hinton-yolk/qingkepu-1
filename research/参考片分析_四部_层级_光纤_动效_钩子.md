### A.2 层级语法（从 A 归纳）
1. **数量递增地聚合**：2 → 4 → 6 个器件，每次聚合都贴一个新名字和符号。
2. **聚合后立刻换表示法**：3D 写实 → 盒子 → 符号。换之前先让观众看清盒子里装的是什么。
3. **拉远成阵列**：一个 → 整片同类，用来给规模感。
4. **类比只在最底层用一次**（乐高），之后沿用同一个类比往上搭，不换比喻。
5. **每升一级，新部件「从上方落下拼接」**（drop-in）：同一种动作反复出现，观众一看就知道「又往上升了一级」。
6. **3D 实物和 2D 符号并排**：先并排对照一次，之后才能单独用符号。
7. **上一层是「缝合」下一层的东西**：例如 M1 金属线盖在单元方阵上，说明聚合不是随便框起来，而是靠连线实现的。

### A.3 迁移：一个比特 → 电信号 → 光信号 → 多通道光互连 → 数据中心（6 个原创连续镜头，竖屏）

| # | 镜头 | 抽象操作 | 抽象发生的时刻 | 解释收益 | 信息损失 | 误导风险与对策 |
|---|---|---|---|---|---|---|
| 1 | **一个比特**：画面中心一个方块「1」，旁边一个「0」；底部时间轴，每个比特占一格（标「一格 = 一个比特的时间」） | 起点（符号） | — | 先建立「比特 = 一格时间里的 0 或 1」 | 比特的物理载体还没出现 | 观众以为比特是「东西」；对策：下一镜马上让它变成电压 |
| 2 | **电信号**：方块下沉成电压台阶，高 = 1、低 = 0，一串台阶沿走线向右跑 | 符号 → 物理量（形变：方块变台阶） | 方块落到时间轴上的那一帧 | 「比特就是电压高低」 | 真实波形有上升时间、噪声 | 台阶画得太方；对策：边缘稍微圆一点，标「示意」 |
| 3 | **光信号**：台阶进入激光器 / 调制器，出来变成光的亮暗；画面左半是电台阶，右半是同节奏的光强包络 | 换载体（电 → 光），**一一对应** | 台阶穿过调制器的那一帧 | 「光的亮暗跟着电压走」 | 波长、相位、偏振都不讲 | 以为所有光通信都是亮 / 暗；对策：角注「最简单的一种：开关调制」 |
| 4 | **多通道**：这一路光收进一根细线；镜头拉远，复制出 8 条并排的同样的线（8 路 × 每路 100 Gb/s），合成一个光模块 | **复制 + 阵列**，再**聚合**成一个盒子 | 拉远到能看到第二条线的那一帧；8 条线收进模块外壳的那一帧 | 「总带宽 = 通道数 × 每通道速度」 | 每一路内部看不见了 | 以为 8 路一定是 8 根光纤（也可能是同一根光纤里 8 个波长）；对策：只说「8 路」，角注两种做法 |
| 5 | **交换机**：一个光模块插进交换机面板，复制成满满一排端口（例如 64 个）；交换机变成一块发光的面板图标 | 复制 + 空间排列 → 符号替换 | 面板插满、开始缩小成图标的那一帧 | 规模：一台交换机 64 × 800G | 模块细节消失 | 端口数随型号不同；对策：数字标「例如」 |
| 6 | **数据中心**：交换机图标复制成几十个机柜，排成行列；机柜之间连出光纤线束，再拉远成整栋楼，屋顶上标一个读数（总带宽） | 阵列 + 空间排列 + 缩放 | 从一排机柜拉远到整栋楼的那一帧 | 「一个比特」一路放大到「整个数据中心」 | 拓扑、交换层级都简化了 | 看起来像一张平面网，实际有多层交换；对策：用 2–3 层高度区分，角注「示意」 |

**贯穿元素**：同一个「1」方块用暖色高亮，一路跟到第 6 镜（在数据中心的某一根光纤里还能找到它）。对应 A 里「跟着同一个对象」的做法。

**借 A 的 drop-in 和并排对照**〔建议〕：
- 第 4、5、6 镜每升一级，都让新一级的外壳**从上方落下罩住**下一级（光纤束 → 模块外壳 → 交换机机箱 → 机柜 → 楼）。
- 第 3 镜「电 → 光」用并排对照：左边电压台阶，右边光强包络，同节奏。
- 防止「导线悬空」式误解：线束和光纤都画在托架或线槽里，不让它们飘着。

### B.2 核心问题：会不会让人以为所有光纤都按折线走？〔判〕
**会。** 从 2:34 到 3:43，光纤里的光一直画成陡峭的折线，弯曲处也是折线，**从头到尾没区分单模和多模**。最后 5:00 的光脉冲改成沿中心直线跑，但没有解释为什么换了画法。

正确的三层区分：
1. **几何光学（折线）**：只适合讲**多模光纤**的直觉，而且折线应该很平（贴着轴）。
2. **模式传播**：单模光纤（9 µm 纤芯，数据中心之间和长途的主力）里光是**一个场分布沿轴传播**，截面上是中间亮、边缘暗的光斑，有一小部分在包层里。不能画成反弹。
3. **脉冲调制**：信息在**光强随时间的变化**里（亮暗、或更复杂的相位和幅度），和光在纤芯里怎么走是两件事。画面要把「光往哪走」（空间）和「光怎么变化」（时间）分成两张图。

### B.3 原创 10 秒动画：调制信号 → 光纤 → 损耗 / 色散 → 探测器

**场景设定**（示例参数，角注写明）：单模光纤，1550 nm，25 Gb/s 开关调制（每个比特 40 ps），光纤长 20 km。
**数量级**（进 FACTS 前再核）：
- 光在玻璃里约 2×10⁸ m/s，20 km 用时 0.1 ms。
- 每个比特在光纤里占 40 ps × 2×10⁸ m/s = **8 mm**。
- 损耗约 0.2 dB/km → 20 km 共 4 dB，剩约 40%。
- 色散约 17 ps/(nm·km)。按信号谱宽约 0.2 nm 估算，20 km 后脉冲约展宽 70 ps，接近 2 个比特宽：会开始互相重叠。

| 秒 | 画面 | 每个图形的物理含义 |
|---|---|---|
| 0.0–2.0 | 左：电压台阶「1 0 1 1 0 1」（横轴 = **时间**）进入调制器；右：同节奏的光强包络 | 台阶高度 = 电压；包络高度 = 光功率（线性）；横轴都是时间，每格 40 ps |
| 2.0–4.0 | 镜头转到光纤侧视：纤芯（9 µm）和包层（125 µm）按比例画；光**沿轴**前进，一串明暗块，没有折线；右上角一个小截面：中间亮的光斑 | 侧视横轴 = **位置**（每个明暗块长 8 mm，标出来）；截面光斑 = 光强的空间分布（单模） |
| 4.0–7.0 | 距离尺从 0 km 走到 20 km，中间画断裂符号「≈」表示压缩；明暗块越来越**暗**，边缘越来越**糊**，相邻的块开始连在一起 | 亮度变暗 = 损耗（标「−4 dB，剩约 40%」）；边缘变糊 = 色散（标「不同颜色的光跑得快慢略有不同」） |
| 7.0–9.0 | 光到达光电二极管；输出电流波形（横轴 = 时间），一条判决门限横线 | 电流 ∝ 光功率；门限 = 判 0 / 1 的标准 |
| 9.0–10.0 | 在每个比特中点取样，读出「1 0 1 1 0 1」；有一位落在门限附近闪一下，角注「再远就会判错，所以要补偿或放大」 | 取样点 = 判决时刻 |

**避免时间和速度比例错误**
- 右上角常驻「**慢放约 10⁹ 倍**」，因为光真实走完 20 km 只要 0.1 ms。
- 「位置图」和「时间图」用不同底色，标清横轴单位，不混在一张图里。
- 距离尺的压缩用断裂符号表示，不假装连续。
- 损耗用对数刻度标 dB，同时给出线性的「剩多少」。

**Remotion 思路**：
- 时间图和位置图是两个 `<svg>` 组件。
- 包络用 `path` 按 `bits[]` 生成；色散用对每个脉冲做高斯卷积，宽度 σ(z) 随距离 `interpolate` 增大；损耗用幅度乘 `10^(-0.02·z/10)`。
- 慢放倍率和距离尺是 HUD 组件。

## C. 动效转场：5 个最值得迁移的技法（全片约 1:32；0:00–0:40〔G〕，0:40 以后〔App〕；精度 ±0.5 秒）

**0:40 以后新增的代表性转场〔App〕**
- 0:46–0:48 **shape morph + mask reveal**：两手捏住的线框立方体被压扁成圆球，回弹后放大成全屏遮罩，透出彩色风景。有明显的挤压回弹，约 1 秒。
- 0:51–0:52 **match cut**：抛起的硬币 → 弹吉他的人，硬币的黄色和圆形正好对上吉他音孔。
- 1:00–1:03 **match cut**：白色圆环 → 黑色对称几何线条，共享正圆轮廓和中心发散运动。
- 1:10–1:11 **match cut**：滚落的红球 → 角色的蓝色躯干，共享下落位置、下落速度和圆形；没有镜头运动。

**综合两段挑出的 5 个技法**（下表）：

| # | 技法（Gemini 分类） | 时间 | 前后共享的东西 | 节拍 / 缓动 |

| 1 | **真 match cut（图形）** | 0:13.0 | 一个红球，**大小和画面位置完全一样**：前一镜在水里，后一镜在 UI 版面里 | 卡在拍点；约 0.2 秒、带回弹 |

### C.1 迁移到光互连（原创）+ 实现路线

| 技法 | 原创应用 | 关键帧相对时序 | 实现 |
|---|---|---|---|
| 图形 match cut | 光纤**截面**（包层圆 + 纤芯圆）→ 光模块 **LC 接口**的圆孔：圆在画面中心、大小一致 | 前镜最后 2 帧圆心对准画面中心 → 切 → 后镜第 1 帧同一位置、同一半径，之后 6 帧回弹到正常大小 | Remotion：两个 `<Sequence>` 首尾相接；后镜 `spring({fps, frame, config: {damping: 12, stiffness: 220, mass: 0.6}})` 驱动 scale 1.08 → 1 |
| shape morph | 电压**方波**的一个台阶 → 光强**包络**（圆角）→ 探测端的**眼图**一格 | 0–8 帧方 → 圆角，8–16 帧单个 → 叠加成眼 | SVG path 插值：先把三条路径重采样成相同点数（或用 flubber），`interpolate(frame, [0, 8, 16], …)`，`Easing.bezier(0.34, 1.56, 0.64, 1)` 带回弹 |
| mask reveal | 交换机面板上一个圆形「放大镜」从端口中心张开，里面是光模块内部 | 0–12 帧圆半径 0 → 屏宽 60%，12–18 帧回弹 | `<clipPath><circle r={r}/></clipPath>` 包住内部画面层；r 用 spring；边缘加 2 px 描边环 |
| camera whip | 从链路发送端的交换机**甩到**接收端的交换机（方向 = 光的传播方向，从左到右） | 前镜最后 5 帧加速向左平移 + 横向模糊 → 切 → 后镜前 5 帧从右侧减速进入 | 平移 `Easing.in(Easing.cubic)` / `Easing.out(Easing.cubic)`；模糊用 SVG `<feGaussianBlur stdDeviation="24 0"/>`（只在 x 方向）；3D 场景用 Three.js 相机平移 + 后期运动模糊 |

## D. 短视频钩子与节奏（〔G〕+〔App〕交叉核对）

### D.1 结构
- **0–3 秒**：一个具体动作（女孩把红铅笔插进透明外壳的蓝色卷笔刀，转动摇柄）。**动作本身制造问题**。
  - 〔App〕外壳上印着「ZACK D. FILMS」。
  - 〔G〕说屏幕上有大字「HOW DO THESE WORK?」和一句提问旁白；〔App〕没看到这行字，也说拿不到音频。**这两条以 App 为准，存疑。**
- **约 2 秒**〔App〕（API 说约 3 秒）：镜头向前推进，**直接穿过半透明塑料外壳**进到内部，没有切。
- **视觉更新间隔**（Gemini 记录）：0.3、0.6、0.5、4.3、0.8、1.0、2.1、2.9、2.9、1.9、2.7、2.5、0.6 秒，中位数约 2 秒，大多在 2–3 秒，只有一处 4.3 秒。
- **结尾**：回到外面，取出削好的铅笔写字（回到开头的实物）。

### D.2 虚构内容（只能借鉴节奏）
**真实机构**〔App〕：金属齿轮组（大齿轮 + 小齿轮，0:03 起一直在）、圆柱形螺旋铣刀（0:09、0:22 清楚可见）、被削去木皮的红铅笔和笔芯（0:22 起）。
**虚构 / 夸张元素**〔G〕〔App〕两个来源基本一致：
- 随齿轮上下动、戴蓝色礼帽的霸王龙头（0:04）；
- 趴在传送带上又站起来的大耳朵小狐狸 / 小老鼠（0:05–0:08）；
- 吊在绳上、戴安全帽护目镜的工人（0:10，0:16 拿写字板，0:24）；
- 吊在绳上挥斧头的格子衫伐木工（0:10、0:21）；
- 被工人抓着啃圆锥形木头的海狸（0:11、0:19）；
- 绑在齿轮上跟着转、翻白眼的土拨鼠 / 松鼠（0:33，〔App〕）。

**结论**：真实机构和虚构角色**混在同一个画面里**。真实部分（齿轮、螺旋刀）是骨架，虚构角色负责每 1–3 秒给眼睛一个新东西。
- 我们只借「真实机构做骨架 + 每 2–4 秒一个新视觉」的节奏；
- **虚构角色不能用**：我们讲的是真实器件，一个虚构的小人就会让行家怀疑整条片子的可信度。
- 节奏上可以换成**真实但人们没注意过的细节**（例如电场线、扫描光带、读数）。

### D.3 迁移：「按下手机屏幕的一瞬间，触控控制器如何感知？」（横屏 16:9，约 42 秒）

**技术底子**（进 FACTS 前逐条核实）
- 手机多用**投射式电容屏**：盖板玻璃下面有一层透明电极网格（ITO 或金属网格），一组是驱动线（TX），一组是接收线（RX）。
- 控制器依次给每条 TX 线加激励信号，在每条 RX 线上测**互电容**。
- 手指导电，会把一部分电场「引走」，所以手指下方那几个交叉点的互电容**变小**。
- 整张网格扫描一遍，得到一张「电容变化图」；按变化量求加权中心，得到比电极间距更细的坐标；再通过 I²C / SPI 报给主芯片。
- 采样率常见 120–240 Hz，部分游戏手机更高。具体数值和电容量级要查证。

| 秒 | 画面 | 每 2–4 秒的视觉更新 | 准确性要点 |
|---|---|---|---|
| 0–3 | 微距：一根手指落向手机屏幕，触碰瞬间画面定格；大字「按下这一瞬间，手机怎么知道你按在哪？」 | 定格 + 大字 | 具体动作就是问题 |
| 3–6 | 镜头穿过盖板玻璃，各层依次掀开：玻璃 → 光学胶 → 触控电极层 → 显示层 | 每 1 秒掀一层 | 角注「触控层的位置因机型而异（可能做在显示屏里）」 |
| 6–10 | 电极网格亮出：横线 TX、竖线 RX（菱形图案）；一条 TX 发光，电场线弧形连到 RX | 网格出现 → 一条线点亮 | 场线是示意，标「电场（示意）」 |
| 10–14 | 手指靠近，部分场线弯进手指；该交叉点旁的读数条从 100% 掉到约 85% | 场线被引走 + 读数下降 | 方向要对：互电容**变小**（不是变大） |
| 14–18 | TX 一条接一条扫描（从上到下），右上角标「扫完一遍：几毫秒」 | 扫描光带移动 | 依次扫描，不是同时；时间要标 |
| 18–23 | 整张网格变成热力图，手指下面亮出一团；中心出现十字准星，坐标数字跳出 | 热力图 + 准星 | 位置是插值算出来的，可以比格子细 |
| 23–28 | 坐标沿一条细线送到主芯片，App 里的按钮按下变色 | 数据流 + 界面反馈 | 角注「从触碰到画面变化：几十毫秒」（待核） |
| 28–34 | 对照：戴上普通手套再按，场线不被引走，读数不变，画面没反应 | 手套出现 + 无反应 | 和「为什么」系列 EP.04（戴手套点不动）呼应，**注意不要重复做成同一条** |
| 34–39 | 拉回外面：手指抬起，读数恢复，热力图熄灭 | 层层合上 | — |
| 39–42 | 一句话结论：「屏幕下面是一张电容网，手指一碰，电场就少了一点」 | 结论字 | 回扣开头的定格 |

**注意力结构**：开头 3 秒用具体动作制造问题，3 秒内进到物体内部，之后每 2–4 秒一个新画面元素，结尾回到外面的同一个动作。这些是从 D 借来的节奏；D 的虚构内容一概不借。
