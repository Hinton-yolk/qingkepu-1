# 数据周报

用户每周手动导出数据（不自动登录平台：两个平台的用户协议都禁止自动化程序登录或收集信息）。
你负责整理、诊断、给出下周改什么，并把结论沉淀进规则。

## 1. 收数据
- 放进 `data/<YYYY-MM-DD>/`：原始截图放 `screenshots/`（文件名：`<平台>_<视频短名>_<页面>.<ext>`），Excel 原样保存。
- 把每条视频整理成 `metrics.csv`，列和 `data/2026-11-06/metrics.csv` 完全一致；小红书行的 `platform` 写 `xhs`。
  小红书的「2 秒退出率」填进 `bounce_2s_pct`，「平均观看时长」填进 `avg_watch_s`。截图里看不到的数据留空，不要估。
- Excel 用 Python 读（`python3 -I`，pandas 或 openpyxl）。读不出的列，照实说明。
- 注明每条视频截图时**发布了多久**：比较两条视频时，尽量用相同发布时长的数据（例如都看 48 小时）。

## 2. 诊断（按这个顺序看）
基准来自 2026-11-06 的快照，有新数据后更新这里。

| 关卡 | 指标 | 好 | 差 | 当前最好 |
|---|---|---|---|---|
| 1 开头 | 2 秒跳出率 | < 30% | > 45% | 20.5%（微波炉） |
| 2 前 5 秒 | 5 秒完播率 | ≥ 50% | < 30% | 50.2%（陀螺仪） |
| 3 留存 | 平均播放占比 | ≥ 30% | < 10% | 29.8%（陀螺仪） |
| 4 互动 | 点赞率 / 收藏率 | ≥ 1.5% / ≥ 0.4% | < 0.5% / < 0.1% | 1.7% / 0.46%（陀螺仪） |
| 5 长尾 | 搜索流量占比 | 越高越好 | — | 9%（光互连 01） |

- 先看关卡 1：没过的话，后面的问题都还没被检验到，不要下「内容太深」之类的结论。
- 有进度分析图（回看率 / 跳过率）时，把峰值的时间点对到该集脚本（`episodes/<系列>/<集>/`），指出具体是哪一句、哪个画面。
  回看峰值在开头，通常是第一句没听清或第一帧信息太多；跳过峰值在铺垫段，说明观众在找重点。
- 涨粉、点赞、收藏按每千次播放来比，不要直接比绝对数。
- 抖音和小红书分开比，再对比同一条片子在两个平台的差异。
- 样本量小时说清楚（例如「5 秒后只剩约 220 人」），结论标成「方向」而不是「定论」。

## 3. 写报告：`data/<日期>/REPORT.md`
1. **一句话结论**：本周最重要的一件事。
2. **数据表**：本周每条视频的关键指标，按 2 秒跳出率排序。
3. **逐条诊断**：每条 2–3 行，指出卡在哪个关卡、对应脚本里的哪一段。
4. **下周改 3 件事**：每件对应一条具体规则（`CLAUDE.md` 或系列 skill 里的哪一行），写清楚怎么改。
5. **实验进展**：正在跑的实验（见 `DECISIONS.md` 第 12 条：光互连完整版发小红书 vs 拆条发抖音）现在能得出什么。
6. **待定问题**：`DECISIONS.md` 里标「待定」的事项，这周的数据能不能回答。
   - 第 5 条「主阵地」：需要小红书单条数据，有了就给出判断和理由。

报告用中文，先结论后细节，让用户在手机上 1 分钟能看完重点。

## 4. 把结论沉淀进规则
- 有被数据支持的新规律，提议改 `CLAUDE.md` 或对应系列的 skill，**用户同意后再改**。
- 改动涉及 `DECISIONS.md` 里的决定时，同时更新那一条，并在「变更记录」写一行。
- 更新上面的基准表。
- 提交时只提交 `data/<日期>/` 和改过的规则文件。
