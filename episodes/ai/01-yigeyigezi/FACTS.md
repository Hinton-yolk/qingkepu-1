# FACTS · EP.01 AI 为什么一个字一个字往外蹦？（对应文案 v3；第 13–17 条为 11-19 补的内容）

〔事实〕查得到；〔示意〕〔类比〕〔估算〕片中已加注；〔待核对〕写进片子前要对原文。

## 1. 大模型一次只生成一个 token，下一个 token 以前面所有 token 为条件〔事实〕
- 片中：「它真的只能一个字一个字地写」「前一个字没定，后面的字没法写」。
- 依据：自回归语言模型按 p(x_t | x_<t) 逐个生成。第 t 个 token 定下来以后，才能作为输入去算第 t+1 个。
- 来源：Vaswani et al., *Attention Is All You Need*, NeurIPS 2017（§3 解码器自回归）；Radford et al., *Language Models are Unsupervised Multitask Learners*（GPT-2 技术报告，2019，§2）。
- 「一个字」严格说是一个 token：中文里一个 token 大致是一个字到一个词，因分词器而异。

## 2. 用「写 / 定」，不用「想」〔事实，措辞依据〕
- 模型的**输出**只能一个一个定下来，但它的内部表示会提前「规划」后面的内容。可解释性研究里有公开的例子：模型写押韵诗时，下一行还没写，就已经在内部选好了韵脚词。
- 来源〔待核对〕：Lindsey et al., *On the Biology of a Large Language Model*, Transformer Circuits Thread（Anthropic，2025），押韵诗的 planning 一节。写进片子前对原文，确认章节和表述。
- 另外，很多 App 有「深度思考」模式：模型先生成一段思考过程，再生成答案。思考过程本身也是逐 token 生成的。
- 所以片中不说「它只能一个字一个字地想」「每个字都是刚刚才想出来的」，改说「写」。

## 3. 每个 token 都要把模型从头到尾过一遍〔事实〕
- 前向计算要经过每一层。稠密模型每个 token 用到全部参数，约 2N 次浮点运算（N = 参数量）。来源：Kaplan et al., *Scaling Laws for Neural Language Models*, arXiv:2001.08361, Table 1。
- 混合专家（MoE）模型每个 token 只激活一部分参数，但每一层都要过。例：DeepSeek-V3 总参数 6710 亿，每个 token 激活约 370 亿。来源：DeepSeek-AI, *DeepSeek-V3 Technical Report*, arXiv:2412.19437（摘要）。
- 「动辄几百亿个参数」：主流对话模型的参数量在几百亿到上千亿（例如上面的 DeepSeek-V3；Llama 3.1 有 80 亿、700 亿、4050 亿三档，见 Meta, *The Llama 3 Herd of Models*, arXiv:2407.21783）。

## 4. 每个新 token 都要回头看前面所有 token；前面算过的结果存着〔事实〕
- 自注意力：新位置和前面每个位置计算相关度，每个旧位置一条。句子越长，这一步越重。Kaplan 2020 Table 1 里每 token 的计算量有一项随上下文长度增长（2·n_layer·n_ctx·d_attn）。
- 前面位置的 key / value 会缓存起来（KV cache），每步只有新 token 过模型，不重算旧 token。来源：Pope et al., *Efficiently Scaling Transformer Inference*, arXiv:2211.05102（MLSys 2023），KV cache 和推理开销的讨论〔待核对章节号〕。
- 片中画法：第一轮整句（你的问题）一起送进模型；之后每轮只送新字；旧字块有「存档」标记；细线每个旧字一条。

## 5. 打分、按分数抽签〔事实，分数为示意〕
- 模型输出词表上的概率分布。常用做法是按概率采样（用温度、top-p 调节）；温度设为 0 就是贪心，总选第一名。
- 来源：Holtzman et al., *The Curious Case of Neural Text Degeneration*, ICLR 2020。
- 「海 41% · 睡 18% · 爬 12% · 吃 9%」是示意数字。

## 6. 每层里的乘加并行；同一句话里，字和字之间只能排队；实际服务会批处理〔事实〕
- 一个 token 的前向按层顺序算，每层内部的矩阵乘法在 GPU 上并行。
- 生成第 t+1 个 token 必须等第 t 个定下来。
- 线上推理服务把很多请求拼成一批一起算，整块显卡并不闲着；片中只说「同一句话里」，小字已注明。

## 7. 单条对话逐字生成时，显卡大多在等参数从显存搬过来〔事实〕
- 批量小（单条对话）时，每生成一个 token 都要把全部（MoE 是激活部分的）参数从显存读一遍，但每个参数只做很少的运算，所以速度主要受显存带宽限制，不受算力限制。
- 来源：Pope et al. 2022（小批量解码受内存带宽限制的分析）；Leviathan et al. 2023（§1 动机：大模型推理的瓶颈常在内存带宽和通信，额外的并行计算几乎不增加耗时）。
- 片中：「因为最慢的不是算，是把参数从显存搬过来」，小字「一个字一个字写的时候，显卡大多在等参数搬过来」。

## 8. 训练时一整段同时算〔事实〕
- 训练用现成文本，每个位置的输入（前面的字）都是现成的，不用等模型自己选（teacher forcing）。配合因果掩码，一次前向就能同时得到所有位置的预测和误差，所以训练能在序列维度上并行，生成不行。
- 来源：Vaswani et al. 2017（§1、§4：Transformer 相对 RNN 可并行训练；§3.2.3 解码器掩码）。

## 9. 投机解码〔事实〕
- **流程**：
  1. 小的草稿模型先连续猜 k 个 token。
  2. 大模型一次前向，同时算出这 k 个位置（外加下一个位置）的分布，这一步像训练一样并行。
  3. 从头开始逐个决定接受或拒绝（按两个分布的比值随机接受）。
  4. 遇到第一个被拒绝的位置，就从修正后的分布 max(0, p − q) 重新采样一个 token，丢掉它后面的草稿。
  5. 如果 k 个全部被接受，大模型还会多给出 1 个 token。所以每轮前进 1 到 k+1 个 token。
- **质量**：这套接受 / 拒绝规则保证输出的概率分布和大模型自己逐个采样**完全相同**；用贪心解码时，输出的文字逐字相同。片中小字「数学上保证和大模型自己逐字写的一样（标准做法）」。「标准做法」用来区别于 Medusa 等改变输出分布的变体。
- **为什么快**：单条对话时大模型受显存带宽限制（第 7 条），一次前向验证 k 个位置和生成 1 个位置的耗时接近；只要草稿常被接受，每轮就能前进好几个 token。片中「批改 4 个字，和写 1 个字差不多快 · 单条对话时」。
- **速度**：
  - Leviathan, Kalman, Matias, *Fast Inference from Transformers via Speculative Decoding*, ICML 2023（arXiv:2211.17192）：T5-XXL（110 亿参数）用 T5-small（约 7700 万参数）打草稿，比标准 T5X 实现快 2–3 倍，输出相同。
  - Chen et al., *Accelerating Large Language Model Decoding with Speculative Sampling*, arXiv:2302.01318（DeepMind，2023）：Chinchilla 700 亿参数用 40 亿参数的草稿模型，分布式设置下快 2–2.5 倍，样本质量不变。
  - 两篇测的都是单条请求。批量大时显卡不再那么受带宽限制，提速会变小〔待核对：对照原文和后续文献的 batch 设置〕。片中小字「论文实测，单条对话，因模型而异」。
- **片中「对得上的全收下，从第一个对不上的接着来」**：「对不上」= 和大模型的判断对不上，不是说那个字是错的中文。画面上「吃」被划掉、换成大模型重新采样的「看」，后面的「饭」一起作废，和流程一致。
- 不说哪个具体产品在用。片尾聊天气泡放在示意框里，标「示意：用了投机解码后的效果」。

## 10. 「有的 App 会把字再匀速显示」〔判断，措辞已留余地〕
- 界面怎么显示收到的 token（逐个显示、分包显示、平滑动画）由各家 App 决定，没有统一做法；片中说「有的 App」，不点名。模型本身逐 token 生成见第 1 条。

## 11. 「显卡里上万个核」〔事实〕
- 例：RTX 4090 有 16384 个 CUDA 核心（NVIDIA 规格页）。沿用「AI 为什么非要用显卡？」的绿点阵符号。

## 12. 「小模型参数少得多，写得快，但没那么准」〔事实〕
- 两篇论文的草稿模型比目标模型小一到两个数量级：7700 万对 110 亿，约 143 倍；40 亿对 700 亿，约 17 倍（见第 9 条）。
- 参数少，每个 token 要搬的数据和计算都少，所以快；能力弱，所以要大模型批改。

## 13. 一个字进模型先变成一串数；每一层拿它和参数表「乘一下、加起来」〔事实；示意〕（补 1）
- token 先查嵌入表变成一个向量（一串数）；之后每一层做的主要是矩阵乘法：向量和权重矩阵相乘（逐项乘、再求和 = 乘加），加上注意力和非线性，输出新的向量交给下一层。参数 = 这些权重矩阵里的数。
- 「真实的一串数有几千个」：向量维度（d_model）例：Llama 3 8B 为 4096（Meta, *The Llama 3 Herd of Models*, arXiv:2407.21783, Table 3）。
- 「一层里有成千上万道这样的乘加」：每层的乘加次数是百万到亿量级，「成千上万」是保守说法，不会错。
- 片中画面是示意：数字条只画十几格，层板上的参数块只画几十个。

## 14. 聊得越长，每个字要回头看的越多〔事实〕（补 3）
- 每生成一个新 token，注意力要读一遍前面所有 token 的 key / value 缓存；上下文越长，读的越多，KV cache 占的显存也越大。见第 4 条（Kaplan 2020 Table 1 中随 n_ctx 增长的一项；Pope et al. 2022 对 KV cache 开销的讨论）。
- 小字「前面的字越多，存档越大，每次回头看一遍也越久」：只说「越久」，不给倍数。

## 15. 词表有十几万个 token，每个都打分〔事实〕（补 2）
- 模型最后一层输出词表上每个 token 的分数（logits），再变成概率。
- 词表大小例：Llama 3 为 128,256（Meta 博客「a tokenizer with a vocabulary of 128K tokens」；Llama 3 Herd of Models 论文）；Qwen2.5 为 151,643 个常规 token（Qwen Team, *Qwen2.5 Technical Report*, arXiv:2412.15115）。所以写「十几万个」。
- 小字注明「一个『字』严格说是一个 token」。

## 16. 搬 16 GB、约 16 毫秒；算约 0.1 毫秒〔估算〕（补 4）
- 假设：80 亿参数的稠密模型（例 Llama 3 8B，80.3 亿参数），半精度（每个参数 2 字节），单条对话（批量 1），一张 RTX 4090。
- 搬：80.3 亿 × 2 字节 ≈ 16.1 GB；RTX 4090 显存带宽 1,008 GB/s（NVIDIA Ada Lovelace 架构白皮书附录 A）→ 16.1 GB ÷ 1.008 TB/s ≈ 16 毫秒。这是按带宽上限算的下限，实际框架一般只用到带宽的六七成，搬得更慢；小字写「实际搬得更慢」。
- 算：每个参数每个 token 约 2 次运算（第 3 条，Kaplan 2020）→ 约 160 亿次；RTX 4090 半精度张量算力 165.2 TFLOPS（FP32 累加、稠密；同一白皮书附录 A）→ 1.6×10¹⁰ ÷ 1.652×10¹⁴ ≈ 0.1 毫秒。
- 两者差约 160 倍，所以单条对话逐字生成时受显存带宽限制（第 7 条）。注意力读 KV cache 的那部分没算进去，句子短时可以忽略。
- 涉及具体显卡型号只讲规格，不评产品、不荐股。片中小字「以 RTX 4090 这类游戏显卡估算」。

## 17. 好猜的字猜得准，难的常猜错；平均每步收下两三个字〔事实〕（补 5、补 6）
- Leviathan et al. 2023 摘要：「hard language-modeling tasks often include easier subtasks that can be approximated well by more efficient models」（难的语言任务里常有容易的部分，小模型就能猜对）。每步期望前进 (1 − α^(γ+1)) / (1 − α) 个 token（α = 接受率，γ = 一次抢答几个，论文式 (1)）；α 随任务和草稿模型变化，所以「因模型和内容而异」。
  - 例：α = 0.6、γ = 4 时约 2.3 个；α = 0.8、γ = 4 时约 3.4 个。和「快 2–3 倍」一致（加速比还要扣掉小模型的耗时）。
- 补 6「收下的每个字，都是大模型自己也会选的」：贪心解码（总选第一名）时，收下的字就是大模型自己会写的字，逐字相同；按分数抽签时，用论文的接受 / 拒绝规则，输出的概率分布和大模型自己写完全相同（第 9 条）。小字已注明后一种情况。
- 「看日 → 落」是示意例子，不是论文里的数据。
