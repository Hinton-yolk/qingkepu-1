# EP.01 · Animation Design Sprint 01（三段动画样片）

导演任务书：从动态分镜进入真正的动画制作。只做三段独立样片，不做完整影片，不做高清终渲，不加配音。
画风沿用运动草稿的暖白桌面世界（材质、灯光、字块造型都直接复用 `../style3d/film_desk.py`），没有另起风格。

## 和运动草稿的根本区别
运动草稿每一拍重新搭一个场景，靠相机慢推和 0.4 秒淡化撑动效。这次每段：
- **场景只搭一次**（`build()`），主角从第一帧到最后一帧都是**同一批物体**；
- 每一帧只改物体的位置、朝向、材质状态（`pose(t)` 是时间的纯函数），物体的变化本身就是解释；
- 相机跟着主角走（`Rig`），不再用推镜代替动画。

## 文件
| 文件 | 内容 |
|---|---|
| `lib.py` | 公用库：可逐帧改状态的字块（陶瓷 = 正式，冷白磨砂半透 = 草稿 / 假设；可发光、可退场）、沿路径滑动、会长出来的玻璃轨道、相机、逐帧记录轨迹 |
| `shot_a.py` / `shot_b.py` / `shot_c.py` | 三段样片的场景和动作（可编辑源文件；时间表写在每个文件开头） |
| `run_shot.py` | RunPod 入口：`blender -b -P run_shot.py -- --which a ...` |
| `runpod_pack.py` | 生成 RunPod 渲染包和 jobs.json |
| `post.py` | 2D 提示层（跟着物体走的小标签）、原创音效、编码、运动轨迹图和轨迹数据 |

本机试构图：`blender -b -P shot_c.py -- --outdir DIR --scale 0.25 --samples 8 --font NotoSansSC-Bold.otf --only 5.6,7.4`
整段渲染（RunPod）：`python3 runpod_pack.py <包目录> <输出目录> --scale 0.5 --samples 24 --chunks 4`，再 `python3 tools/runpod_render_gql.py run <包目录>/jobs.json --pods 3 --max-hours 1 --yes`
合成：`python3 post.py a|b|c <3D 帧目录> <输出目录>`

规格：540×960 原生 30 fps（没有插帧），Cycles 24 采样 + 降噪；合成时放大到 1080×1920 叠 2D 层。音效响度 -16 LUFS（样片，不是终版）。

## 三段的主角和动作

### A · 文字生成与分叉（14 秒）
- **持续存在的物体**：输出托盘；「周末我想」4 个正式字块；空位框；候选「去」「睡」；假设续写「海边看日落」「个懒觉」；两条玻璃轨道。没有任何物体中途被换成长得一样的新物体。
- **动作**：
  - 「想」刚落位；
  - 空位呼吸，两个候选从空位里升起；
  - 两条轨道从空位往两个方向长出去，候选各沿一条滑过去；
  - 续写的字一个接一个从前一个字后面滑出来，沿轨道转向、排好；
  - 上面一条被采用、发琥珀光，下面一条变淡、下沉，退到背景；
  - 「去」沿原轨道退回空位，一路从半透明变成实心陶瓷，落位；
  - 下一个空位亮起。
- **科学上的处理**：两条续写用冷白半透明（假设），和实心的正式字分开；标签写「一种可能的续写」「另一种可能」。最后只有「去」变成正式的字，后面「海边看日落」仍是半透明，标签写「后面的字还要一个一个写」，避免让人以为一次输出了整句。

### B · 模型逐层计算（10.5 秒）
- **持续存在的物体**：数值托盘（同一块）；「周末我想」4 个字块（缩成小牌子，跟着托盘走，始终看得出每串数是哪个字变的）；4×6 个数值方块；三道「层」；4 根分数柱和 4 个候选字。
- **动作**：
  - 每个字往前倒到托盘上，脚下滑出一串数（方块一边滑一边长高）；
  - 托盘带着这些数穿过三道层，相机在侧后方跟着走；
  - 每串数穿过一道层时，方块高度变一次，层上的参数块亮起；第一层里「想」连回前面每个字（回头看）；
  - 出了最后一层，「想」那串数飞进分数柱，柱子长到各自的高度，候选字坐在柱顶；
  - 「去」被选中，沿同一个方向往右走，落进下一个空位，变成正式的字。
- **科学上的处理**：只画三层，标签写「模型的一层（示意，实际有几十层）」；方块高度变化不对应任何真实数值；分数标「示意」。没有画公式，没有说这就是 Transformer 的完整计算。

### C · 推测解码（17 秒）
- **持续存在的物体**：输出托盘和「周末我想去」；架高的草稿轨；小模型；大模型（验证通道，顶上 4 盏灯）；草稿「海 边 吃 饭」；大模型给出的「看」；✕；后来的草稿「日 落」。
- **动作**：
  - 小模型连续抛出 4 个草稿字，沿弧线越过前面的字，落到草稿轨上；
  - 整组滑进大模型，灯亮，一道光同时扫过 4 个位置（集中验证，一次看完）；
  - 结果从左往右传：海 ✓（青绿）、边 ✓、吃 ✗（琥珀 + ✕）；后面的「饭」依赖「吃」，跟着变暗，不再检查；
  - 海、边沿滑道落到正式输出，一路从半透明变成实心；
  - 吃、饭沿草稿轨退回小模型；大模型自己给出这一位的「看」，从通道里升起，补到第三位；
  - 小模型从新前缀「……海边看」接着抛「日 落」，排队进大模型；
  - 镜头拉远，看到正式输出、草稿路径和验证机制，标题「小模型先猜，大模型集中验证」。
- **科学上的处理**：按前缀接受（第一个对不上之后的全部作废），纠正的字来自大模型；有字被拒，不暗示猜测总会被接受；不出现性能数字，不说一定加速。

## 自查：还有哪些地方靠淡化或推镜，而不是靠物体动作
不拿 motion check 当证明；下面是逐段看片后自己找的。
- **A**
  - 续写的字从前一个字后面滑出来时，开头 0.25 秒是淡入（同时在滑、在变大），不是纯淡入，但也不是完全从前一个字里「挤」出来。
  - 落选的那一条「退到背景」主要靠变淡，加一点下沉，没有明显的物理动作（比如被推开、滑走）。
  - 中段相机跟着候选往右走，「周末我想」有一半出了画面。
- **B**
  - 第一层里「回头看」的几条青绿细线是亮起来、暗下去，不是从一个字长到另一个字。
  - 7.0–7.7 秒托盘停下、数还没飞出去，有一小段像停顿。
  - 飞向分数柱的方块在画面里偏小，「这串数变成了分数」这一下不够醒目。
  - 落选的三个候选只是变淡。
- **C**
  - 「饭」作废只靠变暗，没有动作；观众（Codex）也在这里卡住了，没看出它是跟着「吃」一起作废的。
  - 「看」从通道底下升起来，没有明显的出口，观众容易以为是「吃」变成了「看」。
  - 集中验证的光幕是一块淡入淡出的发光板，读起来有点像盖子。
  - 14–17 秒收尾主要是相机拉远加标题淡入，物体只有「日 落」在滑：这是三段里最接近「推镜代替动画」的地方。
- **共同**
  - 提示标签都是淡入淡出（2D 层，按任务书允许）。
  - 音效是样片级的合成音效，没有按音乐拍点精修。

# Animation Integration Test 01（2026-11-20）：三段整合成一条连续动画

导演任务书：按 B → A → C 的顺序，把三段合成一条连续动画，同时修复运动设计。主交付物是 `EP01_IntegratedAnimation_Test01.mp4`（34 秒，540×960 原生 30 fps，无配音）。

## 做法
- `shot_int.py`：**整条片子只有一个场景**（模型在已有文字后方，分叉从正式输出的空位长出去，草稿轨从输出托盘末端展开）。所有主角从第一帧到最后一帧都是同一批物体，没有任何换场重建。
- 相机：`CAM` 表里每一段都写了这次运动的目的（跟随谁、靠近什么、拉远揭示什么），用三次插值连成一条连续路径，中间没有剪辑。
- 出片：`finalize_int.sh`，依次合成 2D 提示层和音效，切出三个局部转场，出每秒接触表和世界坐标轨迹图。

## 身份链（全程同一批物体）
已有文字「周末我想」（全程留在托盘上）
→ 每个字身后展开的一串数（同一块数值托盘带进模型）
→ 第一层里，「想」的那串数先伸出连线到前面的字；前面的字响应，小珠沿线回来；「想」的数变一次（青绿闪一下）
→ 穿过后两层
→ 「想」那串数从模型顶上越过各层飞出来，6 个方块分头落进三根柱脚，分数柱长起来，候选「去 / 睡 / 出」坐在柱顶
→ 分叉轨道先从空位长出去；「去」「睡」从柱顶沿弧线进入两条轨道；柱子缩回桌面（「出」跟着下去）
→ 两条假设的续写沿轨道滑出来
→ 采用上面一条：下面的字收回到「睡」，「睡」沿来路退回候选池（柱子原来的位置）
→ 「去」沿轨道回到空位，变成正式的字；上面那条假设的后续沿轨道收回
→ 草稿轨从托盘末端展开，小模型和大模型（验证通道 + 输出口）升起
→ 小模型抛出「海边吃饭」；整组从入口进入通道；一道光同时扫过 4 个位置；结果沿序列点亮：海 ✓、边 ✓、吃 未接受（顿一下）
→ 海、边从通道后方出来，落进正式输出
→ 吃带着后面的饭，沿草稿轨退出入口，撤回小模型
→ 大模型输出口亮起，「看」从口里滑出，沿独立的弧线落到正式输出末端
→ 「周末我想去海边看」；小模型从新前缀接着抛下一个字「日」

## 渲染
RunPod，这一轮合计实扣 $1.56（余额 8.01 → 6.46），共渲了三遍：
1. 第一遍整片：约 100 帧出现黑块，原因是金属材质的各向异性在 GPU 上部分视角渲成全黑；
2. 去掉各向异性后整片重渲：又发现草稿轨弯道太急，玻璃条自相交渲黑；落选字收回时互相穿插；
3. 修好后只重渲 18.6 秒以后的帧和第 15 秒的一小段。

中间有一次 RunPod 没有空闲 GPU，自动退出，花了约 $0.02。最终 1020 帧逐帧检查，没有黑块。

## 尚未解决的连续性和可读性问题（自查）
- **6–7 秒**：「想」那串数越过模型飞出来时，画面里很小，镜头没贴住。信息从模型到分数柱这一段是全片最弱的跟随。
- **11–14 秒**：拉远看两条分叉时，「周」被切掉一部分。共享前缀大部分可见，但不是完整的四个字。
- **19–20 秒**：小模型和大模型是从桌面下升起来的。属于辅助环境，但没有来源，像凭空长出来。
- **24 秒**：集中验证的光幕在手机尺寸下不明显，「一次看 4 个」主要靠标签。
- **26–29 秒**：C 段为了同时看见撤回和补充候选，镜头较远，字块在手机上约 60 px。「吃饭撤回」的动作很快，又在画面下方，容易漏看。
- **31–34 秒**：收尾时「周」在左边缘被切一半。最后两秒的动作只有「日」被抛出和空位呼吸，偏静。
- **模型**：模型的三道层在 C 段一直留在画面左上角的背景里（身份连续，但占画面）。
- **音效**：样片级合成，没有按音乐拍点精修。
- **动效检查**：没有拿它当质量证明，上面这些是逐秒看接触表和整片后的判断。
