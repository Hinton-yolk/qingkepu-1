## 一、桌上的演示装置

一条纸带从左走到右，全片就看它。

| 桌上的东西 | 代表什么 |
|---|---|
| 纸带：黑格 = 1，白格 = 0；下沿留一条白边 | 线上的信号（高 / 低电平） |
| 印带器（左边）：一下印一格 | 发货端：数据排成一列发出去 |
| 读带口（右边）：一道窄缝，只露出当前这一小段 | 收货端：任何一刻只看得到当前的电平 |
| 黑白交界经过窄缝时「嗒」一声 | 信号的跳变（鼓点） |
| 节拍器，放在读带口旁边 | 收货端自己的时钟 |
| 节拍器每响一下，在白边上盖一个红点 | 清点一次（在每个比特中间采样） |
| 打乱盒（印带器后面）、还原盒（读带口后面） | 扰码 / 解扰 |
| 纸带上的墨洇开，格子边缘发灰 | 信号在路上变糊 |
| 修字盒 + 插座上的功率计 | 修信号的电路；耗电 |

要点：
- **纸带上不画格线。** 印带器印了五下，出来的是一整段连着的黑。观众和读带口一样，光看这段黑数不出是几格。
- 红点是这一集唯一要观众「数」的东西：节拍对了，一段黑下面正好五个红点；节拍偏了，只有四个。
- 纸带、窄缝、节拍器是类比，片中 y6 说明一次「芯片也一样」。

## 二、逐拍分镜

时间按每秒约 6 个字估，开头两句放慢。全片约 1:20。
画面里的字都贴在东西旁边（小纸签），同屏不超过 8 个大字；字幕全程有，放在抖音文案区上方。左上角五站条常驻，亮「打包出发」。

### 开头（0–8 秒）

**y1 · 0.0–3.0 · 机位 A（手机特写，慢推）**
- 口播：少数一个比特，这句话就全乱了。
- 画面：桌上一部手机，屏幕亮着，聊天气泡「今晚七点，老地方见」。0.5 秒起，气泡里的字从中间开始一个个变成乱码，1.5 秒时整句都乱了。百叶窗的光斜在桌上。
- 画面上的字：大字问题贴在手机上方的纸签上：「芯片怎么数清 0 和 1？」
- 声音：消息提示音，接一串错位的「咔哒」。

**y2 · 3.0–8.0 · 机位 B（跟着纸带横移，全片第一个真要动的镜头）**
- 口播：**AI** 芯片之间的数据排成一列跑，到了对面，要一个一个数清楚。
- 画面：镜头从手机移开，落到旁边的印带器上。它「嗒、嗒、嗒」地印，纸带一格接一格吐出来。镜头跟着纸带往右走，走到读带口停住。
- 画面上的字：路线图小卡在镜头经过时闪过，亮着「打包出发」。读带口旁的纸签：「到了对面：一个一个数」。
- 声音：印带器的节奏声。

### 问题（8–20 秒）

**y3 · 8.0–13.0 · 机位 C（读带口特写，固定；全片的主机位）**
- 口播：可连续五个 1，在线上就是一段平平的高电平：四个，还是五个？
- 画面：印带器连印五下黑（画面角上的小画中画里看得到这五下）。一整段黑带走到读带口，窄缝里一直是黑的。读带口上方的翻牌计数器在「4」和「5」之间来回翻。
- 画面上的字：纸签「黑 = 1　白 = 0」；计数器旁「四个？五个？」；角注「示意：真实链路常用四种电平」。
- 声音：黑带经过时没有「嗒」，只有纸带走的沙沙声。

**y4 · 13.0–20.0 · 机位 C**
- 口播：要数清，就得知道每个比特占多长时间，这就是节拍。可高速连接通常不另外送一个节拍器过去。
- 画面：一把小尺落在纸带上方，量出「一格」那么长，标上「节拍」。说到「不另外送」时，印带器旁边那只节拍器被一只纸箱罩住、划掉；读带口这边只有它自己的那一只，摆得稍慢，红点盖得偏稀。
- 画面上的字：「每个比特占多久 = 节拍」；被划掉的那只旁边：「不随货送」。
- 声音：节拍器的「嗒」和纸带的「嗒」明显对不上。

### 办法（20–34 秒）

**y5 · 20.0–25.0 · 机位 C（很慢地推近节拍器）**
- 口播：就像跟着一首歌拍手：没人给你打拍子，你听着鼓点，自然就跟上了。
- 画面：一段黑白相间的纸带经过窄缝。每个黑白交界经过时，窄缝边上的小灯闪一下。节拍器每被闪一下，摆锤就往对的方向挪一点。
- 画面上的字：小灯旁「鼓点」。
- 声音：配乐只留鼓；纸带的「嗒」和节拍器的「嗒」越靠越近。

**y6 · 25.0–34.0 · 机位 C**
- 口播：芯片也一样：信号每跳一下，就是一个鼓点。它跟着鼓点校准自己，再按节拍一个一个清点：五个，不是四个。
- 画面：
  1. 「芯片也一样」：镜头不离开装置。三张纸签依次翻面，正面是桌上的东西，背面是它代表的真东西：「纸带」→「线上的信号」，「读带口」→「收货的芯片」，「节拍器」→「芯片里的时钟」。约 2.5 秒。
  2. 两种「嗒」合成一声。那段长黑带再来一次：红点一个一个盖在白边上，一、二、三、四、五。计数器翻到「5」停住。
- 画面上的字：计数器「5」；纸签「五个，不是四个」。
- 声音：五声清楚的鼓，最后一声加重。

### 麻烦和补救（34–46 秒）

**y7 · 34.0–38.5 · 机位 C**
- 口播：可要是一长串全是 1，没有鼓点，拍子就会慢慢跑偏。
- 画面：一段很长的黑带走进窄缝，小灯不再闪。节拍器还在摆，但越摆越慢，红点的间距越拉越开，颜色从红变成珊瑚色。
- 画面上的字：「没有鼓点」。
- 声音：鼓停，只剩节拍器，速度一点点往下掉。

**y8 · 38.5–46.0 · 机位 D（发货端特写）→ 机位 B 反向跟纸带 → 机位 C**
- 口播：所以很多链路发出去之前，先把数据打乱，**让鼓点不会断太久**；收到以后，再按同样的规则还原。
- 画面：回到左边。长黑带进打乱盒，出来变成有黑有白的花带。镜头跟着花带到读带口：小灯又一下下闪，节拍器摆稳，红点回到红色。花带再过还原盒，出来还是原来那一长段黑。
- 画面上的字：盒子上「打乱」「还原」；两个盒子之间一张纸签「同一套规则」。角注「示意」。
- 声音：鼓回来。

### 代价（46–63 秒）

**y9 · 46.0–50.0 · 机位 C**
- 口播：难的是，SerDes 的速度大约每过几年就要翻一倍。
- 画面：纸带走的速度不变，但格子变窄一半，再窄一半。节拍器跟着越摆越快。
- 画面上的字：「速度翻倍 = 每个比特的时间减半」。
- 声音：节拍一档一档加快。

**y10 · 50.0–58.0 · 机位 C → 机位 E（拉开看整张桌子）**
- 口播：越快，信号在路上越容易糊，节拍越难听准；所以它自己也带着不少修信号的电路，这些都要耗电、占面积。
- 画面：格子窄了以后，纸带上的墨往两边洇，黑白交界变成一片灰。小灯该闪不闪，节拍器开始犹豫。然后读带口前面多出一只修字盒，纸带出来边缘又清楚了；接着又多一只、再多一只。镜头拉开：读带口这一头的盒子占了小半张桌子，它们的插头都插在一个插线板上，功率计的指针往上走。
- 画面上的字：「越快越糊」；盒子上「修信号」；功率计旁「耗电」；桌面上「占地方」。
- 声音：每多一只盒子「咚」一声，功率计轻轻的嗡声越来越高。

**y11 · 58.0–63.0 · 机位 E**
- 口播：每一代都在拼同一件事：跑得更快，还要每送一个比特，少花一点电。
- 画面：盒子一只只缩小、并成一只，功率计的指针往回落，而节拍器更快了。
- 画面上的字：「更快」「每个比特更省电」。

## 五、真东西为什么不出现（主 agent 的判断，用户可以推翻）
按用户的标准「对阐释有没有帮助」看，y6 切去拍一块板卡帮助不大，反而有三个坏处：
- y6 是全片的高潮（两种「嗒」合成一声，数出五个），中间切走会打断它；
- 手头的模型是一块消费级显卡，和这一集讲的「AI 芯片之间的高速通道」不是一回事，指着它讲容易不严谨；
- 观众要的对应关系只有三条，纸签翻面就能说清，不用离开装置。

这一集里的真东西只有那部手机（开头和结尾）。Drive 上的 `RTX4090Model.zip` 这一集没有用，也没有去读。
