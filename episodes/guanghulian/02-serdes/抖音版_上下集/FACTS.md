# 光互连 02 · 抖音版（小红书纸桌讲解风格）· 事实与来源

底稿事实（排成一列的两个原因、SerDes 名字、节拍、每几年翻倍、每比特电）以 `articles/ep02.md`（@Yihong）为准。
拆解版已经核过的说法在 `../douyin-split/FACTS.md`，这里只列这一版新加或改了说法的地方。

| 口播 / 画面 | 依据 | 结论 |
|---|---|---|
| 「25 根线，跑不过 4 根线」「老打印机的并口线，每秒大约两兆字节；只有 4 根线的 USB，每秒几十兆」 | 打印机并口用 DB-25 接口（IEEE 1284），ECP/EPP 模式每秒约 2 MB；USB 2.0 线里 4 根线（电源、地、D+、D−），最高 480 Mb/s，实际每秒几十兆字节（见 `douyin-split/FACTS.md`） | 成立。并口慢不只因为并行（协议、线缆也有关），片子只当「线少反而快」的生活例子；回扣句说「用的也是同一个思路」，不说「原因完全一样」 |
| 第一帧两根进度条：USB 一秒一张、并口线约二十秒一张 | 按上面两个数量级（约 1:20）画的比例示意 | 示意 |
| 「AI 训练时，上万颗芯片每算一步都要交换数据」 | 训练集群万卡级；分布式训练每一步都要同步（all-reduce 等）（见 `douyin-split/FACTS.md`） | 成立 |
| 「它们之间最快的路，也只修几条」 | AI 芯片之间的高速电互连用少量高速串行通道（SerDes），不是宽并行总线 | 成立 |
| 「今天一条通道，每秒要送出上千亿个比特」 | 每条通道 112 Gb/s 级起（原文） | 成立 |
| 「少数一个比特，这句话就全乱了」（第一帧：线上少一位，后面整体往前挪一格，消息变乱码） | 串行数据少数一位，后面所有位都错位，按字符解码就成了乱码；真实链路会检测到并纠正 / 重传。乱码字是示意 | 示意 |
| 「高速连接通常不另外送一个节拍器过去」 | 原文：这类高速连接通常不另外送时钟，接收端从数据跳变里恢复（CDR） | 成立 |
| 「就像跟着一首歌拍手」 | 类比时钟数据恢复 | 类比 |
| 「一长串全是 1，没有鼓点，拍子就会慢慢跑偏」 | 长连 1 / 长连 0 没有跳变，CDR 无从校准，相位会漂 | 成立（类比表达） |
| 「所以很多链路发出去之前，先把数据打乱……收到以后再按同样的规则还原」 | 扰码 / 解扰（同一多项式）。也有链路用编码（如 8b/10b）保证跳变，所以说「很多链路」 | 成立 |
| 「SerDes 的速度大约每过几年就要翻一倍」「自己也带着不少修信号的电路，都要耗电、占面积」「每送一个比特，少花一点电」 | 原文 | 成立 |
