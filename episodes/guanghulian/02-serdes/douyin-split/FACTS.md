## 第 1 条：为什么不修几十条路一起送

| 说法 / 画面 | 依据 | 状态 |
|---|---|---|
| 「几千个针脚」：大型 GPU、交换芯片的封装底面有几千个焊球 | 大尺寸 BGA/FCBGA 封装的焊球数通常在 2,000–5,000 以上，其中大部分用于供电和接地。具体型号的数字以厂商封装手册为准 | 量级成立，具体数字待核 |
| 「大多数针脚：供电、接地」 | 高功耗芯片的电源/地焊球占比很高（为降低电源阻抗和压降）。是定性说法，不给比例 | 成立（定性） |
| 画面里的焊球阵列 | 示意图，约 870 颗；画面上标了「示意」 | 示意 |
| 并排走要在同一时间窗口内到达，跑得越快窗口越窄 | 并行总线的时序余量（skew budget）随单位时间间隔（UI）缩短而缩小；走线长度差带来的时间差（skew）是固定的，不随速率变小。画面：第 5 道多绕一段，晚到的时间不变，窗口变窄后落到窗口外 | 成立。赛跑是类比，片子里说的是「就像」 |
| 「速度 ×8」角标 | 示意，表示速度提高，不对应具体速率 | 示意 |

## 第 2 条：连续五个 1，怎么数清

| 说法 / 画面 | 依据 | 状态 |
|---|---|---|
| 「今天一条通道，每秒要送出上千亿个比特」 | 主流高速 SerDes 每条通道约 112 Gb/s（PAM4），新一代约 224 Gb/s。1000 亿 = 100 G，说法成立。画面计数器停在「1120 亿」（= 112 Gb/s） | 成立 |
| 「1 秒 → 1 毫秒 → 1 微秒 → 1 纳秒」放大，最后一格「不到 0.1 纳秒里的 10 个比特」 | 按 112 Gb/s 计，每个比特约 8.9 ps，10 个比特约 0.089 ns | 成立 |
| 连续五个 1 =「一段没有缝隙的高电平」 | 两电平（NRZ）的简化画法。100G 级以上的通道用四电平 PAM4，但「没有节拍就数不清」的道理一样 | 简化，成立 |
| 收货端从高低变化里推算节拍（时钟数据恢复，CDR） | 高速串行链路一般不单独传时钟，接收端用 CDR 从数据跳变中恢复时钟和相位。参考：B. Razavi, *Design of Integrated Circuits for Optical Communications*（CDR 章节） | 成立 |
| 「数据会先被打乱一下，让高低变化够多」（新增句） | 以太网等链路在发送前做扰码/线路编码（如 IEEE 802.3 第 49 条的 64B/66B 扰码；PAM4 链路还有 256B/257B 转码和 RS-FEC），保证足够的跳变密度，CDR 才能保持锁定 | 成立 |
| 节拍拉长一点就数成 4 个 | 示意：节拍的周期不对，就会数错比特个数 | 示意 |

## 第 3 条：号称每条通道 200G 的芯片，该问哪三个问题

| 说法 / 画面 | 依据 | 状态 |
|---|---|---|
| 「224G」与标题里的「200G」 | 每条通道 200G 级别的电接口，线路速率约 224 Gb/s（多出来的是编码和纠错开销）。OIF 的 CEI-224G 定义 224 Gb/s 每通道；IEEE P802.3dj 定义 200 Gb/s 每通道的以太网电接口 | 成立；802.3dj 的状态（是否已正式发布）待核 |
| 每条通道速度 28G → 56G → 112G → 224G，「大约每代翻一倍」 | 业界几代 SerDes 的典型速率：28G NRZ、56G PAM4、112G PAM4、224G PAM4，大约每三四年一代。画面只给速率，不给年份 | 成立；口播说「每过几年翻一倍」 |
| 速度翻倍，信号更容易变模糊 | 速率越高，奈奎斯特频率越高，铜线在高频的损耗越大（第三篇详讲） | 成立 |
| SerDes 自带「整理」能力（发出时修、收进时修） | 发送端的 FFE / 预加重，接收端的 CTLE、DFE 等均衡；100G 级以上多用 DSP 架构的接收端 | 成立（口播不展开名词） |
| 「每个比特花多少电」，画面标「pJ/bit」 | 业内用 pJ/bit（每传一个比特消耗的能量，皮焦）比较 SerDes 和光模块的能效。片子里只讲指标，不给任何公司的数字 | 成立 |
| 「在什么路况下跑到这个速度」 | 规格要看通道损耗条件（例如在奈奎斯特频率下多少 dB 的插损）和误码率指标；同一个速率，短距/低损耗和长距/高损耗难度差很多。画面上两条路是示意 | 成立；画面不给具体 dB 数 |
| 「是否已经在真实芯片上跑通」 | 区分仿真/IP 宣称和硅验证（silicon-proven）、量产 | 成立 |
| SerDes 很少单独卖；常以 IP 授权，大公司多自研 | 原文（用户稿 L39–L41） | 原文 |
| 不点名、不荐股 | 全片没有出现公司名；文案注明「只讲怎么看懂技术，不构成投资建议」 | 已检查 |
