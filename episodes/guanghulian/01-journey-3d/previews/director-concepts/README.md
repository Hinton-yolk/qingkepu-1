|---|---|---|---|
| T4 | 玻璃丝里一线青光 + 问题「AI 芯片之间为什么靠光传话？」；同一条路先走金色铜线，越走越糊，对面八格认错；调制器里光一直亮着，电一碰电极光就暗一下；同一条路、同一个镜头再走青光，对面八格和发出的一样；结尾回到玻璃丝 | 路一远，电信号会糊、对面认错；把电写到光上，同一条路到了对面还认得出 | 读成「铜线一律不行」；C 段是「电到 = 光暗」，D 段八格是「亮 = 1」，细看的人可能觉得对不上；把光当成完全无损 |

已知的问题：
- **试听版的声音没有人听过**（实现角色和主 agent 都没听）。声音事件由网页 `t4Events()` 导出，声音脚本只读这个文件；数字核对只测到 3 个孤立的「嗒」，最大偏差 1 ms，其余事件因为前后声音重叠没法用起音检测核对。
- C 段：电极片在碰撞的同一帧变亮，盒内电极高度的光晚 1 帧（个别 2 帧）变暗；出口要再过约 9–10 帧，是暗段往上流的时间。
- B → C 是压暗再淡入，不是匹配转场；铜线远端被「收到」面板盖住后，「逐渐糊」主要靠条纹边缘变虚。
- 「收到」八格依次点亮的时间是定的，不是严格按条纹到达对面的时刻。
- 开场黄色线缆压到只剩两条窄边，「一把线缆」的感觉弱了。
- 没有配音；字体、配色为临时。`tools/motion_check.py`：PASS（静止帧 1%，最长静止 0.13 秒）。

## T1 电控制光 v1

两版同一个构图、同一套时间，各 8 秒，540×960，30 fps。

| | A 直觉版 | B「步调」揭晓版 |
|---|---|---|
| 观众看到了什么 | 下面的激光器发出一束光，往上穿过一个盒子（调制器），一直稳稳地亮。金色的电信号从右边进来，沿着盒子边上的电极往上走，走到头为止。电每到一下，盒子靠电极的一侧泛一下金色，随后出来的光暗一截。进去的光始终不变 | 前 3.9 秒和 A 一样。然后盒子打开：里面的光分成两路，每一路上有一道道往上走的横杠。平时左右横杠对齐，像梯子；电经过的时候，靠电极那一路的横杠被拖后半格，左右错开，像错位的拉链；这时候合起来的光就暗 |
| 希望观众理解什么 | 光本来一直亮着；是电让出来的光一暗一亮。电控制光，不是电变成光 | 同上，再多一层：电只是把其中一路光拖慢了半步，两路合起来就变暗 |
| 最大的误解风险 | ① 以为电把光「挡住」或「吃掉」了（当成阀门问题不大，当成电把光消耗掉就错了）；② 没注意到进去的光一直没变 | ① 横杠被当成实物（一格一格的东西在运），而不是光的步调；② 「慢半步」和「合起来变暗」之间的关系一遍看不出来，只觉得里面很花；③ 解释多了，反而盖过「电控制光」这一句 |

**几个有意的选择**
- **电到了，光变暗**（不是电到了光变亮）。原因：光本来就亮着，电一到它暗下去，观众没法把它看成「电变成了光」。
- 暗的时候没有全灭，还剩一条细线。
- 电信号的图样止于电极顶端的小方块，没有跟着光往上走。
- 静音版没有字幕，只有四个贴在东西上的标签（激光器、调制器、电信号、光）。试听版加了临时声音，并用字幕代替口播；没有用任何配音。
- 试听版的声音：光是一个不变的长音；电到电极顶端时一声低的「嗡」；约 0.2 秒后长音跟着出口的光一起变轻。

**已知的问题**
- `tools/motion_check.py` 的结果是 **FAIL**：A 版静止帧 23%，B 版 24%，最长静止 0.8 秒和 1.3 秒。静止的部分主要是开头两秒，画面上只有一束不变的光。这是内容决定的，没有为它再改。
- B 版里「慢半步」「两路对齐就亮、错开就暗」的说法没有核过；哪一路被推、实际是不是两路同时反向推，都是示意。横杠的间距和真实波长没有比例关系。
- 字体是环境里现成的文泉驿正黑，不是成片字体；颜色和布局没有按成片的风格做。
- 两版里出来的光要等电沿电极走完（约 1.2 秒）才开始变暗，因果之间隔得有点久。

## T2 同机位铜 / 光对照 v2

9 秒，540×960，30 fps。两遍各 4.5 秒，中间一个硬切；两遍用同一个相机推进函数和同一个条纹流速。由 Sonnet 角色实现，主 agent 看过关键帧后改了一轮。

- 第一遍标「假设：还走铜线」：一条有透视的金色带子，条纹往远处流，越远边越虚、亮暗差越小，逐渐变成均匀的暗金色，没有哪一处突然消失，没有任何距离数字。对面「收到」的八条线都是差不多的暗金色，其中一条闪三下珊瑚色。
- 第二遍标「换成光」：同一条带子的位置上是一根很淡的玻璃丝，正中间一线青光，明暗一段一段边缘分明；到对面略暗（约 80%）。对面的八条线依次亮出，和「发出」的一样。
- 静音版没有字幕；试听版加了临时声音（八拍一组的「嗒」，第一遍逐渐拖尾变闷，第二遍一直清脆）和两句字幕。

已知的问题：
- 实现的角色只看了静帧，**没有听过试听版的声音**；主 agent 也没有听。声音拖尾的时间（1.2–4.2 秒）是按 v1 的画面定的，v2 改了条纹画法之后没有重新对。
- 第二遍对面的暗条比发出端的暗条更暗一点（整体乘了 0.84）。
- 第一遍对面八条线「分不清」主要靠亮度接近和轻微游移，观众可能读成「本来就是暗的」。
- `tools/motion_check.py`：PASS（静止帧 1%）。

## T0 两个开场 v2

各 4 秒，540×960，30 fps，只有静音版。由 Sonnet 角色实现，主 agent 看过关键帧后改了一轮。

- **A「玻璃丝」**：第一帧是几根黄色线缆，镜头 1.4 秒内钻进其中一根；之后画面中间是一根斜着的玻璃丝，正中间一条青色的亮线一段一段在流，旁边平行躺着一根头发（玻璃丝约是头发的 1.6 倍粗）。标签「玻璃丝」「头发」「光」依次出现。大字：「AI 芯片之间传数据／为什么要用玻璃丝？」
- **B「送得到吗」**：下方一排八个金色的亮暗块，一条金色的路伸向远处，条纹越远越糊；远处一个机柜标「对面的芯片」，1.6 秒起上面出现珊瑚色的问号。大字：「这条消息／送得到吗？」

已知的问题：
- A：亮线读出来是「一串亮段」；「玻璃丝」标签没有贴在玻璃丝上；旁边其它玻璃丝几乎看不出；大字压住了玻璃丝和头发的下端。
- B：前 1.5 秒主要靠大字撑悬念；「铜线」「对面的芯片」是小字。
- 字体和配色是临时的。`tools/motion_check.py`：两段都 PASS。
