# T4 整合概念短片 · 导演分镜和节奏表（主 agent 写，2026-11-12）

对应 PR #3 第 17 条评论《T4：一次真正的“可看懂的电影小样”》和 ChatGPT 对 T0/T1/T2 的看片审阅；用户在会话里说了执行。
这是二维概念片，不是成片画面。时间单位秒，全片约 31 秒，540×960，30 fps。

## 一句话
第一次看的人看完能说出：**「数据走远了，电信号会糊、对面认错；把电写到光上，同一条路到了对面还认得出。」**

## 三个关键动作（每个都要能单独复述）
1. 铜线那一遍：越走越糊，对面八格**认错了**。
2. 电控制光：光一直亮着，**电一到，出来的光就暗一下**。
3. 光那一遍：同一条路、同一个镜头，对面八格**和发出的一样**。

## 逐段画面

全片的「消息」是同一个八格图样：**亮亮暗亮暗暗亮暗**（1,1,0,1,0,0,1,0）。金色 = 电，青色 = 光，珊瑚色 = 只给「认错了」。

### 走廊构图（B、D 共用，A 的结尾落在它上面）
沿用 T2 v2 的透视路：下方近处是「发出」的芯片（GPU A），上方远处是对面的芯片（GPU B），中间一条往远处收窄的路。两边有淡淡的机柜轮廓。
B 和 D **用同一个相机函数、同一个条纹流速、同一套时间（相对段首）**，这是全片的押韵，不能各写一套。

### A 开场提问 0.0–4.0
- 第 0 帧：深色底，画面中间一根斜着的玻璃丝，正中一线青光，亮暗一段一段在往上流——**第 0 帧就看得见光**。黄色线缆只是两边虚化的背景，合计不超过画面四分之一（ChatGPT：不要第一帧占满黄线缆）。
- ★ 大字在上三分之一，不压玻璃丝：小一号「AI 芯片之间」，大一号「为什么靠光传话？」。
- 0–2.0 缓慢推近（画面一直在动）。
- 2.0–4.0 快速拉远（缓入缓出）：这根丝原来是一条线，从下面的芯片「GPU A」通到上面远处的「GPU B」。落定在走廊构图。大字在 3.0–3.6 淡出。两颗芯片上贴小标签。
- 不放头发（审阅意见：头发只作辅助，不抢开场主视觉；这一版为了让三个动作清楚，先不放）。

### B 电的挑战 4.0–11.0
- 4.0–4.6 路上的青色细线淡出，换成一条金色的宽带（铜线）。小标签「假设：还走铜线」。GPU A 上方亮出「发出」的八格（金色，亮暗按图样）。
- 4.6–8.6 金色条纹按图样从近往远流，镜头沿路往前推。条纹**越远边越虚、亮暗差越小**，逐渐变成均匀的暗金色；没有哪一处突然断掉。
- 8.6–9.4 「收到」面板从 GPU B 处放大、移到画面上部正中（宽约 360 px，八格每格约 40 px，不再是 T2 那种细小格子）。面板上方紧贴一行小一号的「发出」参考格，列对齐，方便一眼对照。收到的八格是差不多的暗金色，其中第 3、6 格（错的位）闪珊瑚色；面板旁出现「✗ 认错了」。
- 9.4–10.4 定格：面板不动，背景里的条纹仍然很慢地流，珊瑚格轻轻呼吸（不能整帧静止超过 0.6 秒）。
- 10.4–11.0 走廊变暗，镜头急退回 GPU A 一侧，准备进 C。
- 角注（小字，左下）：「示意：高速、不带中继芯片的铜线；不是突然断掉，是越来越糊」。

### C 电控制光 11.0–19.5（T1-A 为主，改节奏）
- 构图沿用 T1-A：下面激光器，一束青光往上穿过调制器（盒子），从上面出去；电极是盒子右侧中部的一块**短**金色电极片，金色信号线从画面右侧水平接过来。不要 T1 那种沿盒子往上走 1.2 秒的长电极。
- 11.0–12.2 只有光：入口、出口都稳稳亮着，光束里有很淡的光点往上流（画面不静止）。标签「激光器」「调制器」「光」。
- 12.2–17.0 电来了：右侧信号线上依次送来八个位（按图样，「亮」位是一个金色脉冲，「暗」位没有脉冲），每位约 0.55 秒。金色脉冲沿短线走约 0.25 秒碰到电极片：**同一帧**电极片和盒子靠电极的一侧亮一下金色，盒子里从电极那个高度往上的光**立刻**（2 帧以内）暗下去，暗的那一段接着往上流出盒子。入口的光始终不变。暗不是全灭，留一条细线。
- 第一个脉冲时，在电极片和出口之间给一个短暂的指向标记「电到 → 光暗」（两版都有，0.8 秒后淡出），帮第一次看的人对上因果。
- 17.0–19.5 再来一组更快的位（每位约 0.3 秒），出口的光一明一暗连成节奏。
- 角注：「示意：调制器里实际是电改变了光的步调；暗不是全灭」。
- 不加 B 版的两路 / 横杠揭晓（审阅意见：B 不作必修；这一版为了一眼看懂，不放）。

### D 光走同一条路 19.5–26.5
- 19.5–20.3 匹配转场：镜头沿出口的光往上摇，光束变成走廊中间那条线，落在和 B 段首**同一个**走廊构图。小标签「换成光：同一条路」。
- 20.3–24.3 用 B 段完全相同的相机函数和流速：青色的亮暗一段一段边缘分明，到远处整体略暗（约 80%），边缘仍齐。路边小标签「光也有一点损耗」。
- 24.3–25.1 「收到」面板用和 B 段完全相同的动作出现；八格依次点亮，和上面的「发出」参考行逐格一致；旁边「✓ 和发出的一样」（白色 / 青色，不用珊瑚色）。
- 25.1–26.5 定格，背景仍流动，√ 轻微呼吸。

### E 抵达 + 回扣 26.5–31.0
- 26.5–28.5 收到的八格缩回 GPU B 的芯片，芯片亮一下（消息到了）。
- 28.5–31.0 匹配转场回到开头那根玻璃丝的近景（和第 0 帧同构图），★ 结尾大字「路一远，电会糊／光，还认得出」，下方小字「不是因为光更快」。
- 最后 0.3 秒不要黑场淡出得太早；结尾画面保持流动。

## 声音（只在试听版，代码合成，不是配音）
- **音画同步的根本做法**：所有声音事件（每一位的「嗒」、电脉冲碰到电极、面板出现、✓ / ✗、转场）的时间都由网页里的同一套函数给出：网页导出 `window.t4Events()`，返回 `[{t, kind, ...}]`；用一个小脚本经 Playwright 把它写成 `events.json`，`audio_t4.py` 读这个文件合成。**声音脚本里不许另写一套时间常数**（T2 的 `n % 8` 跨段没重置就是这么错的）。
- A：玻璃质感的轻「嗒」，跟着玻璃丝里每一段亮光经过画面中心；底下一层很轻的长音。2.0 秒拉远时一个上扬的「呼」。
- B：每一位一声「嗒」（暗位轻），随条纹变虚，尾音越拖越长、越闷（拖尾程度用和画面「虚」同一个函数算）。面板出现时一声低沉的不协和短音，珊瑚格闪时各一声轻「嗡」。
- C：光是一个不变的长音。电脉冲碰到电极片的那一帧一声低「嗡」，同时长音音量下沉（不是全静），随出口的暗段恢复。17 秒起节奏加快。段首进之前停半拍（10.6–11.0 几乎无声）。
- D：每一位一声清脆的「嗒」，从头到尾不拖尾；八位的图样从本段第一拍重新数起，和画面上流的那一段对应。✓ 时一个解决的和弦。
- E：和弦落定，最后回到开头那一声玻璃「嗒」。
- 整体响度大致 -16 到 -14 LUFS，不要削波。

## 科学护栏（只拦讲反的）
- 不画电子变成光：光在 C 段开头就已经亮着，电只让它暗。
- 铜线不突然断：逐渐变虚，对面是「认不清」。标「假设」。
- 光不是无损：到远处约 80%，有小标签。
- 结尾不说「光更快」。
- 走廊是示意，不按比例，不出现米数。
