## 一、影片核心

### 一句话
一条消息要从一颗 GPU 到走廊对面的另一颗。走铜线，它没出几米就糊成一片；于是在糊掉之前，它被改写成一串闪光，挤进一根只有头发丝十分之一粗的玻璃芯里送过去。

### 观众最后记住的一句
**不是光跑得更快，是电走不远。可光的门，只有头发丝的十分之一宽。**

### 这部片子跟的是什么
跟的是**一条消息**，不是一个电脉冲、一个光子或一个小球。

消息在画面上有一个固定的样子：八条并排的线，亮亮暗亮暗暗亮暗。出发时它是这个样子，抵达时还是这个样子。路上它换了三次载体（电 → 光 → 电），换了几种排法，观众每一段都认得出「它还清不清楚」。全片的悬念就是这一件事：**它到的时候，还认得出来吗？**

### 情绪曲线
| 段 | 观众的感受 | 靠什么 |
|---|---|---|
| 开头 | 咦，芯片之间用闪光传数据？ | 一根玻璃丝里的闪光，旁边一根头发 |
| 出发 | 哦，数据长这样 | 八条线的亮暗，拉成一列节拍 |
| 电的路 | 糟了，糊了 | 条纹的边一点点化开，节拍声发闷 |
| 假如一路走铜线 | 到不了 | 幽灵铜缆在几米处就灰掉，对面还远 |
| 换乘 | 原来是这样写上去的 | 一束不变的光，被电一下一下掐暗 |
| 窄门 | 这也太难了 | 歪一点点，光就少一半 |
| 光的路 | 松一口气，然后被距离震住 | 同一条线槽再走一遍，这次一路清楚 |
| 抵达 | 认出来了，就是它 | 八条线亮起，和出发时一模一样 |

### 矛盾、悬念、反转、高潮
- **矛盾**：数据要发得快，路又要长，铜线两样不能兼得。
- **悬念**：这条消息到对面还认不认得出来。
- **反转**：开头说「不是因为光更快」。观众以为换光是为了速度，看到的却是：铜线上的条纹糊掉，玻璃里的条纹不糊。
- **第二个反转**：以为换成光就一路顺了，结果最难的是进门那几微米。
- **视觉高潮**：同一条线槽、同一个机位走两遍。第一遍是铜（假如），几米就灰了；第二遍是光，镜头一路拉远到整个机房，条纹还清清楚楚。

### 为什么比逐句配图有效
1. 原稿按五站平铺，每站一个知识点，分量相同。观众记不住五件事。这一版只让三件事有戏：**糊、写到光上、窄门**。其余的（并排变一列、差分、网卡、DSP、交换机）都退成路过时看见的东西，一个标签带过。
2. 原稿的因果靠句子连（「所以」「但是」）。这一版的因果靠画面连：同一串条纹，在铜上糊，在玻璃里不糊，观众不听旁白也看得出来。
3. 原稿的比喻是货物运输。写实硬件上再叠卡车，容易让人以为数据是被运走的东西。这一版只用一个比喻，而且它本身就是「图样靠介质传」：**说话**。GPU 之间「传话」；铜线像隔着墙听人说话，声音还在，字听不清；DSP 是有人把话重新说清楚；光是换一条不吞字的路。原稿自己也说 GPU 要「说得快」。
4. 声音跟画面是同一件事。消息有一段固定的节拍。铜线上条纹糊的时候，节拍声同步被滤掉高频，变闷。这不是配乐手法，是同一个物理过程：铜线对变化快的成分衰减更大。

## 二、拆题（仓库规则要求的四问，用来找机制和反转，不是片子结构）

标题：一个比特的旅程：从 GPU 到 GPU。

| 四问 | 答案 | 演示 |
|---|---|---|
| 为什么不（一直用电）？ | 数据发得越快、路越长，铜线上的信号越糊 | 条纹化开；幽灵铜缆几米就灰掉 |
| 不，意味着什么？ | 近处靠芯片把话重新说清楚（费电），远处只能换路 | DSP 前糊后清，散热片发热 |
| 如果换成光，会怎样？ | 条纹写到光上，在玻璃里走几百米、几公里还清楚 | 调制器；同一条线槽走第二遍 |
| 换成光，又意味着什么？ | 多了两道难题：把电写到光上，把光对进玻璃芯 | 歪半个红细胞，光少一半 |

- 「原来是这样」：不是光更快，是电走不远。
- 「原来还可以这样」：同一条消息，中途换了载体，照样送到。
- 结尾把标题反过来说：一个比特的旅程，其实是三段——电、光、电。

## 三、完整导演剧本（按视觉节拍排）

**时长**：约 2 分 10 秒（正片约 124 秒 + 片尾卡 4 秒）。这是按节拍估的，以 Animatic 看节奏为准；不为凑时长删解释，也不为显得完整往里加。
**旁白**：21 句，约 265 字（不算标点；现稿是 37 句、约 540 字）。有四段不说话，让画面和声音自己讲。
**画面里的字**：只出现在正在演示的东西旁边。同一时刻画面里最多一个标签加一个角注。不放五站条，不放悬浮的波形面板和读数表。字幕、标签和角注避开抖音、小红书界面遮住的区域，沿用现有 Remotion 工程的安全区设置。
**颜色**：金色只给电，青色只给光，珊瑚色只给「出错」。条纹暗的地方不是全黑，是变暗。

下面的时间是全片时间，单位秒。

### 第 1 拍　玻璃丝（0–6）
| 项 | 内容 |
|---|---|
| 观众看见 | 第一帧：机柜顶上的线槽，几百根黄色跳线。镜头已经贴着其中一根在往里推。这一根有一段护套是半透明的，里面一根玻璃丝，一串青色的明暗只沿着它正中间细细的一线在走。1.5 秒时，一根头发横在旁边：玻璃丝和头发差不多粗，中间走光的那一线只有头发的十分之一。大字贴在这根线上：「GPU 之间传数据／为什么要用玻璃丝？」 |
| 镜头 | 一个不切的推进，3 秒时穿过护套，停在玻璃丝和头发旁边。光只画在正中间的芯里，不往外漫 |
| 看懂的因果 | 数据是一串明暗，走在一根玻璃丝正中间极细的一线里 |
| 旁白 | 「AI 机房里，数据是靠闪光传的。」（0.3–2.3）「可不是因为光更快。」（3.2–4.8） |
| 声音 | 机房的低频风声。闪光每过一下，一声很轻的玻璃质感的「嗒」，八拍一组，这就是全片的节拍动机 |
| 观众理解了 | 这条讲的是：数据为什么要变成光 |

角注：`红外光看不见，青色为示意`。
尺寸：玻璃丝（包层）约 0.125 毫米，头发约 0.07–0.08 毫米，走光的芯约 8–9 微米（FACTS F10、`blender_test_scale/FACTS.md`）。

### 第 2 拍　它出发时是电（6–20）
| 项 | 内容 |
|---|---|
| 观众看见 | 竖在画面中间的那根青色玻璃丝，原地变成一根金色的金属线（同一位置、同一形状，颜色和质感换了）。镜头后撤，露出它是八条并排金属线里的一条。八条线整条亮或整条暗：亮亮暗亮暗暗亮暗。镜头顺着它们走到芯片边缘：八条线在这里一层层并拢，最后只剩一路，亮暗变成一下接一下的节拍。再往外，这一路是并排的两根线，永远一亮一暗、互相相反 |
| 镜头 | 匹配转场进入；之后一个方向的平移，不转向 |
| 看懂的因果 | 并排的一排，变成一个接一个的一列；节拍比原来快 |
| 旁白 | 「它出发的时候，是电。」（6.5–8.2）「芯片里，数据是并排放着的。」（9.5–11.6）「可出口就那么几个，只能排成一列，一个接一个地发。」（13.0–17.2） |
| 声音 | 八条线亮起时是一个和弦（同时响）；并成一路后变成同一组音一个接一个（琶音）。观众用耳朵也能听出「一排变一列」 |
| 观众理解了 | 消息的样子（八条线的亮暗）；它被拉成了一串节拍 |

标签：`一路信号，两根线送：电压一正一反`。
角注：`这是 GPU 自己的高速接口，这样的通道有 16 条，这里只跟 1 条；连线和电路为简化示意，硅和绝缘层已透明化`。
不说「SerDes」这个词；它出现在片尾的路线图上，留给下一集讲。

### 第 3 拍　电的路：糊（20–40）
| 项 | 内容 |
|---|---|
| 观众看见 | 镜头跟着这一对线往下穿出芯片（一对凸点，一帧带过封装），落到电路板上。板上是一对并行的走线，亮暗沿着线排开，像一条会往前流的条形码，两根线上的图样互相相反。走了十几厘米，条纹的边开始发虚。到一颗芯片（网卡）前，条纹进去，出来的时候重新变得清楚，而且变短、变密。接着是一段机箱里的铜缆：这次条纹糊得更快，到机箱后部时亮和暗已经快分不出了 |
| 镜头 | 贴着走线低飞，一个方向。到网卡时相机停 0.5 秒，芯片边上的条纹仍在流动 |
| 看懂的因果 | 路越长越糊；节拍越密，糊得越早 |
| 旁白 | 「麻烦是：数据发得越快、路越长，信号就越糊。」（26.5–30.5）「像隔着墙听人说话：声音还在，字听不清了。」（33.0–37.0） |
| 声音 | 节拍声随着条纹一起被滤掉高频，越来越闷。到网卡时短暂恢复清脆并加快，进铜缆后再次变闷。20–26 秒不说话 |
| 观众理解了 | 铜线会把消息弄糊，这是这部片子的麻烦所在 |

标签（网卡旁）：`网卡：重新打包，换更快的节拍`。
角注：`亮暗 = 电压高低，已慢放数十亿倍，条纹未按比例；网卡之后实际用四级电平，这里画两级`。

### 第 4 拍　假如一路走铜线（40–50）
| 项 | 内容 |
|---|---|
| 观众看见 | 镜头从机箱后部抬起来，看见线槽通向走廊对面的另一排机柜，那边标着「GPU B」。一根半透明的幽灵铜缆（只有轮廓，标「假如」）沿线槽伸出去，条纹跟着走。镜头沿线槽匀速拉远，场景里立着立体字的距离：1 米、2 米、3 米（**数字待核实**，见本拍末尾）。条纹在两三米处化成均匀的暗金色，再往前什么都没有了。对面的机柜还很远 |
| 镜头 | 一个连续的拉远镜头。**这个机位和运动在第 8 拍会原样再用一次** |
| 看懂的因果 | 这个速度下，铜线送不到对面 |
| 旁白 | 「照这样，它到不了对面。」（44.5–46.5） |
| 声音 | 节拍闷成一片低鸣，然后没了。静半拍 |
| 观众理解了 | 铜线走不远。接下来必须有别的办法 |

角注：`以每条通道约每秒一千亿个比特为例；机柜内的短距离，今天仍大量用铜`。
这是全片最需要查证的一拍，见第六节「要验证的」第 1 条。

### 第 5 拍　有人把话重新说清楚（50–57）
| 项 | 内容 |
|---|---|
| 观众看见 | 回到机箱后部。铜缆接进一个插在笼子里的小模块（外壳半透明）。快糊掉的条纹进了模块里的一颗芯片，出来时重新变得边缘分明。芯片上方的散热片泛起一点热浪 |
| 镜头 | 推进到模块里，停 0.5 秒 |
| 看懂的因果 | 趁还救得回来，把消息重新认清；这要花电 |
| 旁白 | 「趁还认得出来，一颗芯片把它重新说清楚——代价是电。」（50.5–55.5） |
| 声音 | 闷的节拍「啪」地一下恢复清脆 |
| 观众理解了 | 近处可以补救，但每补一次都费电，不能一路补到对面 |

标签：`DSP：重新认清、理整齐`。角注：`常见方案；也有不带 DSP 的模块`。

### 第 6 拍　换乘：写到光上（57–75）
| 项 | 内容 |
|---|---|
| 观众看见 | 模块里另一颗很小的芯片（激光器）发出一束青色的光，沿芯片上一条极细的通道走，亮度一点不变。这束光分成两路，并排走过一段，再合起来。金色的条纹沿着两路旁边的电极到达。条纹每到一个「暗」，合起来之后的那束光就暗一下。从这里往后，青色的光上带着条纹，金色的条纹留在原地，不再往前 |
| 镜头 | 先看那束不变的光（3 秒，什么都不发生）；然后镜头移到电极和光并排的位置，停住不动，让变化自己发生 |
| 看懂的因果 | 光本身不带消息；是电在控制它的明暗。消息从金色的东西跳到了青色的东西上 |
| 旁白 | 「激光器只管发一束稳稳的光。」（58.5–61.0）「电信号推一下，这束光就暗一下。」（65.5–68.5）「这串数据，就写到了光上。」（71.0–73.0） |
| 声音 | 激光是一个不变的长音。电极到达后，长音被切成节拍，音色从金属换成玻璃。61–65 秒不说话 |
| 观众理解了 | 电怎么变成光：不是电变成了光，是电在光上写字 |

标签：`激光器`、`调制器`。
角注：`以硅光模块为例；暗不是全灭；电信号先经驱动器放大（未画出细节）`。
不讲干涉。模型做成看得出「分两路再合起来」，想知道的人下一集再看。

### 第 7 拍　窄门（75–93）
| 项 | 内容 |
|---|---|
| 观众看见 | 带着条纹的光走到芯片边缘。镜头一路推近，场景里的立体字给出尺寸：光通道「不到 0.5 微米」；对面是一根玻璃丝，中间那个能走光的芯「约 9 微米」；旁边一根头发横过，比这个芯粗十倍左右（和整根玻璃丝差不多粗）；一个红细胞停在旁边作比例，和玻璃芯差不多大。光通道末端把光斑放大，对准玻璃芯，光进去了，条纹清楚。然后玻璃丝往旁边挪了半个红细胞那么远：进到芯里的光暗了一半，漏掉的光在旁边散成一小片很淡的光锥。再挪回来，亮度恢复 |
| 镜头 | 一个连续的对数匀速推进，从毫米到微米，约 3 秒一个十倍，最后 1.5 秒减速停住。停住之后只动玻璃丝 |
| 看懂的因果 | 门极窄；歪一点，光就丢 |
| 旁白 | 「接下来是最难的一步：进门。」（75.5–78.0）「这扇门，只有头发丝的十分之一宽。」（81.5–84.5）「歪半个红细胞那么远，光就丢一半。」（87.5–90.5） |
| 声音 | 推进时节拍不变。挪歪的时候节拍**变轻但不变闷**，和铜线的「闷」明确不同；挪回来恢复 |
| 观众理解了 | 换成光的代价：对得极准。铜线的毛病是糊，光的毛病是丢 |

角注：`相对于对准时的比例；假设两边光斑同为约 9 微米；模斑转换器只画外形`。

### 第 8 拍　光的路（93–108）
| 项 | 内容 |
|---|---|
| 观众看见 | 光进了玻璃芯。镜头开始往后拉，一直不切：玻璃丝 → 头发粗细的包层 → 黄色护套的跳线 → 线槽。到线槽时，机位和第 4 拍完全一样，立体字的 1 米、2 米、3 米还在原地。条纹越过了铜线灰掉的地方，继续清清楚楚地往前。镜头继续拉远：机柜、走廊、整个机房。路中间，这根线拐进一台机柜又出来 |
| 镜头 | 一个连续的对数匀速拉远，约 2.5 秒一个十倍。经过第 4 拍的机位时放慢半秒，让观众认出来 |
| 看懂的因果 | 同一条路，铜线几米就糊，光一路清楚 |
| 旁白 | 「同样的路，光走过来，还是清清楚楚。」（98.0–101.0）「它没有跑得更快，只是一路上丢得极少。」（103.0–106.5） |
| 声音 | 节拍一直清脆。越过 3 米处时音乐进入新段落（进之前停半拍）。93–98 秒不说话 |

### 功能链（画面不必每块都拍，但逻辑上都在）
GPU A 的接口（串化，两级）→ 电路板 → 网卡（重新打包，换成更快的节拍，四级）→ 机箱内铜缆 → 模块里的 DSP → 驱动器 → 调制器（激光器供光）→ 芯片上的光通道 → 光纤 →（交换机）→ 光纤 → 模块里的探测器、放大器、DSP → 网卡 → GPU B 的接口（解串）。

和现稿的差别：模糊的演示放在网卡之后的铜缆上，由模块里的 DSP 来整理，这和 `08` 查到的结构一致（`08` 第六节「不一致 2」的做法一）。

### 最大的一处简化：图样贯穿全程
真实线路上，每一段的比特序列都不一样：GPU 的接口有自己的编码，网卡按网络协议重新打包，后面还有纠错编码和四级电平。**保持不变的是载荷，不是线路上的波形。**

片中的处理：
- 只有两端的「八条线」图样是同一个，它代表载荷。
- 路上的条纹每过一颗芯片就换一种排法（网卡之后更密）。不把路上的条纹画成同一串。
- 网卡旁的标签写「重新打包」。

### 要验证的（进 FACTS 之前都不算数）
1. **铜缆能走多远**。提案里写的是「两三米」。我的依据是印象里的以太网标准（每条通道 100 Gb/s 的无源铜缆标准距离约 2 米，带芯片的有源铜缆能到几米），**没有查原文**。这个数决定第 4 拍和方案二能不能成立，必须先查。查不到可靠来源，就把立体字改成不带数字的「几米」。
2. **半个红细胞，光丢一半**。按 FACTS F11 的公式算：红细胞约 7.5 微米（`blender_test_scale/FACTS.md`），一半是 3.75 微米；exp(−3.75² ÷ 4.6²) ≈ 0.51。假设和 F11 相同：两边光斑同为约 9 微米，这是最宽松的情形；相对于对准时的比例。
3. **「隔着墙听人说话」**是类比：墙对高音的阻隔比对低音强。方向和铜线一致，但机制不同（墙是质量隔声，铜线是趋肤效应和介质损耗）。旁白里用「像」字，不说「就是」。
4. **第一句「AI 机房里，数据是靠闪光传的」**：对机柜之间成立；同一机箱、同一机柜里仍大量用铜（FACTS H20）。第 4 拍的角注要把这一点说出来。
5. **「数十亿倍」**的慢放倍率：动画定下节拍后按实际速度重算（FACTS H3 的算法）。
6. 现稿里没解决的仍然没解决：参考机型只核了一款；适配它的硅光模块没查到；内部铜缆的长度和信号速度没查到。

### 观众不会被带偏成什么
| 容易有的误解 | 片中怎么防 |
|---|---|
| 数据是一个被运走的小球 | 没有任何球或粒子。电是沿线的亮暗，光是沿线的明暗，芯片里是整条线亮暗 |
| 电变成了光 | 画面上金色的条纹留在电极上不走，光是另一束本来就在的光 |
| 光比电跑得快 | 开头和第 8 拍各说一次不是；画面里不安排任何比速度的镜头 |
| 铜线没用了 | 机箱里那两段都是铜；角注写明短距离仍大量用铜 |
| GPU 直接连着光模块 | 网卡在画面里出现，条纹在那里明显变了样 |
| 所有模块都这样 | 角注：以硅光模块为例；也有不带 DSP 的 |
| 条纹的长度是真的 | 角注：已慢放，未按比例 |

### 最值得先做的三个视觉测试
| # | 测试 | 证明什么 | 长度 | 怎么做 |
|---|---|---|---|---|
| T1 | **糊**：一对走线上的条纹越走越虚，节拍声同步变闷 | 不看字幕，能不能看出「信号坏了」，而且看得出是糊不是暗 | 8 秒 | 几何很简单，不需要资产；带声音 |
| T2 | **同一条线槽走两遍**：幽灵铜缆几米灰掉；同机位换成光，一路清楚 | 全片的高潮立不立得住；押韵的机位观众认不认得出 | 12 秒 | 用现有的机房场景 |
| T3 | **窄门**：玻璃丝挪歪半个红细胞，光暗一半，漏光成锥 | 微米级的动作在手机上看不看得清；「丢」和「糊」分不分得开 | 8 秒 | 用测试镜头三的资产 |

### 概念预演建议多长
三个测试合计约 28 秒，540×960，粗模加声音。这三段立住了，再做约 120 秒的全片粗模 Animatic。

这一阶段不渲染。到时候按 `CLAUDE.md` 的规则估价：先渲两三帧量出每帧耗时再估整批。参考上一轮实测（540×960、24 采样，每帧 2.5–3.7 秒，每小时约 0.89 美元），28 秒约 840 帧，粗估在 1 美元上下，超过就先报给用户。

## 八、对自己方案最有杀伤力的反对意见

**1.「图样贯穿全程」在行家眼里是错的。**
线路上的比特每一段都被重新编码、打包、加扰，没有哪一串波形从 GPU A 原样走到 GPU B。片子却让观众觉得「同一串东西一路走过去」。
修正：见第六节。只有两端的八条线是同一个图样，路上的条纹每过一颗芯片就换排法。如果这样仍嫌误导，退一步：路上的条纹完全不重复任何图样，只表现「清楚 / 糊」。

**2. 把铜线说得太没用。**
现实里机柜内大量用铜，新一代机柜甚至用铜背板连几十颗 GPU（这一句凭已有知识，没查）。「三米就到不了」只在特定速率、无源铜缆的条件下成立；用有源铜缆、降速率都能更远。行家会说这是为了讲故事挑了条件。
修正：第 4 拍的条件写在角注里；机箱里两段铜线在画面上是正常工作的；数字查不实就不上数字。更稳的说法是「数据发得越快，铜线能走的距离越短」，把幽灵铜缆做成距离随节拍变密而缩短，不报具体米数。

**3. 两分钟里的东西还是太多。**
图样、节拍声、说话的比喻、差分、网卡、DSP、调制器、对准、交换机，再加两段尺度旅行。每一样都有道理，合起来观众可能抓不住主线。
修正：只有三件事配旁白讲（糊、写到光上、窄门）。其余都只是一个标签，按第三节末尾的顺序可以一样一样砍掉。Animatic 给没看过的人看一遍，复述不出「为什么换光」就继续砍。

**4. 开头给的是答案，不是问题。**
第一帧就是光纤，等于先说了结论。真正的麻烦（糊）20 秒以后才出现，中间 14 秒在讲「一排变一列」，和开头的问题没有直接关系，观众可能在这里划走。
修正：两个办法。一是用方案二开头（先给矛盾）。二是把第 2 拍压到 8 秒以内，或者挪到第 4 拍之后当成回答「那它原来长什么样」。我倾向保留方案一并压短第 2 拍，但这要看 Animatic。

**5. 靠声音的设计，在静音播放时不成立。**
节拍变闷是这个方案里我最喜欢的一点，但很多人刷短视频不开声音。
修正：它只是加分项。糊必须先在画面上成立（T1 要静音看一遍）。

**6. 和系列已有的约定有出入。**
系列定过大框架「寄快递」，顶部有五站导航条，每集要点明自己在框架里的位置。这一版用的是「说话」，画面上没有导航条，五站只在片尾卡出现。
修正：这是创作判断，不是事实问题，交给用户定（见第九节）。

## 九、需要用户定的创意问题

1. **开头**用方案一「玻璃丝」还是方案二「到不了」。第一句前要不要加一句大框架。
2. **比喻**：用「说话」（隔着墙听不清），还是保留系列定的「寄快递」，还是原稿的卡车和高铁。
3. **五站**：画面上不放导航条、只在片尾卡出现，可以吗。「SerDes」这个词正片里不说，可以吗。
4. **第 4 拍的幽灵铜缆**：接受用一个「假如」的画面来讲铜线走不远吗。数字查实之前，是写「几米」还是先不做这一拍。
5. **时长**：约 2 分钟，旁白约 300 字，四段不说话。方向对吗。
6. **三个视觉测试**先做哪个，或者三个一起做。
7. **标题**：片名是「一个比特的旅程」，片中跟的是「一条消息」（八个比特的图样）。标题不动、片中说「这串数据」，可以吗；还是把画面简化到真的只跟一个比特。
8. 现稿里没定的科学选择（参考机型、光模块以硅光为例、明暗画两级）在这一版里照旧沿用推荐方案，仍等用户确认。
