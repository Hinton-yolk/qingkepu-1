## 一、影片核心

### 一句话
一条消息要从一颗 GPU 到几十米外的另一颗。数据发得这么快，走铜线没出几米就糊成一片；于是在糊掉之前，它被改写成一串闪光，挤进一根只有头发丝十分之一粗的玻璃芯里送过去。

### 观众最后记住的一句
**不是光跑得更快，是这么快的电信号走不远。可光的门，只有头发丝的十分之一左右宽。**

### 这部片子跟的是什么
跟的是**一条消息**，不是一个电脉冲、一个光子或一个小球。

消息在画面上有一个固定的样子：八条并排的线，亮亮暗亮暗暗亮暗。出发时它是这个样子，抵达时还是这个样子。路上它换了三次载体（电 → 光 → 电），换了几种排法，观众每一段都认得出「它还清不清楚」。全片的悬念就是这一件事：**它到的时候，还认得出来吗？**

### 情绪曲线
| 段 | 观众的感受 | 靠什么 |
|---|---|---|
| 开头 | 咦，芯片之间用闪光传数据？ | 一根玻璃丝里的闪光，旁边一根头发 |
| 出发 | 哦，数据长这样 | 八条线的亮暗，拉成一列节拍 |
| 电的路 | 糟了，糊了 | 条纹的边一点点化开，节拍声拖出尾音、糊在一起 |
| 假如一路走铜线 | 到不了 | 节拍每密一档，幽灵铜缆上清楚的那一段就缩短一截；对面还在几十米外 |
| 换乘 | 原来是这样写上去的 | 一束不变的光，被电一下一下掐暗 |
| 窄门 | 这也太难了 | 歪一点点，光就少一半 |
| 光的路 | 松一口气，然后被距离震住 | 同一条线槽再走一遍，这次一路清楚 |
| 抵达 | 认出来了，就是它 | 八条线亮起，和出发时一模一样 |

### 矛盾、悬念、反转、高潮
- **矛盾**：数据要发得快，路又要长，铜线两样不能兼得。
- **悬念**：这条消息到对面还认不认得出来。
- **反转**：开头说「不是因为光更快」。观众以为换光是为了速度，看到的却是：铜线上的条纹糊掉，玻璃里的条纹不糊。
- **第二个反转**：以为换成光就一路顺了，结果最难的是进门那几微米。
- **视觉高潮**：同一条线槽、同一个机位走两遍。第一遍是铜（假如），两三米就灰了；第二遍是光，镜头一路拉远到整个机房，条纹还清清楚楚。

### 为什么比逐句配图有效
1. 原稿按五站平铺，每站一个知识点，分量相同。观众记不住五件事。这一版只让三件事有戏：**糊、写到光上、窄门**。其余的（并排变一列、差分、网卡、DSP、交换机）都退成路过时看见的东西，一个标签带过。
2. 原稿的因果靠句子连（「所以」「但是」）。这一版的因果靠画面连：同一串条纹，在铜上糊，在玻璃里不糊，观众不听旁白也看得出来。
3. 原稿的比喻是货物运输。写实硬件上再叠卡车，容易让人以为数据是被运走的东西。这一版的主比喻只有一个，而且它本身就是「图样靠介质传」：**说话**。GPU 之间「传话」；铜线像在空车库里喊话，喊得越快、离得越远，回声越把字糊成一片；DSP 是有人把话重新说清楚；光是换一条不糊字的路。原稿自己也说 GPU 要「说得快」。旁白里另有几个顺口的说法（窄门、写到光上、接力），不展开成第二套比喻；Animatic 阶段再清一遍，能不用就不用。
4. 声音跟画面讲同一件事。消息有一段固定的节拍。铜线上条纹糊的时候，节拍声同步拖出尾音、少掉高频，一拍压到下一拍上。这是类比，方向和铜线上发生的事一致：变化快的成分衰减更大，前一个比特的尾巴压到后一个上。

## 二、拆题（仓库规则要求的四问，用来找机制和反转，不是片子结构）

标题：一个比特的旅程：从 GPU 到 GPU。

| 四问 | 答案 | 演示 |
|---|---|---|
| 为什么不（一直用电）？ | 数据发得越快、路越长，铜线上的信号越糊 | 条纹化开；节拍每密一档，幽灵铜缆上清楚的一段就短一截 |
| 不，意味着什么？ | 近处靠芯片把话重新说清楚（费电），远处只能换路 | DSP 前糊后清，散热片发热 |
| 如果换成光，会怎样？ | 条纹写到光上，在玻璃里走几百米、几公里还清楚 | 调制器；同一条线槽走第二遍 |
| 换成光，又意味着什么？ | 多了两道难题：把电写到光上，把光对进玻璃芯 | 歪半个红细胞，光少一半 |

- 「原来是这样」：不是光更快，是电走不远。
- 「原来还可以这样」：同一条消息，中途换了载体，照样送到。
- 结尾把标题反过来说：一个比特的旅程，其实是电和光的接力（电 → 光 → 电；途中每过一台交换机再重复一次）。

## 三、完整导演剧本（按视觉节拍排）

**时长**：约 2 分 10 秒（正片约 124 秒 + 片尾卡 4 秒）。这是按节拍估的，以 Animatic 看节奏为准；不为凑时长删解释，也不为显得完整往里加。
**旁白**：22 句，字数见本节末尾的统计（现稿是 37 句、约 540 字）。有七段 3 秒以上不说话，让画面和声音自己讲（脚本按时间码数的）：17.2–26.5、37.5–41.0、55.5–58.5、61.0–65.5、78.0–81.5、90.5–98.0、106.5–110.5 秒。最长的两段是穿出芯片落到电路板上（9.3 秒），和光进了玻璃芯之后往外拉（7.5 秒）。
**画面里的字**：只出现在正在演示的东西旁边。同一时刻画面里最多一个标签加一个角注。不放五站条，不放悬浮的波形面板和读数表。字幕、标签和角注避开抖音、小红书界面遮住的区域，沿用现有 Remotion 工程的安全区设置。
**颜色**：金色只给电，青色只给光，珊瑚色只给「出错」。条纹暗的地方不是全黑，是变暗。跳线的护套是黄色（真实情况），要和表示电的金色分开：护套做成不发光的哑光柠檬黄，电做成自己发光的琥珀金；第一帧里不出现金色的东西。
**条纹的流速**：全片所有条纹在屏幕上的流动速度统一，尤其第 4 拍和第 8 拍同机位的两遍必须同速，不给人「谁跑得快」的印象。

下面的时间是全片时间，单位秒。

### 第 1 拍　玻璃丝（0–6）
| 项 | 内容 |
|---|---|
| 观众看见 | 第一帧：机柜顶上的线槽，几百根黄色跳线。镜头已经贴着其中一根在往里推。这一根有一段护套是半透明的，里面并排十来根玻璃丝，镜头跟其中一根：一串青色的明暗只沿着它正中间细细的一线在走。1.5 秒时，一根头发横在旁边：玻璃丝和头发差不多粗，中间走光的那一线只有头发的十分之一。大字贴在这根线上：「AI 芯片之间传数据／为什么要用玻璃丝？」 |
| 镜头 | 一个不切的推进，3 秒时穿过护套，停在玻璃丝和头发旁边。光只画在正中间的芯里，不往外漫 |
| 看懂的因果 | 数据是一串明暗，走在一根玻璃丝正中间极细的一线里 |
| 旁白 | 「AI 机房里，数据靠闪光传。」（0.3–2.4）「可不是因为光更快。」（3.2–4.8） |
| 声音 | 机房的低频风声。闪光每过一下，一声很轻的玻璃质感的「嗒」，八拍一组，这就是全片的节拍动机 |
| 观众理解了 | 这条讲的是：数据为什么要变成光 |

角注：`红外光看不见，青色为示意；明暗已慢放，未按比例；多芯跳线，这里只跟一根`。
尺寸：玻璃丝（包层）约 0.125 毫米，头发约 0.07–0.08 毫米，走光的芯约 8–9 微米（FACTS F10、`blender_test_scale/FACTS.md`）。

### 第 2 拍　它出发时是电（6–20）
| 项 | 内容 |
|---|---|
| 观众看见 | 竖在画面中间的那根青色玻璃丝，原地变成一根金色的金属线（同一位置、同一形状，颜色和质感换了）。镜头后撤，露出它是八条并排金属线里的一条。八条线整条亮或整条暗：亮亮暗亮暗暗亮暗。镜头顺着它们走到芯片边缘：八条线在这里一层层并拢，最后只剩一路，亮暗变成一下接一下的节拍。再往外，这一路是并排的两根线，永远一亮一暗、互相相反 |
| 镜头 | 匹配转场进入；之后一个方向的平移，不转向 |
| 看懂的因果 | 并排的一排，变成一个接一个的一列；节拍比原来快 |
| 旁白 | 「它出发的时候，是电。」（6.5–8.2）「芯片里，数据是并排放着的。」（9.5–11.6）「可出口就那么几个，只能排成一列，一个接一个地发。」（13.0–17.2） |
| 声音 | 八条线亮起时是一个和弦（同时响）；并成一路后变成同一组音一个接一个（琶音）。观众用耳朵也能听出「一排变一列」 |
| 观众理解了 | 消息的样子（八条线的亮暗）；它被拉成了一串节拍 |

标签：`一路信号，两根线送：电压一正一反`。
角注：`这是 GPU 自己的高速接口，这样的通道有 16 条，这里只跟 1 条（示例架构）；连线和电路为简化示意，硅和绝缘层已透明化`。
不说「SerDes」这个词；它出现在片尾的路线图上，留给下一集讲。

### 第 3 拍　电的路：糊（20–40）
| 项 | 内容 |
|---|---|
| 观众看见 | 镜头跟着这一对线往下穿出芯片（一对凸点，一帧带过封装），落到电路板上。板上是一对并行的走线，亮暗沿着线排开，像一条会往前流的条形码，两根线上的图样互相相反。走了一段，条纹的边开始发虚。到一颗芯片（网卡）前，条纹进去，出来的时候重新变得清楚，而且变短、变密。接着是一段机箱里的铜缆：节拍变密了，这段铜缆走到头，条纹的边又开始发虚 |
| 镜头 | 贴着走线低飞，一个方向。到网卡时相机停 0.5 秒，芯片边上的条纹仍在流动 |
| 看懂的因果 | 路越长越糊。「节拍越密糊得越早」留给下一拍演示 |
| 旁白 | 「麻烦是：数据发得越快、路越长，信号就越糊。」（26.5–30.5）「像在空车库里喊话：喊得越快、离得越远，字越糊成一片。」（33.0–37.5） |
| 声音 | 节拍声随着条纹一起拖出尾音、少掉高频，一拍压到下一拍上。到网卡时恢复清脆并加快，进铜缆后尾音又出来。17.2–26.5 秒不说话（跨第 2、3 拍） |
| 观众理解了 | 铜线会把消息弄糊，这是这部片子的麻烦所在 |

标签（网卡旁）：`网卡：重新打包，换更快的节拍`。
角注：`亮暗 = 电压高低，已慢放数十亿倍，条纹和发虚的程度为示意，未按比例；沿途的重定时芯片已省略；网卡之后实际用四级电平，这里画两级`。
注意：同样长度下，机箱里的铜缆比电路板走线损耗小（见第六节）。画面不能让人读成「铜缆比走线更糟」，这一段只表现「走到头又开始发虚」。

### 第 4 拍　假如一路走铜线（40–50）
| 项 | 内容 |
|---|---|
| 观众看见 | 镜头从机箱后部抬起来，看见线槽通向走廊对面的另一排机柜，那边标着「GPU B」，立体字「几十米外」。一根半透明的幽灵铜缆（只有轮廓，标「假如」）沿线槽伸出去，条纹跟着走，一开始很疏，能清楚地走到「7 米」的立体字那里。然后节拍一档一档变密，条纹清楚的那一段跟着一截一截缩回来：5 米、3 米、2 米。停在最密的一档：条纹在两三米处化成均匀的暗金色，再往前什么都没有了。对面的机柜还很远 |
| 镜头 | 一个连续的拉远镜头。**这个机位和运动在第 8 拍会原样再用一次** |
| 看懂的因果 | 数据发得越快，铜线能走的路越短；现在这个速度，送不到对面 |
| 旁白 | 「数据每快一档，铜线能走的路就短一截。」（41.0–44.5）「照这样，它到不了对面。」（46.5–48.5） |
| 声音 | 节拍每加快一档，尾音糊得更早；最后糊成一片低鸣，然后没了。静半拍 |
| 观众理解了 | 铜线走不远。接下来必须有别的办法 |

角注：`以不带芯片的铜缆为例，最密一档是每条通道约每秒一千亿个比特；加了芯片的铜缆能到几米；机柜内的短距离，今天仍大量用铜`。
四档的距离（7、5、3、2 米）是以太网历代标准里无源铜缆的距离，对应每条通道每秒约 100 亿、250 亿、500 亿、1000 亿个比特。审核已查：2 米一档读过两份原文；另外三档只有二手来源，进 FACTS 前要对标准条目。见第六节「要验证的」第 1 条。
「几十米外」来自一份第三方参考设计（FACTS H18，仅单一来源），标「示例」。

### 第 5 拍　有人把话重新说清楚（50–57）
| 项 | 内容 |
|---|---|
| 观众看见 | 回到机箱后部。铜缆接进一个插在笼子里的小模块（外壳半透明）。快糊掉的条纹进了模块里的一颗芯片，出来时重新变得边缘分明。芯片上方的散热片泛起一点热浪 |
| 镜头 | 推进到模块里，停 0.5 秒 |
| 看懂的因果 | 趁还救得回来，把消息重新认清；这要花电 |
| 旁白 | 「趁还认得出来，一颗芯片把它重新说清楚——代价是电。」（50.5–55.5） |
| 声音 | 闷的节拍「啪」地一下恢复清脆 |
| 观众理解了 | 近处可以补救，但每补一次都费电、费钱，路越长越不划算 |

标签：`DSP：重新认清、理整齐`。角注：`常见方案；也有不带 DSP 的模块`。

### 第 6 拍　换乘：写到光上（57–75）
| 项 | 内容 |
|---|---|
| 观众看见 | 模块里另一颗很小的芯片（激光器）发出一束青色的光，沿芯片上一条极细的通道走，亮度一点不变（镜头贴着这束光缓缓往前推，光本身不变）。这束光分成两路，并排走过一段，再合起来。金色的条纹沿着两路旁边的电极到达。条纹每到一个「暗」，合起来之后的那束光就暗一下。从这里往后，青色的光上带着条纹；金色的条纹陪着光走到电极尽头为止，不再往前 |
| 镜头 | 先贴着那束不变的光缓推 3 秒（光不变，镜头和环境在动）；然后镜头移到电极和光并排的位置，放到最慢，让变化自己发生 |
| 看懂的因果 | 光本身不带消息；是电在控制它的明暗。消息从金色的东西跳到了青色的东西上 |
| 旁白 | 「激光器只管发一束稳稳的光。」（58.5–61.0）「电信号推一下，这束光就暗一下。」（65.5–68.5）「这串数据，就写到了光上。」（71.0–73.0） |
| 声音 | 激光是一个不变的长音。电极到达后，长音被切成节拍，音色从金属换成玻璃。61.0–65.5 秒不说话 |
| 观众理解了 | 电怎么变成光：不是电变成了光，是电在光上写字 |

标签：`激光器`、`调制器`。
角注：`以单模硅光模块为例（也有其它方案）；实际用四级明暗，这里画两级，暗不是全灭；电信号先经驱动器放大（未画出细节）`。
不讲干涉。模型做成看得出「分两路再合起来」，想知道的人下一集再看。

### 第 7 拍　窄门（75–93）
| 项 | 内容 |
|---|---|
| 观众看见 | 带着条纹的光走到芯片边缘。镜头一路推近，场景里的立体字给出尺寸：光通道「不到 0.5 微米」；对面是一根玻璃丝，中间那个能走光的芯「约 8–9 微米」；旁边一根头发横过，比这个芯粗十倍左右（和整根玻璃丝差不多粗）；一个红细胞停在旁边作比例，和玻璃芯差不多大。光通道末端把光斑放大，对准玻璃芯，光进去了，条纹清楚。然后玻璃丝往旁边挪了半个红细胞那么远：进到芯里的光暗了一半，没对进去的光漏进芯外面的玻璃里，往前散开、很快消失。再挪回来，亮度恢复 |
| 镜头 | 一个连续的对数匀速推进，从毫米到微米，约 3 秒一个十倍，最后 1.5 秒减速停住。停住之后只动玻璃丝 |
| 看懂的因果 | 门极窄；歪一点，光就丢 |
| 旁白 | 「接下来是最难的一步：进门。」（75.5–78.0）「这扇门，只有头发丝的十分之一左右宽。」（81.5–85.0）「歪半个红细胞那么远，光就丢一半。」（87.5–90.5） |

| 观众理解了 | 换成光的代价：对得极准。在铜线上，信号是糊掉的；在这道门口，光是丢掉的 |

角注：`相对于对准时的比例；假设两边光斑同为约 9 微米，这是最宽松的情形，实际往往更严；演示的是装配时的容差，装好后光纤是固定的；模斑转换器只画外形`。
说明：这里故意画了漏光，漏光本身就是内容。「3D 镜头语法」里「不让辉光扩散到波导外面」管的是正常导光的那些段落，那些段落仍然守。

## 五、三秒开场：两个可拍的方案

| | 方案一「玻璃丝」（**推荐**） | 方案二「到不了」 |

| 第一帧 | 线槽里几百根黄色跳线，其中一根护套半透明，里面的玻璃丝正在闪。 大字：「AI 芯片之间传数据／为什么要用玻璃丝？」 | 机箱后部，一根铜缆从笼子伸出去，上面的条纹正往外流。大字：「这串数据要去走廊对面／铜线送得到吗？」 |

| 检查项 | 方案一 |
|---|---|
| 第一帧不听声音，看得出在讲什么吗 | 是：玻璃丝里的闪光 + 大字问题 |

## 六、科学真实性映射

### 画面动作代表什么

| 画面动作 | 代表的物理或系统行为 | 性质 | 依据 |
|---|---|---|---|
| 八条线整条亮、整条暗 | 芯片里的并行数据，每条线一个比特；微米级的线上同一时刻几乎等电位，所以整条一起亮暗 | 示意：真实的并行位宽没查到，画 8 条是为了看得清 | FACTS V9；`08` 导演决策表 Q7 |
| 八条并拢成一路，节拍变快 | 串化：并行数据按顺序送上一条通道 | 简化示意 | FACTS F3、F4（FACTS 里标着「未查到来源」） |
| 一路变成一对、永远相反 | 差分信号：两根导体电压相反，接收端取差 | 真实。「从哪一级起是一对」是简化 | FACTS H5、H6 |
| 电路板上流动的条纹 | 电压沿走线的分布，已慢放数十亿倍 | 示意：条纹长度未按比例（真实每个比特在板上约 5 毫米） | FACTS H8、V8 |
| 网卡到机箱后部是一段铜缆 | 参考机型里网卡在机箱中部，到后部光口是内部铜缆。这是这款机型的做法，别的机型多是网卡自带光口 | 真实（只核了一款机型） | FACTS H10、H11 |

### 功能链（画面不必每块都拍，但逻辑上都在）
GPU A 的接口（串化，两级）→ 电路板 → 网卡（重新打包，换成更快的节拍，四级）→ 机箱内铜缆 → 模块里的 DSP → 驱动器 → 调制器（激光器供光）→ 芯片上的光通道 → 光纤 →（交换机）→ 光纤 → 模块里的探测器、放大器、DSP → 机箱内铜缆 → 网卡（解串、拆包，再排一次队）→ 电路板 → GPU B 的接口（解串）。

和现稿的差别：模糊的演示放在网卡之后的铜缆上，由模块里的 DSP 来整理，这和 `08` 查到的结构一致（`08` 第六节「不一致 2」的做法一）。

### 最大的一处简化：图样贯穿全程
真实线路上，每一段的比特序列都不一样：GPU 的接口有自己的编码，网卡按网络协议重新打包，后面还有纠错编码和四级电平。**保持不变的是载荷，不是线路上的波形。**

片中的处理：
- 只有两端的「八条线」图样是同一个，它代表载荷。
- 路上的条纹每过一颗芯片就换一种排法（网卡之后更密）。不把路上的条纹画成同一串。
- 网卡旁的标签写「重新打包」。

### 要验证的（进 FACTS 之前都不算数）
1. **铜缆能走多远**。初稿凭印象写「两三米」，审核这一轮用 AnySearch 查了（来源表在审核报告里，进 FACTS 时抄过去）：
   - 每条通道约 100 Gb/s 时，以太网标准给无源铜缆定的目标是「至少 2 米」（Samtec 的 DesignCon 2020 论文、Ethernet Alliance 2023 讲稿，读过原文；IEEE 标准原文要付费，没读到）。厂商的无源产品做到 2–3 米。
   - 线性放大的有源铜缆 3–5 米；带 DSP 的有源铜缆到 7 米（两家厂商的说法，互相独立，但都是厂商资料）。
   - 历代标准的距离 7、5、3、2 米（每条通道 10、25、50、100 Gb/s）：只有维基百科的表，二手，**进 FACTS 前要对标准条目**。对不上就退回只画最密的一档。
   - 同一速率下电路板走线约 25 厘米，铜缆 2 米（Ethernet Alliance 讲稿）。所以第 3 拍不能画成「铜缆比走线糊得快」。
2. **半个红细胞，光丢一半**。按 FACTS F11 的公式算：红细胞约 7.5 微米（`blender_test_scale/FACTS.md`），一半是 3.75 微米；exp(−3.75² ÷ 4.6²) ≈ 0.51。假设和 F11 相同：两边光斑同为约 9 微米，这是最宽松的情形；相对于对准时的比例。
3. **「空车库里喊话」**是类比：回声把前一个字的尾巴拖到后一个字上，喊得越快、离得越远越听不清。这和铜线上「前一个比特的尾巴压到后一个上」同向，也带着「越快」「越远」两个维度。机制不同：车库是反射，铜线主要是高频损耗把边沿拉宽。旁白里用「像」字。系列 03 的资料里记着用过类似的说法（「像空车库里说话」），我没有核对 03 的成片。初稿用的是「隔着墙听人说话」，审核指出它没有「越快」「越远」这两个维度，所以换了；两个都列在第九节请用户定。
4. **第一句「AI 机房里，数据靠闪光传」**：对机柜之间成立；同一机箱、同一机柜里仍大量用铜（FACTS H20）。第 4 拍的角注要把这一点说出来。
5. **「数十亿倍」**的慢放倍率：动画定下节拍后按实际速度重算（FACTS H3 的算法）。
6. 「这段距离上光纤的色散可以忽略」是凭已有知识写的，没查来源；不上屏。
7. 现稿里没解决的仍然没解决：参考机型只核了一款；适配它的硅光模块没查到；内部铜缆的长度和信号速度没查到。FACTS 里 F3、F4、F5、F8 仍标着「未查到来源」。

## 八、对自己方案最有杀伤力的反对意见

**1.「图样贯穿全程」在行家眼里是错的。**
线路上的比特每一段都被重新编码、打包、加扰，没有哪一串波形从 GPU A 原样走到 GPU B。片子却让观众觉得「同一串东西一路走过去」。
修正：见第六节。只有两端的八条线是同一个图样，路上的条纹每过一颗芯片就换排法。如果这样仍嫌误导，退一步：路上的条纹完全不重复任何图样，只表现「清楚 / 糊」。

**2. 把铜线说得太没用。**
现实里机柜内大量用铜：有的新机柜里，几十颗 GPU 之间靠几千根铜缆相连（审核查到一家官方来源；那是机柜内的另一条路，不是片中这条）。「两三米」只对不带芯片的铜缆成立；加了芯片能到 7 米左右，降速率也能更远。行家会说这是为了讲故事挑了条件。
修正（已改进第 4 拍）：不再只报一个米数，改成演示规律本身：节拍每密一档，能走的路短一截。条件（不带芯片）和例外（加芯片能到几米、机柜内仍大量用铜）写进角注；「对面」明确画在几十米外，加了芯片的铜缆也到不了。

**3. 两分钟里的东西还是太多。**
图样、节拍声、喊话的比喻、差分、网卡、四档速率、DSP、调制器、对准、交换机，再加两段尺度旅行。每一样都有道理，合起来观众可能抓不住主线。
修正：只有三件事配旁白讲（糊、写到光上、窄门）。其余都只是一个标签，按第三节末尾的顺序可以一样一样砍掉。Animatic 给没看过的人看一遍，复述不出「为什么换光」就继续砍。

**4. 开头给的是答案，不是问题。**
第一帧就是光纤，等于先说了结论。真正的麻烦（糊）20 秒以后才出现，中间 14 秒在讲「一排变一列」，和开头的问题没有直接关系，观众可能在这里划走。
修正：两个办法。一是用方案二开头（先给矛盾）。二是把第 2 拍压到 8 秒以内，或者挪到第 4 拍之后当成回答「那它原来长什么样」。我倾向保留方案一并压短第 2 拍，但这要看 Animatic。

**5. 靠声音的设计，在静音播放时不成立。**
节拍声跟着条纹一起糊是这个方案里我最喜欢的一点，但很多人刷短视频不开声音。
修正：它只是加分项。糊必须先在画面上成立（T1 要静音看一遍）。

**6. 和系列已有的约定有出入。**
系列定过大框架「寄快递」，顶部有五站导航条，每集要点明自己在框架里的位置。这一版用的是「说话」，画面上没有导航条，五站只在片尾卡出现。
修正：这是创作判断，不是事实问题，交给用户定（见第九节）。

## 九、需要用户定的创意问题

1. **开头**用方案一「玻璃丝」还是方案二「到不了」。第一句前要不要加一句大框架。
2. **比喻**：用「说话」，还是保留系列定的「寄快递」，还是原稿的卡车和高铁。如果用「说话」：铜线那一句用「空车库里喊话，回声把字糊成一片」（现稿；有「越快、越远」两个维度，系列 03 的资料里有类似说法），还是「隔着墙听人说话，声音还在、字听不清」（初稿；更短，但没有这两个维度，也容易被理解成「被挡住」）。
3. **五站**：画面上不放导航条、只在片尾卡出现，可以吗。「SerDes」这个词正片里不说，可以吗。
4. **第 4 拍的幽灵铜缆**：接受用一个「假如」的画面来讲铜线走不远吗。四档距离里有三档只有二手来源：等对过标准条目再上屏，还是先只画最密的一档（两三米）。「对面」画在几十米外可以吗。
5. **时长**：约 2 分 10 秒，旁白 22 句、不到 300 字，说话约 63 秒，其余时间不说话。方向对吗。
6. **三个视觉测试**先做哪个，或者三个一起做。
7. **标题**：片名是「一个比特的旅程」，片中跟的是「一条消息」（八个比特的图样）。标题不动、片中说「这串数据」，可以吗；还是把画面简化到真的只跟一个比特。
8. **第 7 拍**：「歪半个红细胞，光丢一半」是最宽松情形下的估算。旁白照这样说、条件放角注，还是换成更保守的说法（例如只说「歪一点点，光就丢一大截」）。
9. **片尾卡**的「下一篇」写什么。
10. 现稿里没定的科学选择（参考机型、光模块以硅光为例、明暗画两级）在这一版里照旧沿用推荐方案，仍等用户确认。
