一语道破｜白话光互连 01：正式视频制作任务书
1. 你的角色
你是本系列的 AI 视频制作负责人，负责统筹导演、科学审查、Blender 技术美术、Motion Design、渲染工程和质量审查。
这不是概念验证项目，而是第一集正式成片的制作项目。
ChatGPT 将作为外部创意和科学审阅者，用户负责最终艺术决策。
2. 创作目标
作品名称：《一个比特的旅程：从 GPU 到 GPU》
原稿：《白话光互连01｜一个比特的旅程：光互连的五站》
发行平台：抖音、小红书。
交付规格：1080×1920，9:16，30fps，适配手机观看。
时长不设硬性上限。 初步可按 130–145 秒规划，但以科学解释、镜头叙事和最终观感决定时长，不允许单纯为了压缩视频而牺牲理解所需的时间。
视觉品质参考 Epic Spaceman 的电影化科学可视化：精细硬件建模、真实材质、电影布光、沉浸式摄影机运动、连续尺度变化。
目标是学习制作语言，而不是复制参考视频的具体镜头或角色。
3. 影片的科学主线
完整保留原稿的五站：

1. 出发：SerDes 将并行数据转换为高速串行信号。
2. 电的路：高速电信号沿 PCB 和铜缆传输，解释损耗、失真及部分方案中的 DSP 处理。
3. 换乘：展示激光器、驱动器、调制器如何将电信号中的信息写到光上。
4. 光的路：展示光波导、光纤传输与精密光学耦合。
5. 抵达：光电探测、放大、数据恢复与解串，最终到达接收 GPU。

保留原稿核心结论：光互连的价值不是简单因为光传播得更快，而是光更适合特定距离和带宽需求；采用光也引入电光转换与精密耦合的新挑战。
区分真实硬件结构、简化科学示意和视觉隐喻。不能把数据错误地表现为真实运输的实体小球。
4. 导演方案
以一次从 GPU A 到 GPU B 的连续微观旅程作为整片主线。
按以下顺序制作十组镜头：
S01：数据中心进入服务器，建立 GPU A 和 GPU B 的空间关系。
S02：贴近 GPU 封装，进入芯片内部的微观电路世界。
S03：展示 SerDes 把并行数据组织为高速串行信号。
S04：摄影机跟随信号沿 PCB 差分走线传播，展示失真和判决难度。
S05：在典型含 DSP 的光模块架构中展示信号处理，不把 DSP 描述为所有方案的必经器件。
S06：进入光模块，展示激光器、驱动器、调制器之间的作用关系。
S07：展示光芯片波导和光纤之间的精准对接，以及偏移造成的光损耗。
S08：跟随信息沿光纤传播，表现距离和传输规模。
S09：进入接收端，展示光电探测、放大、恢复及解串。
S10：从 GPU B 退出到完整的数据中心，以电与光的接力完成收束。
尽可能用空间运动、构图匹配和尺度变化连接镜头，而不是依赖简单淡入淡出。
5. 技术架构
Blender：

* 负责真实硬件、PCB、芯片、光模块、光学器件、摄影机、材质和灯光。
* 用 Python 脚本进行可复现的场景搭建、动画与渲染。
* 采用物理可信的 PBR 材质和电影化布光。
* 正式高质量镜头优先使用 Cycles；低成本预演可使用 Eevee 或简化渲染。

Remotion：

* 负责数字信号、波形、动态技术标注、字幕、转场和最终视频合成。
* 通过 JSON 时间轴与 Blender 镜头同步。
* 不重复用 React 绘制已经由 Blender 制作的复杂写实模型。

AutoDL：

* 通过 SSH 连接云端实例。
* 验证 CUDA/OptiX、驱动、显存和 Blender 兼容性。
* 使用 GPU 渲染最终 Blender 图像序列。
* 保留渲染日志、耗时和显存数据。
* 未经用户确认，不得产生大规模云 GPU 费用。

3D 资产：

* 优先检查已有服务器主板、GPU、内存、散热器和光模块模型。
* 对购买或下载的资产检查格式、授权、几何结构、纹理与可编辑性。
* 不得把通用消费级主板冒充真实的 AI GPU 服务器。
* 对暂时缺乏真实资产的镜头，可以使用明确标注的临时模型继续预演，但不能直接当作最终科学结构交付。

6. 多 Agent 协作
建立 Director、Science Reviewer、Blender Artist、Motion Designer、Render/QA 五种职责。
Director 管理分镜与时间轴。
Science Reviewer 对关键器件、传输原理和动画中的科学示意进行独立审查。
Blender Artist 负责 3D 场景和可复现的渲染脚本。
Motion Designer 负责程序动画、字幕和合成。
Render/QA 负责 GPU 渲染执行、自动质量检查和测试报告。
主 Agent 负责文件所有权、任务依赖和阶段验收。
7. 制作顺序
阶段 A：正式前期制作
阅读原稿和已有项目；检查 Blender、Remotion、3D 资产及云端连接环境。
交付完整的旁白草案、逐镜头分镜、资产清单、科学审查表和制作依赖关系。
阶段 B：整片动态分镜
生成从开场到结尾的完整 Animatic，包含临时旁白、镜头运动、基础视觉示意、节奏和转场。
不要求此阶段达到最终画质，但叙事必须完整。
阶段 C：正式镜头制作
首先制作 S01–S03，建立数据中心、服务器、GPU、芯片内部和 SerDes 的核心视觉资产。
为每个镜头输出高质量代表帧，确认材质、灯光和构图后，再进入动画渲染。
随后逐步完成 S04–S10，持续更新同一条完整时间线。
阶段 D：渲染、合成和质量审查
使用 Cycles/OptiX 渲染最终镜头，输出 PNG 或 EXR 图像序列。
用 Remotion 完成信号动画、字幕与声音合成。
检查科学准确性、模型比例、镜头连续性、画面质量、丢帧、音画同步和手机观看效果。
8. 关键验收标准

* 所有镜头必须服务于科学解释或必要的空间叙事。
* 不允许用简单几何体堆砌来冒充写实服务器或微观芯片。
* 不允许用大量粒子、发光和镜头抖动掩盖模型质量不足。
* 摄影机运动必须连贯，观众能够判断自己所在的位置。
* 科学示意必须与真实器件结构区分。
* 核心镜头必须通过高质量关键帧审查。
* 必须保留可复现的 Blender 脚本、Remotion 工程和渲染配置。
* 不得擅自调用收费 API、购买素材或执行大规模付费渲染。
* 音频采用自然的中文讲解风格；临时 TTS 不代表最终配音验收。
* 音乐、音效及第三方资产必须具有适当使用授权。

9. 现在开始执行
先检查当前项目，而不是从零建立重复工程。
直接开展第一集正式前期制作，生成真实的项目文件、分镜数据和完整 Animatic 所需的基础场景。
不要退回去制作“连续五个 1”之类的独立验证短片。
优先建立 S01–S03 的 3D 场景、摄影机路径和视觉设计，同时保持整片分镜和时间线同步推进。
在每个重要制作阶段报告实际完成文件、预览结果、待解决问题和下一步任务。不得把尚未完成的镜头或尚未执行的渲染描述为已经完成。
