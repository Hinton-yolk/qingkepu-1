## 四、需要用户和 ChatGPT 一起定的
这几件不是主 agent 单方面能解决的。

1. **会话和 PR 评论说法不一致时听谁的**。这一轮的例子：会话里「直接跑」，PR 评论「每批报批」。建议定一条：花钱、公开、改权限这三类事，以更严的为准，并且主 agent 必须回到会话里向用户确认一次。
2. **新规则中途发到 PR 上，主 agent 不会自动看到**。按现在的约定不能给主 agent 设自动触发，所以它只在被叫到时读 PR。两个办法选一个：用户发新评论后在会话里说一声「PR 有新评论」；或者接受主 agent 只在「花钱前、交付前」这两个时点读 PR，其它时候发的新规则要到这两个时点才生效。
3. **云渲染的审批放在哪**（**已定**，用户 2026-11-12 晚：「预算1美元以内的，直接跑，一美元以外的，报给我」，写进了 `CLAUDE.md`）。原来的问题是：PR 评论要求「向用户报批」，而用户实际是在 Claude 会话里批。建议：报批和批准都在会话里完成，主 agent 事后把批准的范围和实际花费记进 PR。
4. **一轮任务的大小**。这一轮把 P0 调研、P1 文案、P2 三个镜头的建模和重渲、审查、交付打成了一包，中间任何一个角色停下都会卡住整包。建议以后一轮只带一个可验收的结果（例如「只锁定硬件路径文档」或「只修 S02 灰屏和 23 秒接缝」），每轮结束都有一个能看的东西。
5. **用量上限**。这一轮撞了两次（每周上限、5 小时上限）。主 agent 看不到还剩多少额度。建议用户在开工时说一句大概还能用多少，或者定好哪些角色用便宜的模型；主 agent 这边把建模、合成这类活交给便宜的模型，只有事实核查用最强的。
6. **文档文件名要不要改成英文**。现在的中文文件名在 PR 里做链接容易坏。改成英文名（例如 `09_round2_notes.md`）最省事，但仓库里现有的中文文件名是用户的习惯，改不改请用户定。
