## 一、和独立稿相比改了什么，为什么

| 改动 | 理由 |
|---|---|
| **调制升成第一高潮，留三拍**：只有光 → 电来了 → 光跟着变。三样放在同一个竖构图里，相机固定 | 融合任务的要求，也是 ChatGPT 剧本第四幕的做法。独立稿里这一段有 18 秒，但「电推一下，光就暗一下」是黑箱。现在让观众看见电改变了调制器里的什么 |
| **讲到「步调」为止**：两路光步调一致就亮，其中一路被电拖慢半步就暗 | 要让「电控制光」看得见，调制器里必须有一样东西在变。只画「分两路再合」而不给出变化，观众看到的仍是黑箱。不出现「干涉」「相位」这两个词。这一条要用户定（第八节） |
| **铜 / 光对照改成紧挨着的两遍**，放在窄门之后；独立稿里铜那一遍在调制之前 | 融合任务的要求。两遍挨着，同机位的押韵不靠记忆，静音也能看出差别。代价是「为什么要换光」的理由来得晚了，所以第 3 拍末尾加一句「对面还在几十米外」把悬念先立住 |
| **撤掉 7 / 5 / 3 / 2 米阶梯和「到某个距离突然消失」** | 融合任务的要求；那三档本来只有二手来源。改成：条纹沿路逐渐发虚，亮和暗的差距越来越小，到对面时八条线拼不出原来的图样 |
| **铜那一遍明确是「假设」，并先说一句电在短距离里很好用** | 取自 ChatGPT 剧本第三幕（「电信号当然能传数据，而且在短距离里非常有效」）和它列的误解第 2 条：对比不等于说参考系统里的铜线失效了 |
| **光那一遍保留一点损耗**：到对面略暗，但边缘仍齐 | 取自 ChatGPT 剧本第五幕「保留适度的损耗示意」。也和窄门那一拍统一：光的毛病是变暗，铜的毛病是变糊 |
| **接收端不画成完美恢复**：探测器后面的条纹又淡又毛，放大后仍有毛边，判决之后才齐 | 取自 ChatGPT 剧本第六幕（放大、均衡、时钟恢复、判决；不要毫无噪声） |
| **窄门加一个截面**：先看一眼玻璃芯里中间亮、边缘渐暗的光斑，再转回侧面 | 取自 ChatGPT 剧本第四幕末；仓库「3D 镜头语法」的光纤画法也这样要求 |
| **结尾最后一句**用 ChatGPT 的框架句，和独立稿的接力并成一句 | 「GPU 负责计算，互连负责让它们一起计算」正好是系列的大框架（AI 不只靠算得快，还靠传得快） |
| **DSP 并进「电的路」**，不再单独一拍；串化从 14 秒压到 11 秒 | 融合任务：优先压缩串化讲解和设备过场 |
| **旁白**删掉画面和声音已经讲清的句子 | 删掉的：「可出口就那么几个，只能排成一列」「趁还认得出来，一颗芯片把它重新说清楚」「同样的路，光走过来，还是清清楚楚」「照这样，它到不了对面」「数据每快一档……」「歪半个红细胞那么远，光就丢一半」「光变回电，一列拆回一排」。新增的在调制段（三句）和对照段（一句）。总量见第三节的统计：比独立稿（22 句、292 个字）少，但少得不多，因为调制段加了解释 |

**没有采用的**
- ChatGPT 剧本的眼图。它是一张悬浮的图表，手机上很小，普通观众不认识。这一版用场景里已有的东西表达同一件事：条纹亮和暗的差距缩小，对面的八条线拼不出图样。如果测试 ② 显示这样读不出「认不清」，再换回眼图。
- ChatGPT 剧本开场的「漆黑中 GPU 浮现、拉远」和 12 秒的机房规模段。保留独立稿的玻璃丝开场（见第二节）。
- 它的片名《一万颗 GPU，怎么说同一句话？》没有用进正片，但和这一版「说话」的比喻对得上，列为标题备选（第八节）。

**时长**：正片约 121 秒 + 片尾卡 4 秒，共约 125 秒。独立稿是 128 秒。调制从 18 秒加到 23 秒，这是全片最该花时间的地方；省下来的在串化（−3 秒）、DSP 独立一拍（−7 秒）和抵达。试排时如果 110–120 秒就立得住，先压第 3 拍的设备过场。

## 二、首 3 秒

| | 方案一「玻璃丝」（**主推**） | 方案二「铜线送得到吗」 |
|---|---|---|
| 第一帧 | 线槽里几百根黄色跳线，其中一根护套半透明，里面并排的玻璃丝中有一根，正中间一线光在闪。大字：「AI 芯片之间传数据／为什么要用玻璃丝？」 | 机箱后部，线槽通向远处的机柜。一根铜缆上的条纹正往外流，越远越虚。大字：「这串数据要去几十米外／铜线送得到吗？」 |
| 0–3 秒 | 镜头推进，穿过护套；头发横过来作比例：玻璃丝和头发差不多粗，光只走正中间的一线 | 镜头沿铜缆推出去，条纹越来越虚 |
| 第一句 | 「AI 机房里，数据靠闪光传。」 | 「数据发得这么快，铜线走不了多远。」 |
| 好处 | 第一帧就是答案里最奇怪的那样东西；有尺度；结尾能回到同一帧 | 第一帧就是矛盾 |
| 代价 | 开头只是「光在闪」，第一个讲出因果的演示在 8 秒以后 | 普通观众认不出画面里是什么；第一句超过 2 秒；把第二高潮提前用掉 |

主推方案一。它和仓库规则的两处临界、和系列 skill 的出入，和独立稿第五节写的一样，没有变化：第一句按「开头放慢」念约 2.1 秒；机制演示在第一帧只是「光在闪」。

## 三、融合导演稿

**时长**：正片 0–121 秒，片尾卡 121–125 秒。时间是全片时间，单位秒。
**旁白统计**（脚本数的）：18 句，271 个字（不算标点，「AI」算两个），说话合计约 58 秒；最快的一句每秒 5.8 个字（「可对面那颗 GPU，还在几十米外。」）。3 秒以上不说话的有 7 段：10.8–20.5、23.8–27.5、30.8–35.2、42.0–45.0、49.2–52.5、69.5–79.5、83.6–98.5 秒。
**画面里的字**：只贴在正在演示的东西旁边，同一时刻最多一个标签加一个角注。不放五站条、眼图、读数表。避开平台界面遮住的区域。
**颜色**：金色只给电，青色只给光，珊瑚色只给「认错了」。护套是不发光的哑光柠檬黄，和发光的琥珀金分开。
**条纹的流速**：全片所有条纹在屏幕上同速。第 6、7 拍的两遍用同一条相机曲线、同一个流速参数。
**载荷和线路波形分开**：只有两端的「八条线」是同一个图样。路上的条纹每过一颗芯片换一种排法，不重复那个图样。

### 第 1 拍　玻璃丝（0–6）
| 项 | 内容 |
|---|---|
| 可见动作与因果 | 第一帧：线槽里几百根黄色跳线，镜头已经贴着一根在推进。这一根的护套有一段半透明，里面并排十来根玻璃丝，镜头跟其中一根：一串青色的明暗只沿它正中间细细的一线在走。1.5 秒时一根头发横在旁边：玻璃丝和头发差不多粗，走光的那一线只有头发的十分之一左右。大字贴在线上 |
| 镜头／转场 | 一个不切的推进，3 秒时穿过护套 |
| 旁白和留白 | 「AI 机房里，数据靠闪光传。」（0.3–2.4）「可不是因为光更快。」（3.2–4.8） |
| 声音同步点 | 每过一下闪光，一声玻璃质感的「嗒」。3.0 秒穿过护套时环境声一沉 |
| 观众应看懂 | 数据是一串明暗，走在玻璃丝正中间极细的一线里。这条要讲：为什么要变成光 |

角注：`红外光看不见，青色为示意；明暗已慢放，未按比例；多芯跳线，只跟一根`。

### 第 2 拍　载荷：一排变一列（6–17）
| 项 | 内容 |
|---|---|
| 可见动作与因果 | 那根青色玻璃丝原地变成一根金色的线。镜头后撤：它是八条并排的线里的一条。八条线整条亮或整条暗：亮亮暗亮暗暗亮暗。镜头顺着它们走到芯片边缘：八条一层层并拢成一路，亮暗变成一下接一下。出来的这一路是并排的两根线，永远一亮一暗、互相相反 |
| 镜头／转场 | 6.0 秒匹配转场（同位置、同形状，颜色换了）。之后一个方向的平移 |
| 旁白和留白 | 「它出发时是电：芯片里一排并着的线，亮和暗就是数据。」（6.5–10.8）。10.8–20.5 不说话：并拢成一路这件事交给画面和声音 |
| 声音同步点 | 7.5 秒八条线亮起：一个和弦。11–15 秒并拢：同一组音变成琶音，节拍加快 |
| 观众应看懂 | 这八条线的亮暗就是那份数据（记住它的样子）；它被拉成了一串 |

标签：`一路信号，两根线送：电压一正一反`。
角注：`GPU 自己的高速接口，这样的通道有 16 条，只跟 1 条（示例架构）；连线和电路为简化示意，硅和绝缘层已透明化`。
正片不说「SerDes」，留在片尾路线图上。

### 第 3 拍　电的路（17–38）
| 项 | 内容 |
|---|---|
| 可见动作与因果 | 镜头跟着这一对线往下穿出芯片，落到电路板上。板上一对走线，亮暗沿线排开，往前流；两根线上的图样互相相反。走了一段，条纹的边开始发虚。到网卡：条纹进去，出来时重新清楚，排法变了，更短更密。接着一段机箱里的铜缆，走到头，边又开始发虚。铜缆插进机箱后部的一个小模块（外壳半透明）：发虚的条纹进了模块里的一颗芯片，出来时边缘分明；芯片上方的散热片泛起一点热浪。镜头抬起：线槽通向远处另一排机柜，立体字「几十米外」 |
| 镜头／转场 | 贴着走线低飞，一个方向，全程不切。网卡和 DSP 各停 0.5 秒，停的时候条纹仍在流 |
| 旁白和留白 | 「数据发得越快、路越长，信号就越糊。」（20.5–23.8）「像空车库里喊话，回声把字糊成一片。」（27.5–30.8）「可对面那颗 GPU，还在几十米外。」（35.2–37.6）。DSP 那一下不说话，靠画面、声音和标签 |
| 声音同步点 | 条纹发虚的同一帧，节拍开始拖出尾音、一拍压到下一拍上。网卡处恢复清脆并换一种更快的节拍。DSP 处「啪」地恢复清脆 |
| 观众应看懂 | 铜线上，信号走着走着会糊；可以让芯片重新认清，但要花电；而对面还很远 |

标签：`网卡：重新打包，换更快的节拍`；`DSP：重新认清、理整齐（要耗电）`。
角注：`亮暗 = 电压高低，已慢放数十亿倍；条纹和发虚的程度为示意，未按比例；沿途的重定时芯片已省略；网卡之后实际用四级电平，这里画两级；也有不带 DSP 的模块`。
注意：同样长度下，机箱里的铜缆比电路板走线损耗小。画面只表现「走到头又开始发虚」，不能读成「铜缆比走线更糟」。

### 第 4 拍　第一高潮：电控制光（38–61）
相机固定。竖构图分三层：下面是光的入口，中间是调制器的两路，上面是光的出口；电从侧面进来。

| 项 | 内容 |
|---|---|
| 可见动作与因果 | **只有光（38–44）**：模块里一颗小芯片（激光器）发出一束青色的光，从画面下方进来，分成两路，并排走一段，再合成一路从上方出去。入口、出口亮度都不变。两路光上各有细密的波纹，波峰对着波峰，步调一致。 **电来了（44–52）**：金色的条纹沿着其中一路旁边的电极到达。条纹的「亮」一到，这一路的波纹就被拖慢半步，和另一路错开；条纹的「暗」到了，又对齐。入口的光仍然不变。 **光跟着变（52–61）**：两路合上的地方，步调一致时出口亮，错开时出口暗。出口的光第一次有了明暗，一下一下往上走。金色的条纹走到电极尽头为止，不再往前 |
| 镜头／转场 | 进入时相机从 DSP 跟着条纹平移到位，然后固定 23 秒不动。变化都发生在画面里：波纹在流，条纹在到，出口在变 |
| 旁白和留白 | 「先有一束稳稳的光。它什么都还没说。」（38.5–42.0）「光分成两路。电推一下，其中一路就慢半步。」（45.0–49.2）「合到一起：步调一致就亮，错开就暗。」（52.5–56.0）「电没有变成光。是电控制着光，把数据写了上去。」（56.8–60.6） |
| 声音同步点 | 两路光各一个相同的长音。电极一推，其中一个音错开半步，两个音真的互相抵消，声音变轻（不是全静）；对齐时恢复。从 52 秒起这一轻一响成了新的节拍，音色从金属换成玻璃，音乐在这里进入高潮（进之前停半拍） |
| 观众应看懂 | 光本来不带信息；电改变了其中一路光的步调，出口的光就跟着一明一暗。是电控制光，把信息写到光上 |

标签：`激光器`（38 秒）、`调制器`（44 秒），不同时出现。
角注：`以单模硅光模块为例（也有其它方案）；波纹的疏密未按比例；实际用四级明暗，这里画两级，暗不是全灭；暗的时候光去了另一个出口（未画出）；电信号先经驱动器放大`。
这一拍里凡是讲机制的说法（「慢半步」、哪一路被推、两路是不是同时被反向推）都**待核**，见第五节。

### 第 5 拍　窄门（61–77）
| 项 | 内容 |
|---|---|
| 可见动作与因果 | 带着明暗的光走到芯片边缘。镜头一路推近，立体字给尺寸：光通道「不到 0.5 微米」；对面一根玻璃丝，中间走光的芯「约 8–9 微米」；一根头发横过，比这个芯粗十倍左右；一个红细胞停在旁边，和芯差不多大。先看一眼截面：芯里的光斑中间亮、边缘渐暗。转回侧面：通道末端把光斑放大，对准玻璃芯，光进去了，明暗清楚。玻璃丝往旁边挪了一点点：进到芯里的光暗了一截，没对进去的光漏进芯外面的玻璃，往前散开消失。挪回来，亮度恢复 |
| 镜头／转场 | 61–69 秒一个连续的对数匀速推进，从毫米到微米；截面 1.5 秒；之后相机不动，只动玻璃丝 |
| 旁白和留白 | 「最难的一步：把光对进玻璃芯。」（61.5–64.0）「这扇门，只有头发丝的十分之一左右宽。」（66.0–69.5）。挪歪、挪回的时候不说话 |
| 声音同步点 | 挪歪的同一帧节拍变轻，但不拖尾，和铜线的「糊」不同；挪回时恢复 |
| 观众应看懂 | 换成光的代价：要对得极准。在这道门口，光是丢掉的，不是糊掉的 |

角注：`相对于对准时的比例；演示的是装配时的容差，装好后光纤是固定的；模斑转换器只画外形`。
「歪半个红细胞，光丢一半」和头发的比例都列为**待核**。核过之后，可以在挪歪的时候加回一句带数字的旁白。

### 第 6 拍　第二高潮之一：假如还走铜线（77–91）
| 项 | 内容 |
|---|---|
| 可见动作与因果 | 镜头从玻璃芯一路往后拉，不切：玻璃芯 → 整根玻璃丝 → 黄色跳线 → 机箱后部，停在线槽的起点。跳线旁边浮出一根只有轮廓的铜缆，标「假设」。镜头沿线槽匀速走向对面的机柜。铜缆上的条纹一路逐渐发虚：边沿化开，亮和暗的差距越来越小，没有哪一处突然消失。到对面：八条线试着亮起来，却都是差不多的暗金色，拼不出原来的图样，其中一条闪了一下珊瑚色 |
| 镜头／转场 | 77–82 秒对数拉远；82–83.5 秒停住，幽灵铜缆出现；83.5–90 秒沿线槽的那条相机曲线，第 7 拍原样再用 |
| 旁白和留白 | 「短距离里，电很好用。可同一条路，假如还走铜线呢？」（79.5–83.6）。之后不说话 |

## 七、三项小测试的计划

每项分两步。**第一步免费**：三张关键静帧的简图，加一段本机 CPU 就能出的二维草样（Remotion 或 Canvas，不用 Blender，不用云）。**第二步**是低清动态小样，用户确认这份稿子和测试范围之后才做；放 Drive 方案 A 的审核文件夹，PR 给直链和规格表。

| # | 测试 | 长度 | 最低制作规格 | 通过条件（可判定） |
|---|---|---|---|---|
| ① | **调制器**（先做） | 6–8 秒 | 540×960，30 fps，无声版 + 有声版各一。二维示意即可：入口、两路、电极、出口在同一个固定构图里 | 静音看一遍，能按顺序说出三件事：有一束不变的光进来；电到了，其中一路变了；出口的光跟着一明一暗。不会说成「电变成了光」。量得出的：入口亮度全程变化不超过 5%；电极上的条纹到达比出口第一次变暗早至少 6 帧；出口亮暗比不低于 2 比 1 |
| ② | **同机位铜 / 光对照** | 8–10 秒（两遍各 4–5 秒） | 540×960，30 fps，有声。机房可以是灰模，线槽和两端机柜要有 | 静音看一遍，能说出「第一遍越走越糊，第二遍一路清楚」，并且认得出是同一条路。量得出的：两遍相机逐帧相同；条纹流速相同；对面八条线的亮暗差，铜那一遍不到近端的两成，光那一遍不低于八成；加声音后，拖尾开始和条纹发虚开始相差不超过 2 帧 |
| ③ | **窄门** | 4–6 秒 | 540×960，30 fps，无声即可。相机固定，只动玻璃丝 | 静音看一遍，能说出「对准时亮，挪歪变暗，挪回来又亮」，并且说的是「暗了」不是「糊了」。量得出的：挪动在 540 宽的画面里不少于 12 像素；挪歪时明暗的边缘锐度不变，只有亮度下降 |

- 「说得出」由谁来判：用户和 ChatGPT 各看一遍静音版。观众角色（Codex）要用户先登录，而且听不到声音，只能判静音版。
- 三项合计不到 25 秒。第一步不花钱。第二步如果用到云渲染，按 `CLAUDE.md` 的规则：先渲两三帧量每帧耗时，预计不超过 1 美元直接跑并事后报告，超过先报。
- 顺序：① 先做，它决定第一高潮立不立得住；② 其次；③ 可以和 ② 一起。

## 八、需要用户定的

1. **调制讲到哪一步**：现稿讲到「步调」（两路光步调一致就亮，一路被电拖慢半步就暗），画面上有波纹。另一种是不画波纹，只让观众看见「电到了，出口就暗」。
2. **铜 / 光对照的位置**：现稿把两遍挨在一起放在窄门之后。认可吗。
3. **测试范围**：三项都做，先做 ①。静音复述由用户和 ChatGPT 判，可以吗；要不要现在登录 Codex。
4. **标题**：沿用《一个比特的旅程：从 GPU 到 GPU》，还是考虑 ChatGPT 的《一万颗 GPU，怎么说同一句话？》（和「说话」的比喻对得上）。
5. 独立稿第九节里还没定的照旧：比喻用「说话」还是「寄快递」；画面上不放五站导航条；片尾卡的「下一篇」。
