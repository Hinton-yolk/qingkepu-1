# 07 ChatGPT 直接读取预览视频：存储方案与小文件实测（2026-11-12）

对应 PR #3 评论「追加交接规范」和 Issue #2 的补充要求。

## 结论：现在是阻塞状态
- **还没有任何一个 ChatGPT 能直接下载的视频地址。**「无人工搬运的视频审核」没有实现。
- 我试了零成本的一条路（用户自己的 Google Drive），卡在上传大小上；用户看过情况后决定先不上传，只要方案对比。
- 下面每个方案里「ChatGPT 能不能取到并解码」都**没有验证过**：那一步只能由 ChatGPT 自己做，Claude 这边测到 HTTP 200 不算数。
- 逐秒抽帧接触表继续留在仓库里做辅助，它不能代替看视频。
- 长期规范（`CLAUDE.md` 或交接 SOP）现在不写，等选定方案并由 ChatGPT 实测通过之后再写。

## 一、今天实测到的事实
都是 2026-11-12 在 Claude 的制作环境里测的。

| 测了什么 | 结果 | 说明 |
|---|---|---|
| 仓库可见性 | 私有 | GitHub 搜索接口返回 `private: true` |
| 不登录取仓库里的文件（`raw.githubusercontent.com`） | 404 | 所以把 mp4 提交进仓库也给不出免登录直链 |
| 不登录取 PR #3 评论里的视频附件 | 403 | 证实了 ChatGPT 的判断：PR 附件不能当作它可读 |
| 创建 GitHub Release | 做不到 | 制作环境没有创建 Release 或上传附件的工具；私有仓库的 Release 附件同样要登录 |
| 用户已有的 Google Drive 共享文件夹 | 「知道链接的任何人可查看」，是用户自己设的 | 今天上午我不登录就从里面下载过 3 个文件（12–44 MB，HTTP 200），说明这种文件夹里的文件有免登录直链 |
| 用会话里的 Drive 连接器上传 5.36 MB 的预演 | **失败，没有传上去** | 连接器每次调用上限 4.2 MB，留给文件约 3.1 MB。只建了一个空的子文件夹 |
| 把同一段预演压到 3 MB 以内（只在本地编码，没上传） | 可以 | 39 秒、540×960、30 fps、带标注：2.70 MB；或按镜头分三段：1.76 / 1.33 / 1.91 MB |

没测的：任何地址在 ChatGPT 那边能不能打开、能不能抽帧。

## 二、要满足的条件
来自 PR #3 评论和用户 11-12 的要求：
1. 指向视频文件本身的 HTTPS 直链，ChatGPT 不用登录就能下载。
2. 每次交付不需要用户手动下载再上传。
3. 不公开素材，不改仓库可见性。
4. 不擅自增加费用，不擅自开新账号、改认证方式。
5. 不把密码或长期密钥写进 PR、Issue 或仓库。
6. 不配置 Claude API、Routines、自动触发器。
7. 以 ChatGPT 独立拿到视频并抽帧为验收。

条件 1 和条件 3 之间有张力：免登录直链意味着「拿到链接的人就能下」。能做的是让链接猜不到、只出现在私有仓库和审阅对话里，并且能过期或能撤销。

## 三、方案对比

| | 方案 A：Drive 共享文件夹 + 连接器上传 | 方案 B：Drive + 专用上传凭据 | 方案 C：对象存储 + 限时签名链接 | 方案 D：单独的公开仓库只放预览 |
|---|---|---|---|---|
| 做法 | Claude 用已连接的 Drive 连接器，把审核版传进用户已有的共享文件夹，给出直链 | 同一个文件夹，但 Claude 用脚本直接走 Drive 接口上传 | 私有存储桶（例如 Cloudflare R2、Backblaze B2），每个文件生成一条会过期的下载链接 | 新建一个只放低清审核预览的公开仓库，Claude 用 git 推上去，直链是 raw 地址 |
| 文件大小 | **每个文件约 3 MB 以内** | 不受这个限制 | 不受限制 | 单文件 100 MB 以内 |
| 费用 | 0 | 0 | 这个用量预计为 0 或接近 0（凭印象两家都有约 10 GB 的免费额度，**没有核对当前价目，开通前要查**）；开账号可能要绑定支付方式 | 0 |
| 要用户批准或操作的 | 不需要新账号和密钥；每次上传应用可能弹一次批准 | 要用户建一个只对这个文件夹有权限的上传凭据，通过安全表单存进制作环境 | 要用户开新账号、建桶、生成密钥并存进制作环境 | 要用户建仓库并同意公开这些预览 |
| 链接的性质 | 不过期；猜不到；删文件或关掉文件夹共享即撤销 | 同左 | **会过期**（常见上限 7 天），过期后要重新生成 | 完全公开，谁都能看，能被搜索到 |
| 密钥风险 | 没有密钥 | 有一把长期凭据，存在环境里，不进仓库 | 有一把长期密钥，存在环境里，不进仓库 | 没有密钥 |
| 素材暴露面 | 拿到链接的人 | 拿到链接的人 | 链接有效期内拿到链接的人 | 所有人 |
| Claude 这边现在能不能做 | 能，今天就能测（要先压到 3 MB 以内） | 不能，等凭据 | 不能，等账号和密钥 | 不能，等仓库 |
| ChatGPT 能否取到 | 未验证 | 未验证（和 A 是同一种链接） | 未验证 | 未验证 |

排除掉的做法：
- **GitHub PR 附件、私有仓库的 Release、Actions 产物**：都要登录，今天实测 PR 附件是 403。
- **把 mp4 提交进本仓库**：仓库私有，raw 地址 404；也违反「mp4 不进仓库」。
- **把本仓库改成公开，或开 GitHub Pages**：等于公开全部素材和文档。
- **匿名文件中转站**：把素材交给不受控的第三方，不能撤销。

## 四、3 MB 上限对方案 A 意味着什么
按 540×960、30 fps 估算（今天实测 39 秒压到 2.70 MB，约 550 kbps，画面是低清粗模）：

| 要交的东西 | 能不能塞进一个 3 MB 文件 |
|---|---|
| 39 秒粗模预演 | 能（2.70 MB） |
| 149 秒全片 Animatic | 只能用约 160 kbps，或降到 360×640；看节奏和叙事够用，看细节不够。可以另外按镜头分段传清楚的版本 |
| 局部定稿镜头（写实画面，10–20 秒） | 写实画面比粗模难压，3 MB 大概只够 540×960 的十来秒，看不出材质和灯光的细节 |
| 成片 | 不能 |

所以方案 A 只够撑到 Animatic 阶段；到定稿镜头和成片，必须是 B 或 C。

## 五、我的建议（等用户选）
1. **先花最小的代价弄清 ChatGPT 到底能不能取 Drive 直链。** 这一步不用我上传任何东西：用户的共享文件夹里已经有现成的视频，直链的写法是 `https://drive.usercontent.google.com/download?id=<文件 ID>&export=download&confirm=t`。用户挑一个不介意给 ChatGPT 看的文件，把这个地址交给它试。取不到的话，A 和 B 都不用再考虑。
2. **如果 ChatGPT 能取 Drive 直链**：近期用方案 A 交 Animatic（审核版压到 3 MB 以内，必要时按镜头分段）；进入定稿镜头之前换成方案 B 或 C。
3. **如果要链接会过期、文件不限大小**：方案 C。它最符合「权限可控」，代价是要开新账号和保管一把密钥，需要用户明确批准。
4. 方案 D 只有在用户明确愿意公开低清预演时才考虑。

## 六、选定之后要做的验证
1. Claude 上传当前 39 秒预演（或它的压缩版），在 PR 里写「视频审核交付」一节：直链、对应提交、时长、宽高、帧率、有无音轨、文件大小、sha256。这些数用 `tools/preview_manifest.py` 生成。
2. Claude 自测只作为前置检查：不登录下载、核对 sha256、`ffprobe` 能读出视频流。
3. **ChatGPT 独立下载并抽帧，回报它算出的 sha256 或它看到的画面内容。这一步通过才算验收。**
4. 通过之后，把做法写进长期交接规范，以后每个视频节点的 PR 都带「视频审核交付」一节。
