## 片子在讲什么（逐拍）
| 秒 | 发生的事 | 观众的问题 |
|---|---|---|
| 0–4.2 | AI 回答正在出字。一把镊子夹住句尾光标往后拉：气泡被拉得很长，里面只有空白的纸，一松手光标弹回原位 | 后面的答案，已经写好了吗？ |
| 4.2–9.9 | 下面多出一张「假如早写好」的卡片。用同一个动作掀开盖片：假卡片下面有字，放映时是把盖片挪开、把字露出来；真卡片下面是空白，「火锅」是在光标笔尖处一笔一笔写出来的 | 揭开，还是现写？ |
| 9.9–11.4 | 假卡片退场 | 后面没藏着，是现写的 |
| 11.4–17.2 | 倒带，慢放「火锅」是怎么来的：琥珀色的「前文」条盖住提问和已写的回答 → 从前文冒出几个候选 → 高亮在候选之间跳，停在其中一个 → 落进光标处 → **前文条往前一吞，把「火锅」也收进去** | 那下一块，从哪来？ |
| 17.2–22.5 | 恢复正常速度：「，」「加」「一份」落一块、吞一块，形成节奏。下一轮的候选全是火锅配菜（毛肚 / 肥牛 / 虾滑），一条琥珀线从「火锅」连到它们 | 前文有「火锅」，才冒出「毛肚」 |
| 22.9–26.2 | 光标后面换行，空出两个虚线空位 | 后面几块，能一起算吗？ |

## 这段开场怎么接到整集高潮（五句）
1. 开场立的视觉规则只有一条：琥珀色「前文」条盖到哪里，下一步就只能依据到哪里。
2. 结尾留下的两个虚线空位，就是高潮的舞台：观众提议「两块一起算」，我们真的让两个空位同时开始。
3. 第一个空位的前文条正常盖到「毛肚」；第二个空位的前文条伸过去，却必须经过第一个空位，那里还是空的，于是条子在这里断开。
4. 断口下面，第二个空位的候选分成几组，各自对应第一个空位可能的结果：比如第一块是「蘸料」，后面跟的是「要麻酱」；第一块是「饮料」，后面跟的是「来瓶冰的」。它拿不准该写哪一组。
5. 第一个空位一落定，断口接上，第二个空位的候选马上收成一组。观众自己看懂：它等的就是刚写出来的那一块。这个瞬间同时是知识揭晓和视觉高潮，用的仍然是开场那个「吞进前文」的动作。

## 怎么继续改
```bash
cd episodes/yiyudaopo/ai-yigeyige/protoA
```
- 时间、字幕、候选词都在 `timeline.js`（`T` / `COPY` / `CAND1` / `CAND2`）。画面在 `index.html`，每帧是时间的纯函数 `window.seek(t)`。声音在 `music/score.mjs`，从 `HITS` 读取音效时刻。
- 改了字幕里的新字要重新子集化字体：`python3 tools/fonts.py`（需要 `pip install brotli`）
- 接触表：`node render.mjs --sheet --every=0.5 --tag=x --cols=13` → `qa/sheet-x.jpg`
- 单帧：`node render.mjs --stills=9.7,16.5 --out=qa/stills`
- 声音：`node music/score.mjs && sh tools/master.sh`（-14 LUFS）
- 全片：`node render.mjs --workers=6` → `out/protoA-cursor.mp4`
- 动效检查：`python3 ../../../../tools/motion_check.py out/protoA-cursor.mp4 protoA --end=24.0`（结果：静止 12%、最长静止 0.30 s，PASS）
- 也可以在浏览器里打开 `index.html`，在控制台输入 `seek(12.5)` 看单帧。
