## 待导演核实的说法
1. 第一句「你问 AI 一个问题，背后可能有 GPU 在帮它计算」约 3.7 秒。工作室规则（`CLAUDE.md`「开头 2 秒规则」）要求第一句 ≤ 2 秒、约 12 字。这一版照导演稿没改；画面上第 0 帧已经有 GPU + 大字问题。要不要把第一句拆短，请导演定。
2. B 段「数据不一样，但很多计算规则是相似的」：画面上三块显示的是各自的漫反射亮度（0.88 / 0.56 / 0.72 之类，真实算出来的），规则写作「同一条规则」。真实渲染里不同材质会用不同的着色程序，所以旁白「很多……相似」比画面「同一条」更严谨；画面是在一个材质、一种光照公式内举例。
3. B4「既然能一起算，为什么非要排队呢？」画面先一块一块亮（排队），再一起亮。这是在讲这类工作负载可以并行，不是在说 CPU 只能一块一块算（D 段另有「CPU 也能并行」）。
4. D5「GPU 也不是什么都更快」用的画面是分支分歧（一组单元里一半走一条分支、一半在等）。这是 GPU（SIMT）里真实存在的一种低效，但只是「不一定更快」的原因之一，画面没有暗示是唯一原因。
5. C 段「这也是神经网络中矩阵计算的一种简化示意」：画面是矩阵 × 向量（一行参数 × 同一个输入 → 一个输出）。真实模型里一批 token 一起算时常是矩阵 × 矩阵。
6. E 段「数据迟迟送不过来，计算单元也可能只能等待」：示意画面是 HBM 到芯片边缘的数据点变稀、芯片中心「等数据…」。真实情况是内存带宽 / 延迟限制（memory-bound），数据走中介层里的布线，画面已注「数据流向为示意」。
7. 「张量核心」只作为例子（英伟达的叫法），其他厂商也有类似的矩阵单元。
