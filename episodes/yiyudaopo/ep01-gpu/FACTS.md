# EP01 FACTS：AI 又不打游戏，为什么还要用显卡？（开头 100 秒）

来源等级：〔读〕读过原文；〔常〕教科书 / 厂商文档里的常识，给出处但这次没逐字核对；〔估〕估算，写明假设；〔示〕画面示意，不是实物数据；〔判〕我们的判断，待用户（行家）确认。
**注意**：这一版旁白是按任务书重建的（V2.1 原稿没找到），所以下面是「片中实际说了什么」的依据，不是 V2.1 的依据。

## 旁白里的说法

| # | 片中说法 | 依据 | 等级 |
|---|---|---|---|
| 1 | 「算出这些字的，往往是远处机房里一排排的 GPU」 | 大模型推理大多跑在数据中心的 GPU / AI 加速器上；但也有用 TPU 等其他加速器的服务，所以用「往往」，不说「都是」 | 〔判〕 |
| 2 | 「GPU 最初是为游戏这类 3D 图形造的」 | GPU 起源于 3D 图形加速卡；NVIDIA 1999 年把面向游戏市场的 GeForce 256 称作「世界上第一颗 GPU」（NVIDIA 官方发布稿）。更早的 3D 加速也服务专业可视化（如 SGI 工作站），所以说「游戏这类 3D 图形」，不说「只为游戏」 | 〔常〕 |
| 3 | 「画面由成千上万个小三角形拼成」 | 实时 3D 渲染以三角形网格为基本图元（光栅化管线，见 *Real-Time Rendering* 第 4 版第 2 章）；片中小岛约 1900 个三角形，真实游戏多得多（画面角注已写） | 〔常〕 |
| 4 | 「每一块多亮，要看它朝哪、光从哪来：两组数对应相乘再加起来」 | 漫反射（朗伯）亮度 ∝ max(0, **n**·**l**)，**n** 是表面法线、**l** 是指向光源的单位向量，点积 = 三对分量各自相乘再相加。片中只演示漫反射一项（角注已写「简化」） | 〔常〕 |
| 5 | 「整个画面同一束光、同一套算法，只是每块的数不同，所以能成批地同时算」 | 同一个着色程序对大量顶点 / 像素各算一遍，彼此独立，适合数据并行；GPU 以 32 个线程为一组（warp）执行同一条指令（NVIDIA CUDA C++ Programming Guide，「SIMT Architecture」一节）。也有要等前一步结果的步骤（深度测试、阴影图先渲后用等），角注已写 | 〔常〕 |
| 6 | 「先被切成几小段，每段换成一长串数字」 | 语言模型先把文本切成 token，再查表换成向量（embedding）。切法因模型而异（角注已写）。向量长度：LLaMA-2 7B 为 4096（Touvron et al. 2023），GPT-3 175B 为 12288（Brown et al. 2020，表 2.1） | 〔常〕 |
| 7 | 「模型做得最多的事：乘法和加法」 | Transformer 的计算量主要在矩阵乘法（注意力的投影、前馈层）里，矩阵乘法由乘加组成 | 〔常〕 |
| 8 | 「一次要乘几千到几万对数，再加起来」 | 一个输出 = 输入向量和一行参数的点积。长度：注意力投影等于隐藏维度（几千，见 #6）；前馈层第二个矩阵的输入维度更长，LLaMA-2 7B 为 11008，GPT-3 为 4×12288 = 49152 | 〔常〕 |
| 9 | 「每吐出一个字，要做几十亿到上千亿次乘加」 | 前向每个 token 约 2N 次浮点运算（N = 参数量），即约 N 次乘加（Kaplan et al. 2020，*Scaling Laws for Neural Language Models*，2.1 节）。N 从几十亿（7B）到上千亿（175B 稠密模型 ≈ 1.75×10¹¹）。混合专家（MoE）模型每个 token 只用一部分参数，所以角注写「粗略量级」。画面上的计数器（0 → 7,000,000,000）以 70 亿参数（7B）稠密模型为例：每个 token 约 7×10⁹ 次乘加（不计注意力随上下文长度增长的那部分）。「一个字」≈ 一个 token，严格说 token 和字不是一一对应 | 〔估〕 |
| 10 | 「CPU 也有很多核心、也能并行」 | 服务器 CPU 有几十到上百个核心（如 AMD EPYC 9654：96 核），每个核心还有 SIMD 单元 | 〔常〕 |
| 11 | 「CPU 把大量面积留给控制和缓存；GPU 把更多面积给了运算单元」 | NVIDIA CUDA C++ Programming Guide 第 1 章「The Benefits of Using GPUs」：GPU 把更多晶体管用于数据处理，而不是数据缓存和流程控制（附 CPU / GPU 面积示意图）。片中版图是示意，角注写了「面积比例为示意」 | 〔常〕 |
| 12 | 「一条指令，一次喂进一大批数据」 | SIMT：一个 warp 的 32 个线程同时执行同一条指令（见 #5） | 〔常〕 |
| 12b | 「同一步里，这一大批乘加，彼此不用等」，画面「步与步之间，仍要按顺序」 | 同一层的矩阵乘法里，各输出元素互不依赖，可以同时算；层与层之间、生成下一个 token 与上一个之间有先后依赖；softmax、归一化里的求和也是归约（依赖） | 〔常〕 |
| 13 | 「GPU 也不是什么活都比 CPU 快」（角注） | 分支多、串行依赖强、数据量小的任务通常 CPU 更合适 | 〔常〕 |
| 14 | 「如今的 AI 芯片里，还专门做了算矩阵乘法的单元」，画面「如英伟达的张量核心」「D = A × B + C」 | NVIDIA Tesla V100（Volta，2017）引入 Tensor Core，每个时钟完成一次 4×4 矩阵乘加 D = A×B + C（NVIDIA Volta 架构白皮书）。其他厂商也有类似的矩阵单元（如 Google TPU 的脉动阵列） | 〔常〕 |
