## 怎么做的（一句话）
整部片子是一台虚拟相机在一张「世界平面」上的连续路径，首尾接两段 Blender 底片（同一块模组、同一支 50 mm 镜头）。
- 5 秒：游戏视口用单应变换逐帧贴在 3D 芯片四角上，再摆正成窗口。
- 48.5 秒：2D 相机的推进曲线和 Blender 相机共用同一个函数，叠加层改由底片的逐帧芯片锚点驱动。
- 中间没有一处剪切。所有方块共用一个组件（`Tile.tsx`），圆角、描边、「灌满 → 亮一下」的动作语法全片一致。

## 已按导演稿实现
- 六个镜头、文字原文和出现时刻（偏差见下一节）、五个转场的视觉桥：
  1. 芯片方框 → 视口；
  2. 被选中的方块被镜头跟着横移，琥珀内容倒空、只剩外形，停在 AI 区；27 秒「23」收进同一个外形；
  3. 第一行方块不动，第二行在正下方进来；
  4. 世界坐标从未变过，拉远时琥珀组在左上、AI 组在右下；
  5. 两股方块往下流进芯片轮廓（26:31 + 6 颗 HBM 轮廓），真芯片在格子底下浮现。
- 逐帧差值检查：17 / 30 / 42 / 51 秒四个边界 ±1 秒内最大帧差 1.3–3.3（中位 0.4–1.1），没有单帧尖峰，没有黑场或交叉淡化整屏。
- 首尾是同一块芯片：同一个 Blender 模型、材质和镜头；结尾俯视后拉远并倾斜 9°。
- 算术（全部核对）：2×4+3×5=23；2×1+3×6=20；[3,1]→9；[2,2]→10；[5,1]→13。
- 声音：只有器乐和音效，没有人声。
  - 1.5 秒低频音头；单个计算是几声干脆的 click；并行时一组整齐的 click 收进一记软落点，母题在这里第一次出现；
  - 「23」一声钟音；42–44 秒收；44 秒揭晓 + 母题完整回来（D 大调）；57 秒解决。
- 指标：响度 -14.2 LUFS、峰值 -1.4 dBFS；动效检查 PASS（静止 12%，最长 0.47 秒，没有 5 秒窗口 ≥ 30%）。

## 需要妥协 / 和导演稿有出入的地方
0. **0–3.5 秒慢推的放大量**：设计值是相机距离 150 → 133 mm（约 +13%），审核在屏幕上量芯片方框宽 343 → 371 px，只有约 +8%（透视下芯片在画面里的大小随距离变化比距离本身慢）。低于导演稿的 10–15%，要改得重渲 OPEN。
1. **T1 推镜偏快**：4.4–5.1 秒芯片方框在屏幕上从约 40% 宽推到约 90%，连续但快（这几帧帧差约 19）。要放慢得重渲 OPEN 后半段（RunPod 约 $0.2–0.35）。
2. **开头封装宽度**：基板前缘约占屏宽 71%（第 0 帧），超过导演稿的 55–65%；后缘更窄，平均接近上限。同样要重渲才能改。
3. **小岛宽度**：全景（5–8 秒、11–14 秒）约 70%，符合。8–11 秒推近选中地块时到 82–84%，这是有意的推近（Approach）。
4. **AI 问题提早出现**：16.15 秒开始打字（导演稿是 17 秒出现）。镜头横移时 AI 区从右边进来，问题在相机落定前打完。导演稿写的是「AI 环境从另一侧进来」，我理解为允许。
5. **静止 vs 工作室动效规则**：导演稿允许结果出来时静一下，工作室规则要求最长静止 ≤ 0.6 秒。为此我做了三件事：
   - AI 段加了一个慢推镜（随行数往下长、慢慢靠近）；
   - 加了一块很淡的「注意力光区」，跟着正在算的位置走；
   - 把几个拍点挪了一点：参数行 22.35 秒进（原 23 秒）、算式 23.55 秒开始、第二次同步计算 43.25 秒、44.4 秒加第三次。

   没有加随机晃动。
6. **加了三条示意角注**（地块明暗、数字是示意、方块不是核心），导演稿没写；这是工作室「简化要加注」的规则，行家会在意。
7. **开头 2 秒规则冲突**：工作室规则要求第一帧就有大字问题；导演稿规定 0.0 秒只有硬件、0.35 秒才出字。按导演稿做了，交用户定。
8. **付费渲染**：用户 11-18 中途明确「渲染交给 runpod」，按此执行，事先在对话里报了预算（约 $0.5，L40S 时约 $1）。
   - 三次运行上限估计合计约 **$1.49**（以 RunPod 账单为准）：主任务 $0.97，两次补渲 $0.17 和 $0.35。
   - 补渲的原因：一台 3090 没下载到 Blender，一台 5090 的 CUDA 初始化失败（两台都自动删除）。
   - 机器已全部删除。
   - 另外，本容器到 RunPod REST 接口仍然 502，改用了 GraphQL 版工具。

## 有没有哪处没做到连续
- 没有硬切。观众（Codex）主观上觉得 **15→16 秒「最像换片」**：小岛退出、提问框进来。
- 桥是那块被带过去的方块，但它在倒空琥珀色后只剩一个淡淡的空框，存在感弱。这是这一版最弱的转场。

## 现有素材 / 工具的限制
- 芯片模型是自建的通用示意模组，没有真实表面纹理（硅背面是平整的灰）。
- 小岛是程序生成的低多边形；游戏画面是「示意游戏」，不是真实游戏截图。
- 配乐是代码合成，没有人听过（Codex 听不到声音）。
- 云端 CPU 渲 Blender 约 15 秒 / 帧，只能出预览。

## 付费渲染会不会明显改变结果
- 已经付费精渲的部分：首尾两段 3D 底片（1080×1920、64 采样、逐帧），这是写实感的上限所在，再加采样意义不大。
- 真正能拉开差距的是模型细节，不是渲染：芯片表面、基板走线、更真实的周边器件。这需要建模工作，不是花更多渲染钱。
- 如果要修第 1、2 条（T1 推镜速度、开头构图），需要重渲 OPEN（约 $0.35）。

## 交付前三个角色的结果

  P2 里改了两条：「？」那段的示意数字从 [3,1] 改成 [6,1]，不再和后面的参数行重复；芯片叠加层的角注改为「方块代表计算任务，不代表核心或分区」。
  没改的 P2：0–3.5 秒放大量（见上面第 0 条）、第一帧无字（第 7 条）、「8 + 15」左右间距略不对称、署名位置偏低。
