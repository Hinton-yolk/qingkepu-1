# EP.01 配乐方案（草稿 v3 时间轴，99.3 秒，无配音）

用户 2026-11-22：「先从音乐开始吧」；不加配音（「合成的感觉ai味太重了」）。所以音乐和音效要扛起节奏，但不能抢字幕：观众一直在读字。

## 怎么做
- 用开源模型 **ACE-Step 1.5**（MIT 许可）在 RunPod 上生成**纯音乐**（不要人声），出 3 个方向的候选给用户挑。
- 生成后在本地剪接：按小节切开，对齐到下面的三段；揭晓前停半拍。
- 音效不用模型，用代码合成，卡在画面动作上（见下面的音效表）。
- 响度：成片 -14 LUFS。没有人声，音乐比有旁白的片子略高，但仍要退在字幕阅读的后面：密集讲解段比开头和揭晓段低约 3 dB。

## 三段（CLAUDE.md：开头 / 讲解 / 揭晓三段用不同织体，揭晓前停半拍）
速度先定 **100 BPM**（一拍 0.6 秒，一小节 2.4 秒），几个关键点刚好落在小节线上：

| 段 | 时间 | 画面 | 织体 |
|---|---|---|---|
| 开头 | 0 – 9.6 | 手机答「2 个」、字母飞出、三个 r 变红、气泡翻面 | 稀疏、好奇、俏皮：拨弦 / 木琴的问句动机，几乎不要鼓 |
| 讲解 | 9.6 – 76.5 | X 光（9.5）→ 读字母 → 切积木（14.9）→ Token → 接龙 → 电话 → 中文 → 两条队 → 算账 → GPU | 稳的轻律动：软底鼓 + 沙锤、暖电钢琴和弦、拨弦低音、木琴小动机。中途换配器（不换调、不换速）跟着站点走 |
| （停半拍） | 76.5 – 76.8 | 「所以 AI 不是笨」之前 | 全部停 |
| 揭晓 | 76.8 – 86.4 | 圆圈逐个读字母，三个 r 一起亮 | 更满、更暖：加铺底和旋律，第 33 小节（76.8 秒）进 |
| 下期预告 | 86.4 – 96.0 | 一块一块猜积木，「？」「自信 100%」 | 收回去，留一点悬念（少一层、加一点不确定的音） |
| 片尾卡 | 96.0 – 99.3 | 片尾卡 | 收尾和弦 / 短尾音 |

## 三个方向（每个方向出一首，用户挑）
1. **暖木琴 + 电钢琴**（lo-fi / chillhop 气质）：和暖光桌面最贴。
2. **拨弦 + 钟琴 + 轻打击**（知识区常见的俏皮感）：更轻快。
3. **干净的电子拨音 + 软铺底**（极简电子）：更「科技」，和「AI」题目贴。

共同要求：纯音乐、无人声、调式明亮但不吵、没有大鼓和强烈的 drop、旋律不要太满（观众在读字幕）。

## 音效（代码合成，卡在动作上）
时间从 `timeline.js` 和 `film/index.html` 的事件常量读，不手写秒数，改时间轴后自动跟着走。初定：
- 字母飞出手机：一串轻 pop；三个 r 变红：三个上行的叮；气泡打叉：低一点的「嘟」；气泡翻面：轻翻页声
- X 光扫过：一道细的扫频；眼睛读字母：每个字母一个很轻的 tick
- 切积木：一声干脆的「咔」；积木落到底座：轻 thud；三块跳起：三个 pop（音高依次升）
- 编号出现：小「哔」；句子合成一块：低一点的合拢声；Token 标签：叮
- 后面各站（接龙机吐积木、硬币落下、计数器滚动、GPU 亮起、圆圈读字母、三个 r 一起亮、「？」）同理

## 试听记录
- 第一轮（`pod/jobs_r1.json`）：A 暖木琴 + 电钢琴、B 拨弦 + 钟琴、C 极简电子，各 2 个种子，挑 A s11 / B s22 / C s11。用户：「A不错，麻烦再给三个不同的选择」。
- 第二轮（`pod/jobs_r2.json`）：A 的三个变体 A1 原配方换旋律、A2 原声吉他、A3 爵士电钢琴，各 2 个种子，都挑 s33（开头最稀疏、结尾和弦不断）。
- 挑选只看了能测的指标（速度、拍点稳定、分段响度）；好不好听、有没有人声由用户听了定。
